# @warlock.js/grimoire

> **Experimental.** The structure of the written files and the commands may still change before
> they are declared stable.

A project map for Warlock.js apps, for AI agents and developers. Warlock writes a **book** of what
is in the code: one entry per source file, the routes, the pages of each site and the screens of a
mobile app. Agents write what the product does (**features** and their **flows**), where users
meet it (**apps**: sites, mobile apps, pages and blocks) and the work (**tasks** and
**releases**), all in a visible `grimoire/` folder. The written files point into the book by name,
and a read-only check reports every name that no longer exists.

```sh
npx warlock add grimoire
npx warlock grimoire build
npx warlock scry src/app/catalog/services/new-arrivals.service.ts
npx warlock grimoire check
```

```
grimoire/
  book/        generated by Warlock, not in git
  features/    what the product does: README, CHANGELOG, flows, version briefs
  apps/        sites and mobile apps: conditions, layouts, pages, blocks
  tasks/       open and done work, one file per task
  releases/    one file per release: the agent's brief and the collected changes
```

Entries:

- `@warlock.js/grimoire`: the framework-neutral parts (written-file parser, book, check, scry).
- `@warlock.js/grimoire/warlock`: the Warlock adapter and the `grimoire` and `scry` commands.
- `@warlock.js/grimoire/vitest`: a Vitest reporter that records which acceptance criteria pass.
- `@warlock.js/grimoire/devtools`: the Grimoire tab of the devtools dashboard.

Docs: https://warlock.js.org/v/latest/grimoire/
