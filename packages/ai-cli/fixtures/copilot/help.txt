===== $ @github/copilot --help 
Usage: copilot [OPTIONS] [COMMAND]

GitHub Copilot CLI - An AI-powered coding assistant.

Start an interactive session to chat with Copilot, or use -p/--prompt for
non-interactive scripting. Copilot can edit files, run shell commands, search
your codebase, and more — all with configurable permissions.

Run `copilot <command> --help` for details on any subcommand.

Commands:
  app          Open the GitHub Copilot app
  login        Authenticate with Copilot
  help         Display help information
  init         Initialize Copilot instructions
  config       Manage configuration settings
  update       Download the latest version
  version      Display version information
  workflow     Run dynamic workflows
  sessions     Manage saved sessions
  memories     Manage memories
  plugin       Manage plugins
  mcp          Manage MCP servers
  skill        Manage skills
  instruction  Inspect instruction sources
  lsp          Inspect language server configuration
  sandbox      Manage command sandboxing
  completion   Generate a shell completion script

Options:
  -v, --version
          show version information
  -i, --interactive <prompt>
          Start interactive mode and automatically execute this prompt
      --fleet
          Run the prompt in fleet mode (parallel subagent
          orchestration); combine with -i, -p, or piped stdin
  -p, --prompt <text>
          Execute a prompt in non-interactive mode (exits after
          completion)
  -s, --silent
          Output only the agent response (no stats), useful for
          scripting with -p
      --enable-memory
          Enable memory in prompt mode (disabled by default)
      --model <model>
          Set the AI model to use (use 'auto' to let Copilot pick
          automatically)
      --reasoning-effort <level>
          Set the reasoning effort level [possible values: none, minimal, low, medium, high, xhigh, max]
      --context <tier>
          Set the context window tier (overrides persisted setting) [possible values: default, long_context]
      --auto-tier <preference>
          Set the Auto routing profile (validated against the available catalog)
      --agent <agent>
          Specify a custom agent to use
  -r, --resume [<value>]
          Resume from a previous session (optionally specify existing
          session ID, task ID, ID prefix, or name; name matching is
          exact, case-insensitive)
      --continue
          Resume the most recent session
  -n, --name <name>
          Set a name for the new session
      --session-id <id>
          Resume an existing session or task by ID, or set the UUID
          for a new session
      --connect [<sessionId>]
          Connect directly to a remote session (optionally specify
          session ID or task ID)
      --allow-all-tools
          Allow all tools to run automatically without confirmation;
          required for non-interactive mode. Run `copilot help environment`
          for what COPILOT_ALLOW_ALL accepts and what exact "true" grants [env: COPILOT_ALLOW_ALL=]
      --allow-all-paths
          Disable file path verification and allow access to any path
      --disallow-temp-dir
          Prevent automatic access to the system temporary directory
      --banner
          Show the startup banner
      --screen-reader
          Enable screen reader optimizations
      --plain-diff
          Disable rich diff rendering (syntax highlighting via diff
          tool specified by git config)
  -C <directory>
          Change working directory before doing anything else
      --log-dir <directory>
          Set log file directory (default: ~/.copilot/logs/)
      --extension-sdk-path <directory>
          Override the bundled @github/copilot-sdk injected into
          extension subprocesses with a local `copilot-sdk/` folder.
          Invalid paths fall back to the bundled SDK.
      --log-level <level>
          Set the log level [possible values: none, error, warning, info, debug, all, default]
      --stream <mode>
          Enable or disable streaming mode [possible values: on, off]
      --output-format <format>
          Output format: 'text' (default) or 'json' (JSONL, one JSON
          object per line) [possible values: text, json]
      --share [<path>]
          Share session to markdown file after completion in
          non-interactive mode (default: ./copilot-session-<id>.md)
      --share-gist
          Share session to a secret GitHub gist after completion in
          non-interactive mode
      --add-dir <directory>
          Allow file access to a directory and load its .github/skills
          and .github/agents as trusted configuration (can be used
          multiple times). A relative path resolves against the
          session working directory (the --resume/--worktree/-C
          directory), whatever order the options appear in
      --attachment <path>
          Attach a file (image or native document) to the initial
          prompt; only valid in non-interactive mode (can be used
          multiple times)
      --disable-mcp-server <server-name>
          Disable a specific MCP server (can be used multiple times)
      --disable-builtin-mcps
          Disable all built-in MCP servers (currently:
          github-mcp-server, githubiq)
      --enable-all-github-mcp-tools
          Enable all GitHub MCP server tools instead of the default
          CLI subset. Overrides --add-github-mcp-toolset and
          --add-github-mcp-tool options.
      --add-github-mcp-toolset <toolset>
          Add a toolset to enable for the GitHub MCP server instead of
          the default CLI subset (can be used multiple times). Use
          "all" for all toolsets.
      --add-github-mcp-tool <tool>
          Add a tool to enable for the GitHub MCP server instead of
          the default CLI subset (can be used multiple times). Use "*"
          for all tools.
      --plugin-dir <directory>
          Load a plugin from a local directory (can be used multiple
          times). A relative path resolves against the session working
          directory (the --resume/--worktree/-C directory), whatever
          order the options appear in
      --additional-mcp-config <json>
          Additional MCP servers configuration as JSON string or file
          path (prefix with @) (can be used multiple times; augments
          config from ~/.copilot/mcp-config.json for this session). A
          relative @ path resolves against the session working
          directory (the --resume/--worktree/-C directory) and a
          leading ~/ expands to your home directory
      --mcp-github-auth <server=origin>
          Send the signed-in GitHub account credential only to this
          explicit --additional-mcp-config server and approved origin.
          HTTPS is required except for literal loopback HTTP. Never
          put a token in this argument. Can be used multiple times.
      --allow-all-mcp-server-instructions
          Include initialization instructions from all MCP servers in
          the system prompt instead of only allowlisted servers
      --allow-tool [<tools>...]
          Tools the CLI has permission to use; will not prompt for
          permission
      --deny-tool [<tools>...]
          Tools the CLI does not have permission to use; will not
          prompt for permission
      --available-tools [<tools>...]
          Only these tools will be available to the model
      --excluded-tools [<tools>...]
          These tools will not be available to the model
      --secret-env-vars [<vars>...]
          Environment variable names whose values are stripped from
          shell and MCP server environments and redacted from output
          (e.g., --secret-env-vars=MY_KEY,OTHER_KEY)
      --allow-url [<urls>...]
          Allow access to specific URLs or domains
      --deny-url [<urls>...]
          Deny access to specific URLs or domains, takes precedence
          over --allow-url
      --allow-all-urls
          Allow access to all URLs without confirmation
      --allow-all
          Enable all permissions (equivalent to --allow-all-tools
          --allow-all-paths --allow-all-urls)
      --yolo
          Enable all permissions (equivalent to --allow-all-tools
          --allow-all-paths --allow-all-urls)
      --max-autopilot-continues <count>
          Maximum number of continuation messages in autopilot mode [default: 5]
      --mode <mode>
          Set the initial agent mode [possible values: interactive, plan, autopilot]
      --autopilot
          Start in autopilot mode
      --plan
          Start in plan mode (combine with --mode autopilot to
          auto-approve the plan and implement it autonomously)
      --experimental
          Enable experimental features
      --bash-env [<value>]
          Enable BASH_ENV support for bash shells (on|off)
      --mouse [<value>]
          Enable mouse support in alt screen mode (on|off)
      --acp
          Start as Agent Client Protocol server
      --remote
          Enable remote control of your session from GitHub web and
          mobile
      --remote-export
          Export your session to GitHub web and mobile (read-only;
          does not enable remote control)
      --dynamic-retrieval <category=on|off>
          Enable or disable embeddings-based dynamic retrieval per
          category and persist the choice (category: skills).
          Repeatable, e.g. --dynamic-retrieval skills=off
      --enable-mcp-server <server-name>
          Enable an MCP server disabled in settings for this run only;
          nothing is persisted (can be used multiple times)
      --max-ai-credits <credits>
          Set max AI credits for this session
      --assisted-approval
          Review tool permission requests with the assisted-approval
          safety judge instead of approving them outright. The judge
          is probabilistic and not a security boundary. Equivalent
          to the `assisted` mode of /permissions. Takes precedence
          over --allow-all-tools when the judge engages; requires
          --experimental or enabledFeatureFlags.AUTO_APPROVAL. (env:
          COPILOT_ASSISTED_APPROVAL)
      --usage-output-file <file>
          Write final usage statistics as JSON to the specified file
      --no-custom-instructions
          Disable loading of custom instructions from AGENTS.md and
          related files
      --no-auto-update
          Disable downloading CLI updates automatically. Copilot then
          runs the version bundled in the executable you launched
          rather than a newer previously downloaded one
      --no-ask-user
          Disable the ask_user tool (agent works autonomously without
          asking questions)
      --no-color
          Disable all color output
      --no-experimental
          Disable experimental features
      --no-bash-env
          Disable BASH_ENV support for bash shells
      --no-mouse
          Disable mouse support in alt screen mode
      --no-remote
          Disable remote control of your session from GitHub web and
          mobile
      --no-remote-export
          Disable exporting your session to GitHub web and mobile
          (also disables remote control)
      --no-eager-powershell-resolution
          Disable background PowerShell prompt resolution on Windows
  -h, --help
          Print help

Help Topics:
  billing      AI credit usage
  commands     Interactive Mode Commands
  config       Configuration Settings
  environment  Environment Variables
  limits       Session Limits Controls
  logging      Logging
  monitoring   Monitoring with OpenTelemetry
  permissions  Permissions
  providers    Custom Model Providers (BYOK)
  sandbox      Command Sandboxing

Examples:

  $ copilot

===== $ @github/copilot help environment 
Environment Variables:

  `COPILOT_ALLOW_ALL`: allow all tools to run automatically without confirmation. Accepts "true", "1", "yes", "on", or "y", case-insensitively and ignoring surrounding whitespace; "false", "0", "no", "off", "n", or an empty value turn it off. Setting it to exactly "true" additionally trusts the working directory without prompting, which loads that directory's skills, plugins, MCP servers, and hooks, including hooks that run shell commands; the other truthy spellings only auto-approve tools.

  `COPILOT_AUTO_TIER`: optionally set the Auto routing profile to "efficiency", "balance", or "intelligence", or a server-advertised profile when dynamic Auto tiers are enabled. "fast" is rejected, because the CLI cannot run on that profile. Requires the effective model to be Auto and is overridden by --auto-tier or persisted configuration.

  `COPILOT_AUTO_UPDATE`: set to "false" to disable downloading updated CLI versions automatically. Can also be disabled with the --no-auto-update flag. Auto-update is enabled by default, except in CI environments (detected via `CI`, `BUILD_NUMBER`, `RUN_ID`, or `SYSTEM_COLLECTIONURI` environment variables), where it is disabled by default. Standalone development builds run their bundled package by default and do not offer or install CLI updates unless release-style package behavior is selected with a canonical semantic version in `COPILOT_CLI_VERSION`. `COPILOT_CLI_DIST_DIR` and `--prefer-version` select an explicit package but do not enable updates for a development-identity package. On other standalone-binary installations, disabling it this way or with --no-auto-update also makes launches ignore any newer version already in the package cache and run the version built into the installed binary.

  `COPILOT_CLI_VERSION`: override the CLI version used for update comparisons. On standalone development builds, a canonical semantic version also opts into release-style cached-package selection and CLI updates, but does not pin cache selection to that exact version or change the version displayed by `--version`; use `--prefer-version` for an exact cached package. An empty or non-canonical value is treated as unset for package selection and updates.

  `COPILOT_CUSTOM_INSTRUCTIONS_DIRS`: comma-separated list of additional directories to search for custom instructions files (in addition to git root and current working directory).

  `COPILOT_EDITOR`, `VISUAL`, `EDITOR` (in order of precedence): command used to interactively edit a file (e.g., the plan).

  `COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, `GITHUB_TOKEN` (in order of precedence): an authentication token that takes precedence over previously stored credentials. Exception: in Codespaces, the auto-injected `GITHUB_TOKEN` (a user-to-server token) does not take precedence over a `/login` account. An explicitly exported `GITHUB_TOKEN`, `COPILOT_GITHUB_TOKEN`, or `GH_TOKEN` still takes precedence.

  `COPILOT_HOME`: override the directory where configuration and state files are stored; defaults to `$HOME/.copilot`.

  `COPILOT_MODEL`: optionally set the agent model. Can be overridden by the --model command line option or the /model command.

  `COPILOT_MULTIPLEXER`: override which terminal multiplexer the CLI believes it is running directly inside. One of "tmux", "herdr", or "none"; unrecognized values are ignored. "none" declares that no multiplexer wraps this pane; it does not restore env-derived host-terminal identity inside a herdr pane, whose inherited `TERM_PROGRAM`/`WT_SESSION`-style markers describe the terminal that started the herdr server and stay untrusted. Detection is otherwise automatic from the environment. Set this when it guesses wrong — most often `COPILOT_MULTIPLEXER=tmux` for tmux running nested inside a herdr pane, because herdr panes inherit whatever `TMUX` the herdr server itself was started with.

  `COPILOT_OFFLINE`: set to "true" to enable offline mode. When active, the CLI skips all network access: GitHub authentication, telemetry, web tools, GitHub MCP server, and auto-update are disabled. Requires a local model provider (COPILOT_PROVIDER_BASE_URL).

  `COPILOT_PROVIDER_BASE_URL`: API endpoint URL for a custom model provider (BYOK). When set, the CLI uses this provider instead of GitHub Copilot's model routing. GitHub authentication is not required. For type "azure", use a host URL or a full project URL, including its `/api/projects/<project>` path.

  `COPILOT_PROVIDER_TYPE`: provider type when using BYOK. One of "openai" (default), "azure", or "anthropic". Use "openai" for OpenAI-compatible endpoints including Ollama, vLLM, and Foundry Local.

  `COPILOT_PROVIDER_API_KEY`: API key for the custom provider. Optional for local providers like Ollama.

  `COPILOT_PROVIDER_API_KEY_COMMAND`: shell command that prints a fresh API key for each provider request. Takes precedence over COPILOT_PROVIDER_API_KEY.

  `COPILOT_PROVIDER_BEARER_TOKEN`: bearer token for custom provider authentication. Takes precedence over COPILOT_PROVIDER_API_KEY.

  `COPILOT_PROVIDER_WIRE_API`: API format for the custom provider. One of "completions" (default) or "responses". Use "responses" for GPT-5 series models.

  `COPILOT_PROVIDER_TRANSPORT`: transport for the custom provider. One of "http" (default) or "websockets". Use with `COPILOT_PROVIDER_WIRE_API=responses` to use OpenAI Responses over WebSocket.

  `COPILOT_PROVIDER_AZURE_API_VERSION`: Azure API version when using type "azure". When omitted, uses the GA versionless v1 route. Set explicitly (e.g. "2024-10-21") to use the legacy versioned deployment route.

  `COPILOT_PROVIDER_MODEL_ID`: well-known model ID used for agent configuration and token limits. Defaults to COPILOT_MODEL.

  `COPILOT_PROVIDER_WIRE_MODEL`: model name sent to the provider API for inference. Defaults to COPILOT_MODEL.

  `COPILOT_PROVIDER_MAX_PROMPT_TOKENS`: maximum prompt tokens for the BYOK model. Overrides both catalog and default values.

  `COPILOT_PROVIDER_MAX_OUTPUT_TOKENS`: maximum output tokens for the BYOK model. Overrides both catalog and default values.

  `COPILOT_PROVIDER_HEADERS`: custom HTTP headers sent only to the BYOK provider endpoint (not to GitHub Copilot services). Newline-separated "Name: Value" pairs; a literal "\n" also separates entries in a double-quoted shell string. Useful for gateway keys, tenant IDs, or routing headers.

  `GH_HOST`: GitHub hostname for authentication and API requests; defaults to "github.com". Set this to your GitHub Enterprise Cloud with data residency hostname (e.g., "mycompany.ghe.com"). Use when both GitHub CLI and Copilot CLI should target the same host.

  `COPILOT_GH_HOST`: GitHub hostname used only by Copilot CLI for authentication and API requests, overriding GH_HOST when set. Useful when GH_HOST points to a GitHub Enterprise Server instance but Copilot CLI needs to authenticate against github.com or a GitHub Enterprise Cloud with data residency hostname instead.

  `HTTP_PROXY`, `HTTPS_PROXY` (case-insensitive): proxy server URL for outgoing HTTP and HTTPS connections respectively (e.g., "http://proxy.example.com:8080").

  `NO_COLOR`: when set (to any value), disables color output. See https://no-color.org/ for details.

  `NO_PROXY` (case-insensitive): comma-separated list of hostnames or patterns that should bypass the proxy (e.g., "localhost,127.0.0.1,.example.com").

  `PLAIN_DIFF`: when set to "true", disables rich diff rendering (syntax highlighting via diff tool specified by git config). Can also be set with the --plain-diff flag.

  `USE_BUILTIN_RIPGREP`: when set to "false", uses the ripgrep binary from PATH instead of the bundled version.

  `USE_TGREP`: when set to "true", enables tgrep indexed search regardless of repository size, and also overrides the automatic-start checks described here. tgrep starts even outside a git repository, indexing the working directory itself (so avoid forcing it somewhere large, such as a home directory or filesystem root), and even on a virtualized or network filesystem (for example a VFS for Git checkout, or an SMB or 9p mount). Forcing tgrep also bypasses the Windows cloud-sync safety check, even if detection fails; indexing cloud-sync folders can download cloud-only files. When set to "false", disables tgrep and uses ripgrep. When unset, tgrep is enabled automatically only inside a git repository whose root is neither the user's home directory nor a filesystem root, on a non-virtualized filesystem, and at or above the file-count threshold (50,000 files with the current configuration); Windows cloud-sync folders and detection failures still disable automatic tgrep startup, and ripgrep is used otherwise.

  Automatic startup skips Git roots that are the user's home directory or a filesystem root (including Windows drive and network-share roots) before counting files or reserving a server slot, even when the session starts in one of their subdirectories. If the home directory cannot be determined, automatic startup is also skipped. Separate repositories beneath these directories remain eligible, with or without a Git remote. `USE_TGREP=true` explicitly permits indexing these otherwise-excluded roots.

  Copilot processes sharing a cache directory admit only one managed tgrep server at a time. Sessions on the same worktree can reuse its running server; other worktrees use ripgrep without waiting for the slot. `USE_TGREP=true` does not bypass this limit. The slot is released when the owning server shuts down; already-running sessions that skipped startup are not queued to acquire it. Servers launched manually or by older Copilot versions do not participate in this limit, and borrowing one does not reserve a managed-server slot.

  `TGREP_FILE_COUNT_THRESHOLD`: minimum file count for automatic tgrep indexed search. Accepts a non-negative integer, ignoring surrounding whitespace. Defaults to 10,000 on Windows and 50,000 on other platforms. Invalid values log a warning and use the platform default. Automatic sessions must meet this threshold before reusing an existing index and recheck it before taking over its server. Setting it to 0 removes only the file-count requirement; all other automatic-start checks still apply. `USE_TGREP=true` bypasses this threshold, and `USE_TGREP=false` still disables tgrep.

  `USE_TGREP_WARM_START`: when set to "true", blocks Copilot CLI startup until the tgrep index is ready when tgrep starts. It does not enable tgrep on its own; pair with `USE_TGREP=true` to force indexing and wait for readiness. Useful for evaluating tgrep search against a warm index.

  OpenTelemetry / Monitoring:

  `COPILOT_OTEL_ENABLED`: set to "true" to explicitly enable OpenTelemetry instrumentation.

  `OTEL_EXPORTER_OTLP_ENDPOINT`: OTLP endpoint URL. Setting this automatically enables OTel.

  `COPILOT_OTEL_EXPORTER_TYPE`: Copilot exporter backend; "otlp-http" (default) or "file" for local JSON-lines output.

  `OTEL_EXPORTER_OTLP_PROTOCOL`: OTLP HTTP protocol for the "otlp-http" exporter; "http/json" (default) or "http/protobuf". Use `OTEL_EXPORTER_OTLP_TRACES_PROTOCOL` or `OTEL_EXPORTER_OTLP_METRICS_PROTOCOL` to override per signal.

  `COPILOT_OTEL_FILE_EXPORTER_PATH`: file path for JSON-lines output. Setting this automatically enables OTel.

  `COPILOT_OTEL_SOURCE_NAME`: instrumentation scope name for tracer and meter; defaults to "github.copilot".

  `OTEL_SERVICE_NAME`: service name in resource attributes; defaults to "github-copilot".

  `OTEL_RESOURCE_ATTRIBUTES`: extra resource attributes as comma-separated key=value pairs.

  `OTEL_EXPORTER_OTLP_HEADERS`: authentication headers for the OTLP exporter (e.g., "Authorization=Bearer token").

  `OTEL_EXPORTER_OTLP_CERTIFICATE`: path to a PEM file with extra CA certificate(s) to trust for the OTLP endpoint (e.g., a private/corporate CA). Merged with the OS trust store. Per-signal: `OTEL_EXPORTER_OTLP_TRACES_CERTIFICATE`, `OTEL_EXPORTER_OTLP_METRICS_CERTIFICATE`.

  `OTEL_EXPORTER_OTLP_CLIENT_CERTIFICATE` / `OTEL_EXPORTER_OTLP_CLIENT_KEY`: paths to the client certificate and (unencrypted) private key PEM files for mutual TLS (mTLS). Both must be set together. Per-signal variants are supported.

  `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT`: set to "true" to capture full prompt/response content.

  `OTEL_LOG_LEVEL`: OTel diagnostic log level (not the CLI --log-level). One of: NONE, ERROR, WARN, INFO, DEBUG, VERBOSE, ALL.

  See `copilot help monitoring` for detailed configuration and examples.

===== $ @github/copilot help permissions 
Permissions:

  The GitHub Copilot CLI provides granular control over tool, URL, and path permissions to ensure safe
  operation. By default, the CLI restricts certain actions and prompts for user confirmation when necessary.
  You can customize these permissions using the available command line options.

  Tool Permissions:

  Tool availability is controlled via the --available-tools and --excluded-tools options. The --available-tools option
  disables all other tools; the --excluded-tools option disables only the specified tools. These filters decide which
  tools the model can see.

  Tool permissions are managed via --allow-tool, --deny-tool, and --allow-all-tools. Denial rules always take
  precedence over allow rules, even --allow-all-tools. These flags control approval prompts and do not expose tools
  that were filtered out by --available-tools/--excluded-tools.

  The --allow-tool and --deny-tool parameters take a permission pattern of form kind(argument) where the argument
  is optional and dependent on the kind. The following kinds are supported:

    shell(command:*?)
        Exactly matches a specific shell command to be run. If the command is omitted, all shell commands are allowed.
        In most cases, this will be an exact match against the command name. To match prefixes, use the :* suffix.
        This is particularly useful for git and gh commands, where approval is performed on a first-level subcommand
        basis, e.g. "git push" or "gh pr create". To match all git commands, use "shell(git:*)". Wildcard matching is
        performed on the stem of the command, so "shell(git:*)" will match "git push" but not "gitea".

    write(path?)
        Matches tools that create and modify files, except shell tool invocations. If the path is omitted, matches
        all such writes. A relative path matches by trailing path components, so "write(.env)" matches a file named
        ".env" in any directory, not only the one in the current working directory; use an absolute path such as
        "write(/path/to/.env)" to scope the rule to a single location. To allow all shell redirections, set
        --allow-all-tools.

    <mcp-server-name>(tool-name?)
        Exactly matches a specific tool from a specific MCP server, or all tools from that server if omitted.
        The server name is the name of the MCP server as configured in your environment (e.g. "MyMCP").
        The tool name is the name of the tool as registered with the MCP server (e.g. "my_tool").

    url(domain-or-url?)
        Matches URL access requests. Applies to the shell and web-fetch tools. If omitted, matches all URLs.
        Supports exact URLs: "url(https://github.com)"
        Supports protocol + domain patterns: "url(https://github.com)" or "url(https://*.github.com)"
        Note: All patterns are protocol-aware. Domains without a protocol default to https://.

  URL Permissions:

  The --allow-url and --deny-url parameters accept URLs or protocol + domain patterns.
  All URL permissions are protocol-aware - approving https://example.com does NOT allow http://example.com.
  Patterns without an explicit protocol default to https://.

    # Allow GitHub API access via HTTPS (default)
    $ copilot --allow-url=github.com

    # Allow HTTP access explicitly
    $ copilot --allow-url=http://example.com

    # Deny access to specific domain over HTTPS
    $ copilot --deny-url=https://malicious-site.com

    # Allow all URLs
    $ copilot --allow-all-urls

  Path Permissions:

  By default, file access is restricted to paths within the current working directory and its subdirectories,
  plus the system temporary directory. The --allow-all-paths flag disables this verification and allows access
  to any path on the filesystem. The --disallow-temp-dir flag prevents automatic access to the system temporary
  directory.

    # Allow access to any path on the filesystem
    $ copilot --allow-all-paths

    # Prevent automatic access to the system temporary directory
    $ copilot --disallow-temp-dir

  Enabling All Permissions:

  The --allow-all and --yolo flags are equivalent shortcuts that enable all permissions at once. They are
  equivalent to specifying --allow-all-tools --allow-all-paths --allow-all-urls together. These flags are
  useful for non-interactive scripts or when you want to run without any confirmation prompts.

    # Enable all permissions with a single flag
    $ copilot --allow-all
    $ copilot --yolo

    # Equivalent to:
    $ copilot --allow-all-tools --allow-all-paths --allow-all-urls

  It is expected that these permissions will be extended in the very near future to support wildcard matching and other richer functionality.

===== $ @github/copilot mcp --help 
Usage: copilot mcp <COMMAND>

Manage MCP server configuration.

MCP (Model Context Protocol) servers extend Copilot with additional tools
and capabilities. Servers can be local (stdio) processes or remote (HTTP/SSE)
endpoints.

Configuration is loaded from multiple sources:
  User       ~/.copilot/mcp-config.json
  Workspace  .mcp.json or .github/mcp.json
  Plugin     Installed plugins with MCP servers

Use `copilot mcp list` to see all configured servers,
or `copilot mcp get <name>` for details about a specific server.

Commands:
  list     List configured MCP servers
  get      Show server details
  add      Add an MCP server
  remove   Remove an MCP server
  enable   Enable an MCP server
  disable  Disable an MCP server

          Print help (see a summary with '-h')
