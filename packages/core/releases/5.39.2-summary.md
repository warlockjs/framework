# Warlock.js 5.39.2 — release summary

Released 2026-10-27.

All **33 packages** (`@warlock.js/*` and `create-warlock`) move to 5.39.2 together;
keep every family package on the same version. No breaking changes. This release adds
a replace-style model update and a check that catches a recurring deep-merge mistake.

---

## 1. Breaking changes

- **None.** 5.39.2 has no breaking changes. `merge()` behaves exactly as before.

---

## 2. Replace columns whole with `assign()` (`cascade`)

- **`model.assign(values)`** replaces each named column whole, the same as calling
  `set(key, value)` for each key. Unlike `merge()`, it does not deep-merge nested plain
  objects, so keys the new value omits are removed when you save.
- It applies the same identity protection as `merge()`: on a persisted model, `id`, `_id`
  and the primary key in `values` are ignored, so a request body cannot retarget the save.
- `merge()`'s editor documentation now says that nested objects are deep-merged and that
  removed keys are kept, and points to `assign()` and `set()`.

```ts
// settings is stored as { theme: "dark", filters: { status: "open" } }
post.merge({ settings: { theme: "light" } }); // filters is kept
post.assign({ settings: { theme: "light" } }); // filters is removed
await post.save();
```

---

## 3. `warlock check` flags `merge()` on object columns (`core`)

- **`WL9025` (warning)** reports a `model.merge({ ... })` call whose object literal includes
  a column that the model's `static schema` declares as an object, record or array-of-objects
  validator. The message names the column, explains that removed keys are kept, and suggests
  `assign()` or `set()`. It has no automatic fix, because the two methods behave differently.
- Scalar columns, `assign()`, `set()`, spreads, variables, and `merge()` on objects that are not
  Cascade models are not reported. Test files are skipped.

---

## 4. Upgrade notes

1. **Update the family.** Run `npx warlock update`.
2. **Read what changed.** Run `npx warlock release-notes --from 5.39.1`.
3. **Run `npx warlock check`.** For each `WL9025` warning, decide whether the update should
   replace the column. If it should, use `assign()` or `set()`. If merging nested keys is
   intended, keep `merge()`.
4. **Replace app helpers (optional).** A helper that calls `set()` once per column can become
   `model.assign(values)`.
