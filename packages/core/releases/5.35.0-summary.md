# Warlock.js 5.35.0 — release summary

Released 2026-10-21.

All **33 packages** (`@warlock.js/*` and `create-warlock`) move to 5.35.0 together;
keep every family package on the same version. Two changes are **breaking** (see
section 1); read them before upgrading.

---

## 1. Breaking changes

- **Root components now run in the browser (`web`).** Hydration now covers the same
  full-document ancestry as server rendering, so React `useId()` and generated form
  IDs stay stable beneath layouts. Move server-only work in `root.tsx` (secrets,
  database reads, Node APIs) to the root setup loader. Client navigation still
  replaces only the layout/page subtree inside `#vessel`.
- **Resources receive hidden columns (`cascade`).** Model resources can read hidden
  fields to derive public ones; `hidden` is now enforced on the final resource
  output. Hidden top-level names are still removed, but renamed or nested copies
  must be excluded by resource code.

The upgrade skill has a "5.34 to 5.35" section covering both.

---

## 2. Design system and web generators

- **`warlock add design-system`** scaffolds fourteen app-owned, accessible shadcn
  controls (text, email, password, select with search, multi-select, date, time,
  date-time, checkbox, radio, switch and more), wired to Mongez React Form, with
  pinned dependencies and dry-run support. Existing files are preserved.
- **`create-warlock`**: full-stack and Tailwind + shadcn selections include the
  controls out of the box.
- **`warlock generate page <path>`**: a UI-only page plus its setup file (route,
  loader, metadata); `--interactive` adds a feature hook.
- **`warlock generate form <name>`**: design-system controls, a shared Seal schema,
  a `useSubmitForm` hook and, with `--endpoint`, a guarded controller and route.
- **`warlock generate crud-ui <module>`**: guarded list/create/edit pages, forms,
  filters, pagination and delete for conventional CRUD modules.

---

## 3. Checks and code navigation

- **New `warlock check` rules (WL9013–WL9018)**: oversized or multi-component files,
  component-owned state, effects and handlers, native form controls, native
  validation, and exported controllers without a response schema. Configure
  severity and line limits in `.warlock-check.json`.
- **`warlock check --fix`** applies safe import fixes; `--changed` now includes
  files that import the changed ones.
- **`warlock inspect --section files`** lists every source file with its module,
  role, exports and import graph, without booting the app (also as the MCP
  `inspect_files` tool).
- **`warlock explain <file>`** prints a file's exports, importers and the routes
  and pages that reach it (`--json` supported).

---

## 4. API helpers

- **`AppError`**: typed domain failures with native HTTP handling and
  `http.errorResponse` context.
- **`listEndpoint`**: typed paginated list responses from validated query
  controls, with bounded limits and explicit sort/filter allowlists.
- **`assertResponseContracts`**: checks real HTTP responses against declared
  response schemas in tests.

---

## 5. Performance budgets and accessibility

- **Per-page build budgets**: gzip JavaScript/CSS limits per page with route
  overrides, warn or error enforcement, deltas against the previous build and a
  `warlock build --json` report. Existing apps stay report-only until limits are
  configured; new apps get 150 kB JavaScript and 50 kB CSS.
- **`page.assertAccessible()`** in browser tests runs a pinned axe-core with exact
  rule/selector allowances and violation evidence. New web apps include a home-page
  browser spec (accessibility, overflow, phone and desktop screenshots).

---

## 6. Faster test runs

- **`tests.lifetime: "worker"`** (opt-in): boot connectors once per Vitest worker
  instead of once per file, with per-file resets and awaited worker cleanup.
- **`setupTest({ mode: "unit" })`** loads configuration only, without the app
  bootstrap.
- **`tests.profileSetup` / `WARLOCK_TEST_PROFILE=1`** report setup time per file
  and per worker; `recommendedTestWorkers()` respects CPU quotas.
- New `warlock add test` configs split pure `*.spec.ts` unit files from
  integration `*.test.ts` files. Apps need Vitest 4.1.10 or newer for the
  generated runner.

---

## 7. Fixes

- **auth**: bounded Google token and JWKS requests (`timeoutMs`), expired refresh
  rows no longer count toward session caps, rejected refresh families are no longer
  logged as database failures, and guard descriptors appear in route inspection.
- **web**: sessions are installed after refresh, locale changes and page swaps
  (including guest sessions); stale responses cannot publish an identity; the
  request store survives server module reloads in development; navigation data
  and embedded payloads stay identical.
- **core**: notification locales are generated for every configured locale,
  co-located tests are excluded from configuration discovery, module dictionaries
  load in test workers, and the native loader registers once per process.

---

## 8. Agent skills

- New web topics: building RTL and mixed-direction UI, and preserving feedback and
  motion; a `build-accessible-controls` guide for the design system.
- Corrected `ClientOnly`, navigation and page-protection examples.
- Starter project skills add a state-ownership rule (loader data is server truth;
  shared client state lives in named stores) and teach typed errors, bounded list
  endpoints and response-contract tests.
