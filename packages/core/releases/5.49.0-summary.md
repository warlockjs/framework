# Warlock.js 5.49.0 — release summary

Released 2026-11-08.

All **33 packages** (`@warlock.js/*` and `create-warlock`) move to 5.49.0 together;
keep every family package on the same version. This minor fixes image input for Haiku 5
models, adds clearly named mail-mode checks, lets `warlock check` recognise your own
guard helpers, keeps `warlock check --changed` out of `node_modules`, stops the dev server
from thinning the generated `AGENTS.md`, and corrects several docs pages. The packages with
changes are `ai-anthropic`, `core` and `cascade`. No breaking changes.

---

## 1. Anthropic provider (`ai-anthropic`)

- `claude-haiku-5` and `claude-haiku-5-5` are recognised as vision-capable, so an image
  attachment is no longer refused before the call.

## 2. Core

- `isMailProductionMode()`, `isMailDevelopmentMode()` and `isMailTestMode()` report the
  resolved mail mode. `isProductionMode()`, `isDevelopmentMode()` and `isTestMode()` stay
  as deprecated aliases; they read the mail mode, so use `environment()` for the app
  environment.
- `guardWrappers` in `.warlock-check.json` lists your helpers that wrap `guarded()`;
  `WL9006` no longer reports routes registered inside them.
- `warlock check --changed` leaves out every `node_modules` path.
- The dev server's `AGENTS.md` refresh no longer replaces the generated Models list with
  nothing.
- Docs: which writes do not clear a repository's list cache, and that omitting
  `importModule` leaves model event listeners empty in the test worker.

## 3. Cascade

- Docs: `.default("text")` writes the value as raw SQL (use `.defaultString("text")`
  for text), and a nested `transaction()` joins the outer one, so code after it runs
  before the outer commit (use `afterCommit()`).
