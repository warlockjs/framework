# Warlock.js 5.55.0 — release summary

Released 2026-11-17.

All **34 packages** (`@warlock.js/*` and `create-warlock`) move to 5.55.0 together;
keep every family package on the same version. This minor adds one new package,
`@warlock.js/grimoire` (experimental): a project map for AI agents and developers. It
also opens the extension points Grimoire uses, so your own packages and apps can use
them too: MCP tools, devtools panels, `warlock explain` codes and nested CLI command
lists. The packages with changes are `core`, `web`, `devtools`, `create-warlock` and
`grimoire`. No existing behaviour changes. Upgrading from 5.53 or earlier needs the
`@mongez/*` minimums listed under "Upgrade notes".

## Check first

- **Grimoire is new and experimental.** The structure of the files an agent writes under
  `grimoire/` may still change before it is stable. Stable is planned for 6.0.
- **New apps include Grimoire.** Existing apps are not changed. Run `warlock add grimoire`
  to add it to an existing app.
- **Upgrading from 5.53 or earlier.** Raise the `@mongez/*` minimums in your app's
  `package.json` before you install, or `npm install` stops with an `ERESOLVE` error.
  See "Upgrade notes".
- **The inspect report stays `schemaVersion: 1`.** Fields were only added.

---

## 1. What changed most

- **Grimoire (`grimoire`, new).** A project map in three parts:
  - A generated **book** of the code, built from the `warlock inspect` report, in
    `grimoire/book/`. It is rebuilt by tools and never edited by hand.
  - **Agent-written files** under `grimoire/`: features, flows, apps, layouts, pages,
    screens, blocks, tasks and releases. Each one points at real routes, pages, mails,
    jobs, events and tests.
  - **Checks and answers.** `warlock grimoire check` is read-only and reports problems
    with `GR` codes. `warlock scry` answers questions about a file, its impact, a route, a
    feature, a flow or a search. The `grimoire_*` MCP tools answer the same questions.
- **Tests tied to acceptance criteria.** A Vitest reporter records the last result of
  every test marked `// @proves <feature>/<flow> AC-n`. The check reports failing,
  stale and not-run criteria.
- **A Grimoire tab in devtools.** One search box across flows, blocks, routes, files and
  tasks, and views for features, flows, pages, tasks, releases and the check report. It
  never boots the app and never changes an agent-written file. `exportGrimoireSite()`
  writes the same tab as one static `index.html`.
- **Public extension points (`core`, `devtools`).** Packages and apps can register
  their own MCP tools, dashboard tabs, `warlock explain` codes and CLI commands. See
  section 3.
- **Richer inspect report (`core`).** More file roles, per-file facts and route and page
  fields. See section 3.
- **New apps (`create-warlock`).** Grimoire is part of the generated app, and is offered
  in the feature picker and in `--features`.

## 2. Grimoire in more detail

- **Book.** `buildBook()` writes one JSON entry per source file, an `index.md` per
  module, `app/routes.json`, the page list of each site and the screen list of each
  mobile app. It hashes a file only when its size or modification time changed, writes
  each file atomically, rewrites only changed entries and removes entries of deleted
  files. A run with no changes writes nothing. `loadBook()` reads it without an adapter,
  and `openGrimoire()` loads the whole book in one call.
- **Book maps.** `features/<feature>/bookmap.json` lists the files a feature owns and
  borrows, its routes, its pages per app and the files no flow reaches.
  `flows/<flow>.bookmap.json` lists the files behind each step, each criterion's tests
  with their last result, and the blocks that show the flow.
- **Check.** `warlock grimoire check` reports names that point at nothing, source files
  without a header or a feature, files no flow reaches, criteria without a test,
  `@proves` lines that name nothing, and README versions that differ from the changelog.
  Findings on proposed work are expected and never fail the check. The command exits
  with 1 only on unexpected errors. `--all` lists every finding and `--json` is always
  complete. `warlock explain GR2001` describes any code.
- **Apps.** An app is a site or a mobile app. Pages, layouts, screens and blocks are
  checked (`GR5001`–`GR5009`). Mobile screens are read from Expo Router file names; an
  app that defines navigation in code declares its screens in
  `grimoire/apps/<app>/screens/`. A page step can name its app, `page /support [web-admin]`.
- **Tasks and releases.** Task and release files are checked (`GR6001`–`GR6003`,
  `GR7001`–`GR7005`). `warlock grimoire release <version>` writes the changelog
  entries stamped with that version into `grimoire/releases/<version>.md`.
- **Commands.** `warlock grimoire build` (with `--force`, and `--site [--out]` for a
  static site), `warlock grimoire check`, `warlock grimoire release` and `warlock scry`.
  Add `registerGrimoireCommands()` to `cli.commands` in `warlock.config.ts`.
- **Scry.** `--impact`, `--route`, `--feature`, `--flow` and `--search`. Search ranks exact
  name or path, prefix, whole word, substring, header sentence and fuzzy matches, in that
  order. Long lists stop at 20 lines; `--all` prints every line and `--json` is complete.
  File questions never boot the app.
- **Skills.** Six agent skills ship with the package: `use-the-grimoire`,
  `write-a-feature`, `record-a-change`, `describe-an-app`, `document-a-file` and
  `backfill-a-grimoire`.
- **Adapters.** `createWarlockAdapter()` builds the book from `warlock inspect`. For a
  mobile app it reads only the source folders, and the manifest records the installed
  `@warlock.js/core` version, so a core upgrade rebuilds the book.

## 3. New options and APIs

- **`core`, MCP:** `withMcpTools()` attaches the MCP tools a package registers to a
  command. `mcp.tools` in `warlock.config.ts` lists them, and `startWarlockMcpServer()`
  takes the same list as `tools`. A tool name that is already taken stops the server
  with a message that names the tool.
- **`core`, CLI:** `cli.commands` accepts arrays of commands (`CLICommandEntry`), so one
  register function can return several commands. `withExplainCodes()` lets a package
  answer `warlock explain <code>` for its own codes without booting the app. Codes match
  in any case.
- **`core`, add:** `warlock add grimoire` installs the package, registers its commands,
  updates `.gitignore`, adds the devtools panel and the Vitest reporter. It edits only
  files written as literals, prints the line to add when it cannot, and running it twice
  changes nothing. `warlock add test` adds `grimoireReporter()` when the app uses
  Grimoire.
- **`core`, inspect:** files report `lines`, `about`, `tags` and `exportDocs`. New file
  roles: `use-case`, `seed`, `request`, `mail`, `job`, `event` and `client`. A file
  named `*.use-case.ts`, `*.seed.ts`, `*.request.ts`, `*.mail.ts`, `*.job.ts`,
  `*.event.ts` or `*.client.ts` gets its role from the suffix, even inside another
  folder. Routes with a controller tuple report `controller` and `action`; the `Route`
  type gains `$controller` and `$action`. Pages report `setupFile` and `site`.
- **`core`, tooling:** `collectFiles()`, `fileRole()` and `CollectFilesOptions` are
  exported from `@warlock.js/core/tooling`. `collectFiles()` takes a `dirs` option.
- **`devtools`:** `panels: ["<package>/devtools"]` in `src/config/devtools.ts`
  registers your own dashboard tab. A panel declares an id, a title, data routes served
  under `/__warlock/api/<id>` and a browser view module. Every route and file sits
  behind the devtools guard. The Processes tab uses the same registration.
- **`web`:** `@warlock.js/web/build` exports `discoverPageGraph()`, `layoutChainFor()` and
  the page-graph types.
- **`grimoire`:** `parseGrimoire()`, `buildBook()`, `loadBook()`, `openGrimoire()`,
  `createWarlockAdapter()`, `registerGrimoireCommands()`, `exportGrimoireSite()`, the
  Vitest reporter from `@warlock.js/grimoire/vitest` and the devtools panel from
  `@warlock.js/grimoire/devtools`.
- **`create-warlock`:** Grimoire is a feature in the picker and in `--features`. The git
  step's spinner reads "Initializing git repository" while it runs.

## 4. Upgrade notes

1. **Update the family.** Run `npx warlock update`, then
   `npx warlock release-notes --from 5.54.0`.
2. **From 5.53 or earlier:** raise `@mongez/http` to `^3.5.2` and
   `@mongez/localization` to `^3.6.0` in your app's `package.json` before you install.
   Web apps also raise `@mongez/react-form` to `^4.1.0`. Without this, `npm install` stops
   with an `ERESOLVE` error. These minimums were raised in 5.54.0.
3. **Existing apps keep their files.** To use Grimoire, run `warlock add grimoire`. It
   installs `@warlock.js/grimoire`, adds `registerGrimoireCommands()` to
   `cli.commands`, adds the generated files to `.gitignore`, and adds the devtools panel
   and the Vitest reporter when the app has them.
4. **New apps** include Grimoire, its devtools panel and a project map section in the
   agent guide. Copy what you want from a fresh app.
5. **Inspect consumers:** the report stays `schemaVersion: 1`. Fields were only added,
   so existing readers keep working. A file whose name ends in a role suffix now gets
   that role even inside another folder, for example `services/mail/welcome.mail.ts` is
   a `mail` file.
6. **`warlock explain`** reads only `warlock.config.ts`. A config that fails to load is
   named in the error.
7. A file under a non-`src` `app/` folder, such as `mobile/app/products/x.tsx`, belongs
   to the module `mobile/app`.
8. The release family now has 34 packages, and the release gates cover Grimoire like
   the others.

## 5. Planned for 6.0

- **Grimoire becomes stable.** In 5.55.0 the structure of the written files may still
  change. Pin the family version and read the changelog when you upgrade.
