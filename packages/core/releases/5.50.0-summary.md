# Warlock.js 5.50.0 — release summary

Released 2026-11-09.

All **33 packages** (`@warlock.js/*` and `create-warlock`) move to 5.50.0 together;
keep every family package on the same version. This minor makes `schema.validate(data)`
enforce conditional rules, warns when a repository drops a client `orderBy`, lets
`warlock check --changed` run a long file list on Windows, stops `WL9007` flagging
`href()` redirects, and lets `warlock doctor` report sites whose loaders need a database.
The packages with changes are `core` and `seal`. No breaking changes.

---

## 1. Seal

- `schema.validate(data)` called with one argument builds the same root context as
  `v.validate(schema, data)`. `requiredIf`, `requiredIfIn`, `requiredWith`,
  `requiredWithout` and their `Sibling` variants no longer pass silently when the
  validator is called this way.
- Docs: map field keys to display names with one `translateAttribute` function, per
  call or through `configureSeal()`; `.label()` still wins for a single field.

## 2. Core

- `RepositoryManager` logs a warning naming the column(s) when a client `orderBy` is
  dropped because it is outside `sortable`. The allow-list behavior is unchanged.
- `warlock check --changed` and `warlock test --changed` split a long file list into
  several `vitest related` runs, so a large change no longer fails with `spawn ENAMETOOLONG`
  on Windows.
- `WL9007` no longer reports a redirect or link target built by `href()`.
- `warlock doctor`'s `sites` check lists a site whose page loader queries the database as
  not rendered instead of failing it; the verdict is a warning only when every site is in
  that case.
- Docs: `useCurrentUser()` returns `undefined` outside a request (scheduler jobs, seeds,
  queue workers); `currentUser()` from `@warlock.js/auth` is the typed alternative.
