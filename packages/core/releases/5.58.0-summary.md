# Warlock.js 5.58.0 — release summary

Released 2026-11-18.

All **34 packages** (`@warlock.js/*` and `create-warlock`) move to 5.58.0 together;
keep every family package on the same version. This minor gives the Grimoire tab a real
flow page, a grouped Check tab and a Product map for readers who do not read code, adds
read-only share links to the production monitor, and makes flow steps list only the files
that run. The packages with changes are `grimoire`, `devtools` and `core`.

## Check first

- **Share links need a table.** If you turn on `production.share.enabled`, add the new
  `devtools_shares` table by running your migrations with `devtoolsMigrations`. Without
  the setting nothing changes.
- **Flow steps list fewer files.** Type-only imports are no longer followed, so a step
  that listed server files only through a type import now lists fewer. Ownership coverage
  (GR3006) still counts type-only reach, so its numbers do not change.

---

## 1. What changed most

- **A flow page.** The Grimoire tab shows a flow's summary, status and origin, previous
  and next flow, a health strip, a "Fix next" box with a ready `@proves` line, the journey
  as a stepper with file counts, one row per criterion with its tests, and edge cases with
  "does not apply" collapsed. A flow takes its summary from the paragraph under its title;
  a flow without one gets the warning GR1030.
- **A grouped Check tab.** Findings group by code with counts and the fix shown once, filter
  by severity, code, feature and flow, and "files no flow reaches" (GR3006) shows one row
  per feature instead of one per file. The Overview's top problems rank by severity, then
  by count.
- **A Product map.** Feature cards with a plain summary, audience, apps and a health light;
  feature pages with why, flows as short stories, where each appears in the apps with
  screenshots, release history and planned work; flow pages with the steps in the user's
  words and what proves them. Code detail sits behind "For developers". The static export
  includes the map and its screenshots.
- **Read-only share links.** In the production monitor an admin creates an expiring,
  revocable link to the Product map under Admin, Share links. The token stays in the URL
  fragment and is stored hashed; the link opens only that panel's shared view.
- **Steps list only the files that run.** A page that imports a type through a barrel no
  longer lists the server files behind it. Flow answers on large apps drop from megabytes
  to kilobytes.
- **Test results.** The view tells "no results recorded" apart from "did not run" and picks
  up new results without a restart. The phone layout uses cards, scrolling sub-tabs and
  readable graph labels.

## 2. New options and APIs

- **Written format.** Feature `audience` and `## Why`, flow `## Story`, screenshots as
  image lines pointing into `grimoire/screenshots/`, and `(AC-n)` at the end of a case line
  to link it to a criterion. New checks GR1029, GR2013 and GR2014.
- **Test results file.** The panel option `testResultsFile` reads results from another
  file; the reporter writes there with `grimoireReporter({ file })`. New warnings GR4009
  (proofs but no recorded results) and GR4010 (a proving test the reporter could not match).
- **Devtools panels.** Panels can serve a folder of images (`files`), declare a shared view
  (`share`) and receive captured error counts (`errors`). View contexts gain `file()`,
  `shared` and `share`; `asset()` and `file()` return absolute URLs, so a view can
  `import()` another of its modules.
- **Book maps.** Steps add `entries`, `direct` and `typeOnlyFiles`; book entries add
  `typeOnlyImports`. The devtools flow answer and the MCP `grimoire_flow` tool send counts
  and direct imports per step, with a new route that pages through the files of one step.
- **Core.** The `files` section of `warlock inspect` marks type-only imports with
  `typeOnly: true` (`import type`, `export type … from`, imports and re-exports whose names
  are all `type`, `typeof import()`).

## 3. Upgrade notes

- Nothing to change for apps that do not use share links.
- Code that read every reachable file of a flow step from the devtools answer or the MCP
  tool should read the counts and `direct` imports, or page the files through the new route.

## 4. Verified

- One typecheck of the family and the full test suites, plus every release gate, ran green.
- The share-link store ran its integration spec on PostgreSQL 16 and MongoDB 7 (44 specs
  each, all passing).
- The Grimoire tab and the Product map were checked in a real browser at 1440 and 390 px,
  in light and dark.
