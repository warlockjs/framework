# Warlock.js 5.60.0 — release summary

Released 2026-11-19.

All **34 packages** (`@warlock.js/*` and `create-warlock`) move to 5.60.0 together;
keep every family package on the same version. This minor adds an AI section to devtools
with reports and charts, and fixes cached reads on PostgreSQL, notification delivery
results, cached permissions and the generated `AGENTS.md`. The packages with changes are
`core`, `cascade`, `devtools`, `ai`, `ai-openai`, `ai-panoptic`, `notifications` and `access`.

## Check first

- **Production AI reports need one more table.** `devtoolsMigrations` now includes
  `devtools_ai_rollups` (hourly AI totals). In production, the **Reports**, **Models** and
  **Errors** tabs are on by default once Panoptic loads; until `warlock migrate` creates the
  table, each process logs one warning at boot and the pages show "AI reports need their
  table". Turn the three tabs off with `production.panels` if you do not want them (then no
  totals are written).
- **Panoptic's own dashboard no longer starts inside a Warlock app** (also without devtools,
  and in a test run from the app folder). One notice points at the devtools AI pages. Set
  `panoptic.dashboard.standalone: true` to keep it.
- **Cached roles and permissions expire on a fixed schedule.** Reads no longer extend the
  `cache.ttl`, so a role change shows up within one ttl. Entries cached by older versions
  reload once.

---

## 1. What changed most

- **An AI section in devtools.** Six pages: Reports, Runs, Agents, Models, Errors and
  Evaluate. Reports, Models and Errors show estimated cost, tokens, error rate and latency
  over 24 hours, 7 days, 30 days or a custom range, with accessible charts (keyboard
  tooltips, table view). Runs gains search, status, type and group-by filters and a cost
  tint on the span tree. Evaluate grades a system prompt with the configured judge model.
- **Hourly AI rollups.** Devtools keeps hourly totals per agent, model and provider (runs,
  tokens, estimated cost, errors by category, latency histogram) in the app database in
  production, in JSON files in development. `devtools.ai` takes `reports`, `retentionDays`
  and `flushIntervalMs`.
- **Cached reads on PostgreSQL match the database.** `jsonb` and array columns come back as
  objects and arrays on a cache hit, not as strings.
- **Notification sends tell you what happened.** `send()` and `queue()` resolve with a
  per-channel result, and `throwOnFailure` rejects with `NotificationDeliveryError`.
- **Fewer surprises.** `migrate:export-sql` follows migration order, `warlock dev` and
  `warlock agents-md --write` write the same `AGENTS.md`, and a global `onBeforeSending`
  handler returning `false` cancels the send.

## 2. New options and APIs

- **Devtools.** AI report API: `GET /api/ai/reports`, `/models`, `/errors`, `/runs` and
  `GET`/`POST /api/ai/evaluate`; error codes `ai.range-invalid`, `ai.evaluate-unavailable`,
  `ai.prompt-not-found`, `ai.evaluate-failed`.
- **Cascade.** `transaction(fn, { savepoint: true })` on PostgreSQL.
- **Core.** `middleware.idempotency()` takes `store` and `scope`; `loadTestLocales()` from
  `@warlock.js/core/tests`; `collectAgentsMdReport()` and `collectDevModelModules()`.
- **Notifications.** `NotificationDeliveryError`, `throwOnFailure`.
- **AI.** `Usage.audioInputTokens` and `textInputTokens`; `fallbackModel()` answers carry
  `fallbackAttempts`, and `AgentReport.fallbackTrips` counts them.
- **Panoptic.** `panoptic.evaluate`, `getEvaluateConfig()`, `isInsideWarlockApp()`.

## 3. Upgrade notes

- Run migrations to create `devtools_ai_rollups` if you use production devtools.
- The devtools tab `ai` keeps its id (and `production.panels.ai`) but is titled **Runs** now,
  inside the new **AI** sidebar group.
- `defineNotification(...).send()` and `.queue()` now resolve with a `NotificationSendResult`.
  Code that ignored the old empty result keeps working, but a hand-written fake or wrapper typed
  as `DefinedNotification` must now return a result from `send()`/`queue()`.

## 4. Verified

- One typecheck of the family and the full test suites ran green; two core tests that timed out under server load
  pass in isolation.
- The AI rollup store ran against live PostgreSQL 16 and MongoDB 7 (21 of 21), including concurrent upserts of one
  hour row from several writers.
- Cached repository reads, nested savepoints, `json()` string arrays and `findOneAndUpdate` inside a transaction ran
  against a live PostgreSQL 16.
