# Warlock.js 5.53.0 — release summary

Released 2026-11-11.

All **33 packages** (`@warlock.js/*` and `create-warlock`) move to 5.53.0 together;
keep every family package on the same version. This minor is a security and
performance hardening release across the framework: request and upload limits in
`core`, safer queries in `cascade`, sign-in throttles and token storage in `auth`,
bounded caches, logs and queues, a private-by-default `ai.serve`, and outbound
requests that cannot be steered to private addresses. The packages with changes are
`access`, `ai`, `ai-anthropic`, `ai-cli`, `ai-panoptic`, `ai-tools`, `ai-workspace`,
`auth`, `cache`, `cascade`, `context`, `core`, `create-warlock`, `devtools`, `herald`,
`logger`, `queue`, `scheduler`, `seal`, `sitemap` and `web`. Several defaults change;
every one is listed under "Upgrade notes" with the setting that restores the old
behaviour.

## Check first

- **Uploads over 25 MB.** One multipart request may hold at most 25 MB in total
  (`http.multipart.maxTotalSize`). Apps that raised `http.fileUploadLimit` above that
  must raise `maxTotalSize` too, or set `uploads: { maxTotalSize }` on the route.
- **`?paginate=false` from a client is ignored** on repository lists and `Restful` list
  routes. Set `allowClientUnpaginated = true` on a repository (or
  `repository.allowClientUnpaginated: true`) to allow it.
- **Unknown fields on save.** `strictMode` now works: under `"strip"` (the MongoDB
  default and the generated PostgreSQL config) unknown fields are dropped instead of
  failing, and MongoDB updates validate nested data. Set `strictMode = "fail"` to keep
  rejecting unknown fields.
- **Large arrays and records.** Seal refuses arrays over 10,000 items and records over
  10,000 keys unless the schema sets its own bound;
  `configureSeal({ maxArrayItems: Infinity, maxRecordKeys: Infinity })` lifts it.
- **`ai.serve` sends only text** to the client by default.
  `events: "all", toResult: (result) => result` restores the full stream.
- **svg uploads.** `v.file().image()` refuses svg and checks the file's bytes; use
  `image({ svg: true })` where svg is wanted.
- **Finished jobs are pruned** (24 hours or the newest 1,000 completed; 7 days or the
  newest 5,000 failed). Upgrade queue workers before the processes that dispatch.
- **Production error pages** hide the error message and stack under `warlock start`
  and for any `NODE_ENV` other than development, test or unset.

## 1. Security fixes that matter most

- **Uploads and request bodies (`core`).** A total size cap per multipart request
  (413 `EC108`), optional parsing only on routes that declare `uploads`
  (`http.multipart.routes: "declared"`, 415 `EC109`), a 5-minute request timeout, and
  caps on array indices and urlencoded fields. One key such as `?a[4294967294]=x` used
  to create a four-billion-slot array that request logging then walked, blocking the
  process.
- **Uploaded file types (`core`).** Image and type rules read the file's bytes, svg is
  accepted only on request, and saved markup is stored as `application/octet-stream`,
  so an uploaded svg or html file is no longer served as a page from your bucket.
- **Client IP and host (`core`).** `X-Real-IP` is read only through the new
  `http.realIpHeader`, so a client can no longer choose its own IP to get past per-IP
  limits. The global `http.rateLimit` keys on that same address, so a forged
  `X-Forwarded-For` no longer splits a client's count. `http.allowedHosts` refuses
  unknown hosts before routing.
- **Database queries (`cascade`).** PostgreSQL `has()` counts and JSON helpers no
  longer write request values into SQL text; MongoDB refuses `$` field names and
  operator objects in value positions, caps LIKE wildcards, and stops silently dropping
  filters that made reads, updates and deletes reach every document. `upsert()`,
  `restore()` and `restoreAll()` respect tenant scopes, and `model.set()` can no longer
  write into `Object.prototype`.
- **Sign-in (`auth`).** Throttles count each attempt when it arrives, so a burst of
  concurrent guesses no longer gets past the lock; unknown emails take as long as wrong
  passwords; provider logins no longer link to unverified accounts; the `Auth` model
  hides `password` from serialized output. Opt-in: token digests at rest
  (`hashTokensAtRest`), `__Host-` cookies, issuer and audience checks.
- **AI endpoints and outbound requests (`ai`, `ai-tools`).** `ai.serve` keeps the
  system prompt, tool I/O and usage on the server; output guardrails also cover streamed
  text; guarded requests pin the connection to the checked address on every redirect
  (DNS rebinding) and drop custom headers across origins; `http_request` keeps its API
  key on its own host; the semantic cache serves an answer only to the same agent and
  conversation.
- **Agent workspace (`ai-workspace`).** `grep` runs on a matcher that never
  backtracks (`((a)+)+$` against 27 characters used to take 12.7 s), globs are linear,
  allow-listed commands can no longer start other programs through `PATH`,
  `NODE_OPTIONS` or `GIT_*_COMMAND`, and spill files are private to their workspace.
- **Errors and logs (`core`, `web`, `logger`).** 5xx answers no longer carry raw
  error messages; pages hide error details outside development; file logs keep each
  entry on one line, so request text cannot forge log lines; failed action forms no
  longer echo password, token, OTP or card fields.
- **Development tools (`web`, `devtools`).** The dev server keeps its host check with
  dynamic sites, and devtools answer only loopback hosts without proxy headers, so a
  website pointed at `127.0.0.1` can no longer read your source or request history.
- **New apps (`create-warlock`).** 10 MB per-file uploads, CORS limited to
  `CORS_ORIGINS`, 1-hour access tokens with rotating refresh tokens stored as digests, a
  rebuilt password reset (crypto codes, HMAC at rest, 5 tries), admin checks on the
  example `users` and `posts` routes, and every `.env.*` file ignored by git.
- **Dependencies.** Minimum `fastify` 5.12.6, `fast-jwt` 6.3.4 and `devalue` 5.9.3;
  the `nodemailer` and `sharp` peer ranges include their fixed releases.

## 2. Performance

- **One render per page.** A page document and a client navigation render once instead
  of twice, loader data is serialized fewer times, and production documents preload the
  page's own chunks.
- **Faster responses (`core`).** `Response.send()` passes plain data straight to the
  serializer and no longer waits three event-loop turns per JSON response; route
  handlers, middleware lists and security headers are built once; the shared rate
  limiter makes one cache round trip per request instead of three. Opt-in
  `http.compression` (gzip or brotli).
- **Smaller boot.** `@fastify/http-proxy` (about 83 ms to load) and `oxc-parser` (about
  14 ms) load only when used.
- **Contexts (`context`).** All contexts share one `AsyncLocalStorage`. In the report's
  benchmark, 300,000 awaits took 68 ms with one storage and 182 ms with four, the number
  a request used to carry.
- **Cache (`cache`).** Per-operation logging is off by default (a memory `get` hit
  measured 6.4 µs without it and 30.8 µs with it); memory drivers hold at most 10,000
  entries; tagged writes sample members instead of reading whole values; a Redis `set()`
  with its SWR sidecar is one round trip instead of two.
- **Models and queries (`cascade`).** An insert makes about three full copies of the
  document instead of eight; sibling eager loads run concurrently; `count()` skips sort
  and projection stages; `chunk()` pages by key; PostgreSQL `insertMany()` splits
  batches past the bind-parameter limit; MongoDB command monitoring is off in
  production unless something listens.
- **HTML and text conversion (`ai`, `ai-tools`, `ai-workspace`).** The web-tool HTML
  converter turns a 1 MB page of paragraphs into Markdown in 0.14 s instead of 21 s
  (table cells: 0.07 s instead of 24 s). The RAG HTML loader handles 1 MB of unclosed
  `<script>` openers in 0.04 s, where 40 KB of bare `<` used to take 1.7 s. The failed
  edit hint for a 2,000-line text against a 20,000-line file drops from about 3.2 s to
  about 0.12 s.
- **AI stores (`ai`, `ai-panoptic`).** Checkpoint retention works on Postgres and
  Redis, Redis checkpoints store one key per turn, the procedural skill store lists
  skills with one cache read, input guardrails run once per distinct text, and the
  Panoptic dashboard polls trace summaries instead of every full trace.
- **Workers and messaging (`queue`, `scheduler`, `herald`).** Finished jobs are pruned
  with one statement, the memory driver no longer copies every job on each poll, the
  scheduler tick never waits for a job, and RabbitMQ requests share one reply
  consumer.
- **Web serving (`web`).** Multi-site route tables are compiled once per site,
  multi-site sitemaps are cached per site, hover prefetch waits 65 ms, and live pages
  stop polling in hidden tabs. Opt-in `web.loaders: "parallel"`.
- **Published packages.** Tarballs ship source maps without the embedded sources; in
  the 5.51 `core` tarball, source maps were 5.2 MB of its 11.4 MB. Stack traces keep
  every file name and line.

## 4. Upgrade notes

Most likely to be noticed first. Each line ends with the way back.

1. **Update the family.** Run `npx warlock update`, then
   `npx warlock release-notes --from 5.52.0`.
2. Multipart requests over 25 MB in total answer 413 → raise
   `http.multipart.maxTotalSize`, or set `uploads: { maxTotalSize }` on the route.
3. A client's `?paginate=false` gets one page of at most `maxPerPage` rows →
   `allowClientUnpaginated = true` on the repository, or
   `repository.allowClientUnpaginated: true`.
4. `strictMode: "strip"` drops unknown fields on save instead of failing, and
   MongoDB updates validate the whole touched nested field (stored data that no longer
   fits the schema fails the save; undeclared nested objects are stripped) →
   `strictMode = "fail"` or `"allow"`, or fix the schema.
5. Seal: arrays over 10,000 items and records over 10,000 keys fail; at most 100
   item errors are reported → `.maxLength(n)` / `.maxKeys(n)`, or
   `configureSeal({ maxArrayItems: Infinity, maxRecordKeys: Infinity, maxErrors: Infinity })`.
6. `ai.serve` sends text deltas and `{ text, data, error }` only, and refuses a
   non-string `input` →
   `events: "all", toResult: (result) => result`, and your own `toInput`.
7. `v.file().image()` refuses svg and non-raster bytes; type rules refuse svg, html
   and xml bytes; saved markup is stored as `application/octet-stream` →
   `image({ svg: true })`, list the type, `uploads.trustClientContentType: true`.
8. Finished jobs are pruned (24 h / 1,000 completed, 7 days / 5,000 failed), and
   job data always carries the `{ __warlock, payload }` envelope; a 5.52 worker cannot
   read 5.53 jobs → `defaultJobOptions: { removeOnComplete: false, removeOnFail: false }`;
   upgrade workers before dispatchers.
9. Error pages hide details under `warlock start` and for any `NODE_ENV` other than
   development, test or unset → use `warlock dev`; the server log keeps the details.
10. 5xx answers built from a raw `Error` are `{ error: "Internal server error." }` →
    send the body you want clients to read.
11. Cache operation logging is off → `logging: true` in the cache config.
12. Memory cache drivers evict past 10,000 entries; keep rate limits and lockouts in
    Redis or Postgres in production → `maxSize: Infinity`.
13. With `http.trustProxy: true`, `X-Real-IP` is not read → `http.realIpHeader: "x-real-ip"`.
14. Requests still being sent after 5 minutes time out → raise
    `http.requestTimeout`, or `0`.
15. Production `/ready` answers `{ status }` only, caches results for 1 s and fails a
    check after 2 s → `http.health.details: true`, `cacheTtl: 0`, `checkTimeout: 0`.
16. `Auth` models no longer serialize `password` → read `user.get("password")`, or
    `public static hidden: string[] = []`.
17. Provider login onto an existing unverified account fails with 403 `EC012` →
    `auth.providers.linkExisting: "always"`.
18. `requestPasswordReset` / `requestOtp` no longer throw on a failed send → listen to
    `password.resetDeliveryFailed` / `otp.deliveryFailed`, or `awaitDelivery: true`.
19. More than `max` simultaneous requests on one throttle bucket get 429 → raise
    `max` on that route.
20. GitHub, Discord, LinkedIn, Apple, Facebook and X logins fail after 5 seconds →
    raise the provider's `timeoutMs`.
21. MongoDB `whereLike` patterns with more than two `%` or 256 characters throw →
    `driverOptions: { like: { maxWildcards, maxLength } }`.
22. MongoDB `has` / `whereHas` / `doesntHave` throw, and `update()` / `delete()` on
    grouped, joined or unwound queries throw → filter or write with `whereIn("id", ids)`.
23. MongoDB date and array filters that were ignored now filter, `$` field names and
    object values in operator positions throw → pass primitives, or `whereRaw()`.
24. `paginate()` caps the page size at 1000 and throws on non-numeric `limit` / `page`
    → `maxLimit: Infinity`.
25. MongoDB `query` events are off in production unless something enables them (core's
    request log does) → `queryEvents: true`.
26. `guardedFetch` (`ai`) and the web tools: timeouts include the body, custom headers do
    not follow cross-origin redirects, and an app's own global dispatcher options do
    not apply → raise `timeoutMs`, `crossOriginHeaders`, inject `policy.fetch`.
27. `http_request` with `baseUrl` refuses other hosts → `allowHosts`.
28. Agents with output guardrails stream one delta per trip after the check →
    `stream: "unguarded"`.
29. `semanticCache` skips runs without a `sessionId`, does not store tool runs, serves
    an answer only to the same agent and conversation, and old entries miss once →
    `sessionId` or `scope: "shared"`, `cacheToolRuns: true`.
30. Workspace `grep` refuses lookarounds and backreferences and skips files over 2 MB
    → rewrite the pattern, `search.maxFileBytes`.
31. Workspace shell policies with command rules refuse `PATH`, `NODE_OPTIONS`,
    `GIT_*_COMMAND` and similar assignments → `shell.allowAssignments`.
32. Postgres and Redis checkpoints keep only the latest `keepSnapshots` (100) turns,
    and Redis checkpoints use a per-turn layout (upgrade every instance together) →
    `keepSnapshots: "all"`.
33. `saveSkill` refuses existing skill names, and `runReviewGate` throws when the
    candidate changed → `review.allowUpdates: true`.
34. Panoptic's own dashboard store keeps 1,000 traces, and `GET api/traces` returns
    200 summaries → `panoptic.capacity: 0`, `?full=1`.
35. MCP results over 10 MiB fail → `maxResponseBytes`.
36. Page cache: at most 1,000 query variants per route, tracking parameters are not
    stored, and `cache` routes may send `Vary: Cookie, locale` →
    `maxEntriesPerRoute: false`, declare `app.localeCodes`.
37. Failed page actions no longer refill password, token, secret, OTP, PIN or card
    fields, and `web.forms.redactValues` adds to the built-in list → rename the field.
38. `warlock dev` with a dynamic site refuses unknown hosts →
    `web.devAllowedHosts: [".tenant.test"]` or `true`.
39. Devtools on a custom hostname or behind a local proxy answer 404 →
    `allowedHosts`, `allowProxied: true` in `src/config/devtools.ts`.
40. `FileLog` writes line breaks in messages as `\n`; `ConsoleLog` drops terminal
    escapes other than colours; write failures go to `log.onChannelError` →
    `escape: false` for file logs.
41. Subclasses of `FileLog` that overrode `onSave()` or `writeGroupedMessagesToFile()`
    → override `writeEntries()` / `writeEntriesSync()`.
42. `url()` refuses `javascript:`, `data:`, `vbscript:` and `file:`; `v.number()`
    refuses `NaN` and infinities; number mutators refuse non-numeric input →
    `url({ protocols: [...] })`.
43. `onOneServer()` interval jobs no longer run at boot, and `job:skip` fires for a due
    job still running → `.at()` or `cron()`.
44. Invalid herald messages are rejected instead of requeued → add a dead-letter
    exchange.
45. `ipFilter()` throws at boot on a pattern that is not an IP or CIDR block → fix
    the entry.
46. Array indices above 1000 in input keys are dropped, urlencoded forms over 1000
    fields answer 413 → `http.input.maxArrayIndex`, `http.urlencoded.maxFields`.
47. One-time cache misses: `listCached` keys, idempotency records with params or a
    query, object cache keys with separator characters, multi-site page cache keys.
    Temporary-URL tokens issued before the upgrade are refused → issue new links.
48. `decrypt()` refuses non-16-byte IVs and tags; `putFromBase64` / `putFromUrl` store
    the extension's MIME type; `downloadFileFromUrl` saves unknown extensions as `.bin`
    → `{ mimeType }`, `allowedExtensions`.
49. `Restful.bulkDelete` refuses more than 1000 ids → `bulkDeleteLimit`.
50. Cascade: `upsert()` / `restore()` / `restoreAll()` honour global scopes;
    `set()` / `merge()` / `unset()` refuse `__proto__`, `constructor` and `prototype`
    paths; unordered `chunk()` reads in primary-key order → add `orderBy()` for offset
    paging.
51. Sitemap paths are percent-encoded, and a multi-site `/sitemap.xml` may be up to 5
    minutes old → `web.sitemap.regenerateEvery`.
52. `ai-cli` warns once in production when `inheritEnv` is unset →
    `inheritEnv: "curated"` or `true`.
53. `warlock doctor` may print new warnings; its exit code is unchanged.
54. New apps only: existing apps keep their files. Copy the new upload limit, CORS,
    token, multipart, `.gitignore` and `agentKit.pick` settings from a fresh app, and
    review the old password-reset code.
55. To get the fixed `nodemailer` and `sharp` releases, update them to `^10.1.4` and
    `^0.35.5`; set `tls.rejectUnauthorized: false` for attachment hosts with
    self-signed certificates.

## Verification

- The release tree passed the typecheck of every package, every package's unit tests
  (22,241 tests, none failing, 29 skipped), format, lint and the public-text,
  spec-coverage and skill gates in one final pass.
- Each area of the change was read by an independent reviewer after it was written; the
  regressions the reviewers found were fixed before that final pass. The release gate
  also runs every package's tests and the blog app on the tarballs.
- Not run: the database integration suites against live MongoDB, PostgreSQL and Redis,
  a live RabbitMQ broker, and a live DNS-rebinding test; these paths are covered by
  unit specs with fakes.
