# Warlock.js 5.63.1 — release summary

Released 2026-11-22.

All **34 packages** (`@warlock.js/*` and `create-warlock`) move to 5.63.1 together;
keep every family package on the same version. This patch fixes PostgreSQL `date` columns, which read
back a day early on servers whose time zone is ahead of UTC, and lets an app pass its own pg type parsers.
The package with changes is `cascade`.

## Check first

- If your app runs PostgreSQL on a server ahead of UTC and stores `date` columns, values now read back as
  the stored calendar day (UTC midnight). Records that were edited and saved while the value read a day
  early were stored a day early; check edited dates.
- If you worked around it with `pg.types.setTypeParser(1082, …)` or `TZ=UTC`, you can remove that.

---

## 1. What changed

- **`date` reads as its calendar day.** A `date` (and `date[]`) column reads back as a `Date` at UTC
  midnight of that day, whatever the Node process time zone: `2026-08-24` under `TZ=Africa/Cairo` used to
  read as `2026-08-23T21:00:00.000Z`. `infinity`, `-infinity` and BC dates keep pg's parser; `timestamp`
  and `timestamptz` are unchanged.
- **`clientOptions.types` is used.** A `types` object passed in the PostgreSQL `clientOptions` reaches the
  pool and replaces Cascade's built-in parsers (int8 as a safe number, `date` as UTC midnight); it used to
  be overwritten.

## 2. Verified

- Specs call the pool's parsers directly (plain dates, arrays with `NULL`, `infinity`, BC values) and check
  that a supplied `types` object is the one the pool gets.
- One typecheck of the family, the strictness gate and every package's full test suite ran green on the
  final tree, along with format, lint, the public-text, skill and release-note checks and the docs build.
