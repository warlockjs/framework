# Warlock.js 5.34.1 — release summary

Released 2026-10-19.

All **33 packages** (`@warlock.js/*` and `create-warlock`) move to 5.34.1 together;
keep every family package on the same version. This patch has **no breaking
changes**.

---

## 1. Page setup files are the documented way to add page logic

A page's logic lives in its setup file; its UI file holds only components.

```ts title="src/web/about.setup.ts"
import type { PageConfig } from "@warlock.js/web";

export async function loader() {
  return { teamName: "Acme" };
}

export const config = {
  route: { path: "/about", name: "about" },
  metadata: ({ data }) => ({ title: `About ${data.teamName}` }),
} as const satisfies PageConfig<typeof loader>;
```

```tsx title="src/web/about.page.tsx"
import type { PageProps } from "@warlock.js/web";
import type { loader } from "./about.setup";

export default function AboutPage({ data }: PageProps<typeof loader>) {
  return <h1>{data.teamName}</h1>;
}
```

- Setup files hold `config`, `loader`, `register`, and `action` / `actions`.
  Metadata always lives in `config.metadata`; it is not a separate export.
  `register()` still runs on the server and in the browser.
- The same pairing works for `layout.tsx` + `layout.setup.ts`, `root.tsx` +
  `root.setup.ts`, and error pages.
- A new **Page setup files** docs page explains the split. Every web docs
  example, skill, the `create-warlock` starter and the page/layout/root
  generators now follow it.
- The error for an export a setup file may not declare now lists every allowed
  name (it previously omitted `action` and `actions`).

## 3. Added

### Custom HTTP responses for MCP auth refusals (`ai-tools`)

`ai.mcp.serve` HTTP transports accept `onAuthRefusal`, used by the MCP endpoint
and `transport.routes` after a failed authentication check. It can set the
status, an allowlisted set of headers and a JSON body, so an app keeps its
existing auth-error contract. Host and Origin checks still run first, the
current refusal stays the default, thrown auth errors are never exposed, and a
failing hook falls back to the default.

### Which secrets backend is active (`core`)

`await secrets.backend()` (and `SecretStore.backend()`) returns `"keychain"`,
`"file"` or `"memory"`, with no credential material. It reuses core's own
selection and its memoized keychain probe, so it always agrees with the store.
