# Warlock.js 5.46.0 — release summary

Released 2026-11-06.

All **33 packages** (`@warlock.js/*` and `create-warlock`) move to 5.46.0 together;
keep every family package on the same version. This release fixes issues found while
building a multi-tenant app on 5.45.0: notifications can be keyed by recipient type,
PostgreSQL array and JSON columns save correctly, seeding works after
`migrate --fresh`, and several build and dev-server errors now say what to fix. The
packages with code changes are `cascade`, `core`, `create-warlock`, `notifications`,
`seal` and `web`.

---

## 1. Behaviour changes

- **`warlock migrate --fresh`** now empties the seed log (`_seeds`, `_seed_records`), so
  the next `warlock seed` runs every seeder again. A seed run that skips every seeder
  prints a warning.
- **`warlock seed`** imports every module's `main.ts` after its connectors start,
  together with the early-phase connectors in `warlock.config.ts > connectors` (the
  queue, for example). A `main.ts` that throws now stops the seed run with that error.
- **PostgreSQL**: a number array written to a native array column (`INTEGER[]`) is bound
  as an array, and a string, number or boolean written to a `json` / `jsonb` column is
  JSON-encoded. Both used to fail at the database.
- **`warlock generate.typings`** skips a page with an unsupported route path (with a
  warning naming it) instead of stopping for every page. The build still fails on it.

---

## 2. Notifications (`notifications`, `core`)

- **Security: recipient types.** Declare `columnMap.recipientType` (for example
  `"recipient_type"`) and in-app reads, counts, mark-read, mark-unread, find and dismiss
  filter by type and id, so staff `5` and customer `5` never share an inbox. The
  `database` channel stores the type from the recipient model (an auth model's
  `userType`, otherwise its table name).
- Methods accept a model, `{ type, id }` (`RecipientRef`) or a bare id. With the column
  declared, a bare id throws `RecipientTypeRequiredError`.
- `notificationColumns(…, { recipientModel })` derives the id column type from the
  recipient model; without it the default stays UUID.
- New apps: the generated notifications scaffold declares the recipient type column.

---

## 3. Database (`cascade`)

- `Model.exists(filter?)` returns whether any record matches.
- `whereNot` / `orWhereNot` accept every shape `where` does:
  `whereNot("status", "archived")`, `whereNot("age", "<", 18)`, `whereNot({ … })`.
- PostgreSQL `orderBy` on a select alias (`count(*) AS total`) orders by that alias.

---

## 4. Web (`web`, `core`)

- tsconfig `paths` aliases (such as `@shared/*`) resolve in `warlock dev` and the client
  build. Aliases passed to the Web connector still win.
- A `layout.tsx` outside the routed page tree gets a startup warning.
- The module-boundary error and the `WL9022` message name the module's `web/` folder as
  the place for constants shared by browser and server code;
  `ProjectionAmbiguityError` suggests a literal or a `*.client.ts` file.

---

## 5. Tooling, tests and validation (`core`, `seal`)

- `warlock dev` writes `.warlock/dev.pid` with the PID of the process that serves, and
  forwards `SIGINT` to it.
- `warlock typecheck` / `warlock check` warn once (`WL7103`) when typings in
  `.warlock/typings` are missing or older than `src`.
- `responseSchema` accepts arrays of plain objects as `[{ id: "int", … }]`.
- The test server boots when the default storage driver is a cloud driver and the
  storage fake is on, and finds modules when the project path contains `[`, `(` or `{`.
- `requiredWith` / `requiredWithout` docs say the other field is looked up from the
  root; use the `Sibling` variants inside nested objects.

---

## 6. Scaffolding (`create-warlock`, `core`)

- `warlock add test` pins `@vitest/coverage-v8` to the starter's exact `vitest` version,
  so npm install no longer crashes on a fresh scaffold.
- The starter's storage config reads `STORAGE_DRIVER` and `R2_PREFIX` (default: the
  app name) instead of a shared `warlock.js` prefix.

---

## 7. Upgrade notes

1. **Update the family.** Run `npx warlock update`.
2. **Read what changed.** Run `npx warlock release-notes --from 5.45.0`.
3. **Several identity types receiving in-app notifications?** Add a nullable
   `recipient_type` column, backfill it, then declare `recipientType` in the
   notification model's `columnMap`. See "Recipient types" in the in-app store guide.
4. **Relying on `migrate --fresh` keeping seed history?** It is now cleared; use
   `warlock migrate` without `--fresh` to keep it.
5. **Sharing one R2 bucket across apps scaffolded before 5.46.0?** Set `R2_PREFIX`
   per app.
