# Warlock.js 5.64.0 — release summary

Released 2026-11-23.

All **34 packages** (`@warlock.js/*` and `create-warlock`) move to 5.64.0 together;
keep every family package on the same version. This minor gives Grimoire drift controls: a guard that
checks a change against its task, code rules, locked tests and protected areas, screenshots of each
acceptance criterion in each language with an approved baseline, and a Bird view that shows every
feature, flow and criterion against the app's languages in one table. `scry --search` lists the files
that change together and reads Arabic and accented text. Full-text search on PostgreSQL takes a
language, the database cache driver works on PostgreSQL, API tests get an HTTP server per Vitest
worker, and new apps start with a `grimoire/` folder, a components page and the guard in CI and as an
agent hook. The packages with changes are `grimoire`, `core`, `cascade`, `devtools` and
`create-warlock`.

## Check first

- **API tests use a server per worker.** `testGet`, `actingAs` and the other request helpers start an
  HTTP server inside each Vitest worker on the first request, so it reads that worker's database. In an
  API-only app `warlock add test` no longer writes `src/test-global-setup.ts`. An app with
  `@warlock.js/web` keeps it: the worker's server does not serve web pages, so the shared server of
  `startHttpTestServer()` does, and while its port is published the helpers use it (it reads worker 1's
  database, as before).
- **Database cache driver on PostgreSQL.** `cacheMigration` now creates `expiresAt` as a big integer; it
  created `expires_at` as a timestamp, which the driver never wrote, so every `set` failed. An app that
  ran `cacheMigration` on PostgreSQL drops the `cache` table and runs the migration again.
- **PostgreSQL full-text index weights** are the letters `"A"` to `"D"` (MongoDB: whole numbers from 1 to
  99999). A number on PostgreSQL now stops the migration with a message naming the column; it gave
  invalid SQL before.
- **Flows with a page step** answer two more case questions, `server unreachable` and `server error`.
  `grimoire check` asks for them (`GR1012`) on those flows only.

## 1. What changed most

- **Guard a change against its task.** `warlock grimoire guard [task]` reads the git diff against the
  base and reports files outside the task's features and `Files:` line, removed flows, criteria and
  cases, deleted `@proves` tests, edited `Locked:` tests, tests with fewer assertions, protected areas the
  task does not name in `Touches:` (migrations, auth, config, lockfile, dependencies, public API),
  commits that name no task, and the code rules on added lines. It never boots the app. With `--hook` it
  is a Claude Code `Stop` hook that never traps an agent: no task, no git, or a second stop exit 0.
- **Code rules.** `logical-css`, `specific-errors`, `type-discriminator` and `no-js-imports`
  (`GR3007`–`GR3010`), with a `grimoire-allow <rule>: <why>` escape comment. `grimoire check` runs the
  rules `grimoire/settings.md` names; the guard runs all four on the lines a change adds.
- **Screenshots and approvals.** `// @shows <feature>/<flow> AC-n` above a `shows()` scene saves one
  screenshot per language. `grimoire/approved/baseline.json` records the approved flows, criteria,
  cases, proving tests and images, and every change since shows as "changed, not approved" until
  `warlock grimoire approve` (or the tab's buttons in development). Screenshots are optional: modes
  `changed` (default), `all` and `off`, and `screenshots: false` per flow.
- **Bird view.** A Grimoire tab with every feature, flow and criterion against the app's languages: the
  test status, the captured thumbnail and the approval state per cell, the approved and captured image
  side by side, and a jump-to filter. It works with no screenshots and no baseline.
- **`scry --search` lists what changes together.** After the hits it prints the files the top hits
  import and are imported by inside their feature, the tests that prove them, and a
  `next: warlock scry --impact <file>` line; a weak match says to use grep. One tokeniser reads Arabic and
  accented Latin in the query and the index, so `شحنة` finds `الشحنة` and `cafe` finds `café`.
- **Release stamping and What's new.** `warlock grimoire release --stamp` moves the `## Unreleased`
  entries of the feature changelogs under the release and writes a missing release file. The Product
  map has a What's new view per release, in share links too.

## 2. New options and APIs

- Grimoire: `warlock grimoire guard`, `approve`, `reject`, `approve api`, `release --stamp`;
  `grimoire/settings.md` (`languages`, `screenshots`, `rules`, `protected`); `shows()` in
  `@warlock.js/grimoire/warlock`; panel routes `GET /matrix`, `GET /product/whats-new`, `POST /approve`,
  `POST /reject`; codes `GR3007`–`GR3010`, `GR4011`–`GR4019`, `GR7006`–`GR7013`, `GR9008`–`GR9010`;
  `GuardReport`, `GrimoireMatrix`, `ScryAlsoChange`, and the search result's `alsoChanges`, `weak` and
  `next`.
- Cascade: `whereFullText` / `orWhereFullText` / `whereSearch` options `{ language, weights }`; the
  PostgreSQL data-source option `textSearchConfig`; `whereContains` / `orWhereContains`;
  `FullTextIndexWeight`. The integration harnesses use an existing database from `LOCAL_PG_*` /
  `LOCAL_MONGO_*`.
- Core: `page.mockRequests()`, `clearMocks()` and `setExtraHeaders()` in browser tests; a tooling
  command's preload can be `tolerant`; `collectFiles({ files })`; `recommendedTestWorkers()` respects
  `WARLOCK_TEST_DATABASES`.
- Devtools: in development a failing dashboard or panel route answers with a short `ref`, and a package
  panel's `ctx.api` rejects with `status` and `ref`.

## 3. Fixes

- A closed production monitor URL hit with a request body answers after the body is read, like an
  unknown URL (the app's own 400, 413 or 415 for a bad body).
- `warlock grimoire build`, `check` and `inspect` go on when the app's config or bootstrap fails during
  the preload, so Grimoire's cached-routes fallback works.
- The book lists and fingerprints the top-level code files of a mobile app folder (`App.tsx`).
- `warlock dev` logs file-watcher errors instead of dropping them.
- The database cache driver finds the unique `key` index once and writes with one upsert, and works on
  PostgreSQL (see "Check first").
- `orWhereFullText` on PostgreSQL uses the same NULL-safe vectors and language as `whereFullText`.

## 4. Upgrade notes

- `--search` text output gains the `changes with the top hits:` block and a `next:` line; scripts should
  read `--json`.
- Existing apps get no code-rule findings in `grimoire check` until `grimoire/settings.md` names `rules`.
- To add the guard to an existing app, copy the starter's `.github/workflows/grimoire-guard.yml` and the
  `Stop` hook from the Drift controls guide into `.claude/settings.json`.
- A share link can load any image under `grimoire/screenshots/`, which also holds the approved images and,
  where browser tests ran, the captured ones; share an app whose screens you would show anyway.
