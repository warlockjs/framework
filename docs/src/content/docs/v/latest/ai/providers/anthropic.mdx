> Standalone — usable in any Node project, no `@warlock.js/core` required.

`@warlock.js/ai-anthropic` is the Anthropic provider adapter for
[`@warlock.js/ai`](/v/latest/ai/). It wraps the official
`@anthropic-ai/sdk` Messages API and hands you a vendor-neutral
`ModelContract` — the same shape every agent, workflow, and supervisor
already speaks. Swap Claude in for any other provider without touching
your orchestration code.

## Construct

One `AnthropicSDK` holds one live `Anthropic` client. Build it once at
boot and reuse it everywhere — every model it produces shares the same
connection pool, auth, and rate-limit state.

```ts
import { AnthropicSDK } from "@warlock.js/ai-anthropic";

const anthropic = new AnthropicSDK({
  apiKey: process.env.ANTHROPIC_API_KEY!,
});
```

The config extends the upstream `ClientOptions`, so anything the SDK
accepts works here too — most usefully `baseURL` to point at a gateway
or proxy, and `provider` to relabel the upstream (it defaults to
`"anthropic"` and flows through to `AgentReport.model`, logs, and any
provider-aware middleware).

```ts
const anthropic = new AnthropicSDK({
  apiKey: process.env.ANTHROPIC_API_KEY!,
  baseURL: "https://my-gateway.internal/anthropic",
  provider: "anthropic-gateway",
});
```

## First call

Build a model, hand it to an agent, run it. `execute()` never throws —
failures land in `error` as a typed `AIError`.

```ts
import { ai } from "@warlock.js/ai";
import { AnthropicSDK } from "@warlock.js/ai-anthropic";

const anthropic = new AnthropicSDK({ apiKey: process.env.ANTHROPIC_API_KEY! });

const assistant = ai.agent({
  model: anthropic.model({ name: "claude-sonnet-4-6" }),
  systemPrompt: "You are a concise senior TypeScript engineer.",
});

const { text, usage, error } = await assistant.execute("Why use generics?");

if (error) {
  console.warn(error.code, error.category);
} else {
  console.log(text, usage.total);
}
```

## Use as a model

```ts
const model = anthropic.model({ name: "claude-sonnet-4-6", temperature: 0.7 });
// Pass to any @warlock.js/ai agent / workflow / supervisor.
```

Anthropic requires a token cap (`max_tokens`) on every request. When you
don't set `maxTokens` (per-model, per-call, or through an agent's
`modelOptions`), the adapter picks a default sized for agent work:

| Request                      | Default `max_tokens`                                                                                                              |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Streaming (`stream()`)       | The model's documented max output — 128K for the Claude 5 family and Opus 4.6–4.8 / Sonnet 4.6, 64K for Opus / Sonnet / Haiku 4.5 |
| Non-streaming (`complete()`) | **16384**, capped by the model's max output                                                                                       |
| Unknown model id             | **16384** (set `maxOutputTokens` on the model to use its real limit)                                                              |

The non-streaming default stays at 16384 because the Anthropic SDK refuses
a non-streaming request whose `max_tokens` implies more than ten minutes
of generation unless the client sets a `timeout`; stream long outputs (an
agent's `stream()`), or set `maxTokens` and a client `timeout` yourself.
With extended thinking on, the default also keeps room for the thinking
budget plus 4096 answer tokens. Limits are taken from Anthropic's model
pages (checked 2026-10-17).

```ts
anthropic.model({ name: "claude-haiku-4-5" }); // stream: 64000, complete: 16384
anthropic.model({ name: "my-gateway/opus", maxOutputTokens: 128_000 }); // a gateway id
anthropic.model({ name: "claude-opus-5-5", maxTokens: 8192 }); // explicit cap always wins
```

A response that still hits the cap ends the agent run as incomplete
(`AgentIncompleteError`, `report.status: "incomplete"`) — or continues,
with `continueOnOutputLimit`. See
[Cut-off responses](/v/latest/ai/agents/run-agent/#cut-off-responses--reportstatus-incomplete).

## Capabilities

- **Tool calling** — vendor-neutral `ToolConfig`s map to Claude
  `tool_use` blocks; tool results round-trip back as `user` turns.
- **Streaming** — `stream()` yields text `delta`s, a `tool-call` once a
  `tool_use` block's arguments have fully accumulated, and a terminal
  `done` carrying the final finish reason and usage.
- **Structured output** — on by default. A root-object JSON Schema is
  forwarded to Claude's native `output_config.format` (JSON-schema
  structured outputs). Non-object schemas or a `structuredOutput: false`
  override fall back to the agent's soft system-prompt hint plus
  client-side validation.
- **Vision** — auto-detected from the model name. Every Claude 3,
  3.5/3.7, and 4 family model is treated as multimodal (prefixes
  `claude-3`, `claude-4`, `claude-opus-4`, `claude-sonnet-4`,
  `claude-haiku-4`); pre-3 families (`claude-2`, `claude-instant`) are
  text-only. Override either way with the `vision` flag.
- **No embedder.** Anthropic ships no first-party embeddings API, so
  this adapter has no `embedder()`. Pair Claude with an embedding
  provider — [OpenAI](/v/latest/ai/providers/openai/),
  [Google](/v/latest/ai/providers/google/),
  [Bedrock](/v/latest/ai/providers/bedrock/), or
  [Ollama](/v/latest/ai/providers/ollama/) — when you need vectors.

Image attachments accept both a remote `url` and inlined `base64`
bytes (`image/jpeg`, `image/png`, `image/gif`, `image/webp`).

## Prompt caching

Claude bills the most-repeated tokens — tool schemas, the system prompt — at a fraction of the input rate when reused across trips. The adapter exposes **two independent breakpoints**:

| Where             | How you opt in                                                  | What it caches                                                                                                                   |
| ----------------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **Tool schemas**  | `model({ promptCaching: true })` (per-model)                    | Marks the tools block `cache_control: { type: "ephemeral" }` so multi-trip agents reuse tool definitions at the cache-read rate. |
| **System prompt** | `modelOptions: { cacheControl: { breakpoints: 1 } }` (per-call) | Emits the system prompt as a cached `text` block.                                                                                |

```ts
const model = anthropic.model({
  name: "claude-sonnet-4-6",
  promptCaching: true, // cache the static tool schemas across trips
});
```

`promptCaching` is **off by default**: a cache _write_ costs ~1.25×, so a breakpoint only pays off when the cached prefix is read at least twice (multi-trip / multi-turn agents). The split is deliberate — tool schemas are static (a per-model decision), while the system prompt often carries per-turn placeholders (a per-call decision). Reads and writes flow back as `Usage.cachedTokens` / `Usage.cacheWriteTokens`.

:::note[Bedrock differs]
On the [Bedrock adapter](/v/latest/ai/providers/bedrock/), `promptCaching` is a _capability override_ rather than an opt-in — auto-inferred `true` for Claude 3.5+/3.7/4 and Nova, mapping per-call `cacheControl` breakpoints to Converse `cachePoint` blocks. Set `promptCaching: false` to force it off.
:::

Per call, `cacheControl: { ttl: "1h" }` overrides the model's `promptCacheTtl` for the entries that call writes.

## Thinking on Claude 5 models

Claude Opus 5.5, Sonnet 5.5 and Fable 5 / 5.1 always think. They reject `thinking: { type: "disabled" }` and `budget_tokens` with a 400, so the adapter never sends either to them: a `reasoning` option becomes `thinking: { type: "adaptive" }` plus `output_config.effort`. `effort: "none"` depends on the model:

- **Sonnet 5.5** turns thinking off with `thinking: { type: "between_tools" }`, so the adapter sends exactly that, with no `output_config.effort` and no `display` (the API rejects either beside it; the model default effort, `high`, is within the range it allows).
- **Opus 5.5 and Fable 5 / 5.1** have no thinking-off form. The adapter leaves `thinking` out and the model still thinks at its default effort, so pass `effort: "low"` to spend less.

Thinking text is empty by default on these models. Ask for readable summaries with `thinkingDisplay`:

```ts
await agent.execute("Plan the migration.", {
  modelOptions: {
    reasoning: { effort: "high" },
    providerOptions: { anthropic: { thinkingDisplay: "summarized" } },
  },
});
```

## Provider blocks and compaction

Thinking, redacted-thinking, compaction and server-tool blocks have no place in the neutral `content` string, and several features only work when the assistant turn goes back exactly as Claude sent it. When a response has such a block, the adapter returns the whole ordered turn as `blocks`. The agent stores it on the assistant message and the adapter replays it verbatim on the next call.

Claude checks that every turn before a replayed thinking block is unchanged, including the tool-call turns and tool results in between. Storing only the final reply with its blocks drops those turns, and the next request fails (or the block is dropped). To carry blocks across runs, keep the run's turns from `report.messages` (set `captureMessages: true`) and append the final reply:

```ts
// The agent runs with `captureMessages: true`.
const result = await chat.execute(question, { history });
const finalTrip = result.report.trips.at(-1);

history = [
  // Your history, the question, and every tool-call turn and tool result of the run.
  // The agent re-adds the system prompt on each run, so leave it out here.
  ...(result.report.messages ?? []).filter((message) => message.role !== "system"),
  // The final reply, as the model sent it.
  { role: "assistant", content: finalTrip?.output ?? "", blocks: finalTrip?.blocks },
];
```

`result.blocks` is set only for a single-trip run, where the reply is the whole turn.

The adapter replays a stored block only when it is a well-formed assistant-turn block from this adapter (its `data.type` matches its `type`); otherwise it rebuilds the turn from `content` and `toolCalls`. Treat a transcript that comes from a client like any other client input.

Beta features go through `providerOptions.anthropic`: `betas` routes the call to the beta endpoint, and `body` adds request fields as-is, after the adapter's own. `body` may not set `model`, `messages`, `system`, `tools`, `mcp_servers` or `stream`, which the adapter builds from the call; the call fails with `InvalidRequestError` if it tries. Server-side compaction:

```ts
const agent = ai.agent({
  model: anthropic.model({ name: "claude-opus-5-5" }),
  modelOptions: {
    providerOptions: {
      anthropic: {
        betas: ["compact-2026-01-12"],
        body: { context_management: { edits: [{ type: "compact_20260112" }] } },
      },
    },
  },
});
```

The same `body` carries `fallbacks`, `inference_geo` or any other field the Messages API accepts. Other adapters ignore the `anthropic` key, so the options are safe in a fallback chain.

## Finish reasons

| Claude `stop_reason`            | `finishReason`                                    |
| ------------------------------- | ------------------------------------------------- |
| `end_turn`, `stop_sequence`     | `stop`                                            |
| `tool_use`                      | `tool_calls`                                      |
| `max_tokens`                    | `length`                                          |
| `model_context_window_exceeded` | `context_exceeded`                                |
| `pause_turn`                    | `pause_turn` (the agent resumes it automatically) |
| `refusal`                       | `refusal`                                         |

## Vision

Pass image parts on a user message — the agent resolves attachments
before they reach the adapter, which forwards them as Claude `image`
blocks.

```ts
const model = anthropic.model({ name: "claude-sonnet-4-6" });

const response = await model.complete([
  {
    role: "user",
    content: [
      { type: "text", text: "What's in this photo?" },
      { type: "image", source: { url: "https://example.com/cat.jpg" } },
    ],
  },
]);
```

## Pricing and usage

Every response reports token `usage` (`input`, `output`, `total`).
Claude bills input and output separately with no pre-summed total, so
the adapter computes `total` itself; prompt-cache reads surface as
`cachedTokens` when present.

To turn tokens into money, attach a `pricing` registry — keyed by model
name, in USD per million tokens. It can live on the SDK (one source of
truth) or per-model (wins when both are set). With pricing set, the
framework rolls cost up through every node of the `AgentReport`.

```ts
const anthropic = new AnthropicSDK({
  apiKey: process.env.ANTHROPIC_API_KEY!,
  pricing: {
    "claude-haiku-4-5": { input: 1, output: 5, cachedInput: 0.1 },
    "claude-sonnet-4-6": { input: 3, output: 15, cachedInput: 0.3 },
  },
});
```

Need an offline token estimate before a call? `anthropic.count(text)`
returns a fast character-heuristic approximation — good for budgeting
and quota guards, not for billing. For an exact count, call
`model.countTokens(messages, options)`: it asks Anthropic's
`messages.countTokens` endpoint, with the same system prompt, tools and
thinking settings the real call would send.

For the agent/workflow surface these models plug into, see
[`@warlock.js/ai`](/v/latest/ai/). For provider-specific notes and the
latest model ids, see the `setup-anthropic` skill.

## Build and send an audited request

`model.buildRequest(messages, options?)` is synchronous and makes no network call.
It returns a detached `{ endpoint, body, betas }` snapshot, including thinking,
cache markers, provider body options and merged tool results. `body.stream` is
`false` by default; pass `{ ...options, stream: true }` to build a streaming request.
`betas` identifies the beta header flags; the SDK receives these separately from
its serialized Messages body.

```ts
const request = model.buildRequest(messages, options);
const bodyJSON = JSON.stringify(request.body);
// Hash or reserve spend against bodyJSON before sending.
const response = await model.send(request, { signal });

const streamingRequest = model.buildRequest(messages, { ...options, stream: true });
for await (const chunk of model.send(streamingRequest, { signal })) {
  // Consume the same neutral chunks as model.stream().
}
```

`send()` uses the built endpoint, body and beta flags without rebuilding the
conversation or applying new defaults. Transport cancellation stays separate from
the audited body. `complete()` and `stream()` use this same build/send path and always select their
respective non-streaming and streaming request modes.
Treat the snapshot as read-only after hashing it; SDK JSON serialization and beta
header handling still apply.

Hosts with their own transport can import `toAnthropicMessages`,
`toAnthropicTools`, `toProviderBlocks`, `fromProviderBlocks`,
`ANTHROPIC_BLOCK_FORMAT` and the `AnthropicMessages` type from the package root.
`fromProviderBlocks(blocks, toolCalls)` retains the adapter's assistant-block
allowlist and tool-id validation.
