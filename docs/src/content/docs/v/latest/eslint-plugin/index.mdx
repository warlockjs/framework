---
title: ESLint Plugin
description: Lint rules for Warlock.js apps — validated request input, guarded mutating routes, safe redirects, redacted logs, bounded regexes on input, and the framework's code conventions — with recommended and strict flat-config presets.
---

`@warlock.js/eslint-plugin` catches at edit time the mistakes that are easiest
to ship in a Warlock app: client input reaching the database unvalidated, a
mutating route nobody guarded, an open redirect, a token in a log line, a regex
that a crafted input can stall. It also enforces the framework's conventions so
generated and hand-written code look the same.

Apps created by `create-warlock` in the default ESLint mode already include it.

## Install

```bash
npm install --save-dev @warlock.js/eslint-plugin
```

```js title="eslint.config.js"
import tsParser from "@typescript-eslint/parser";
import warlock from "@warlock.js/eslint-plugin";

export default [
  { files: ["**/*.ts", "**/*.tsx"], languageOptions: { parser: tsParser } },
  warlock.configs.recommended,
];
```

The plugin works with ESLint 8.57+ (flat config) and ESLint 9.

## Presets

| Preset                        | What it enables                                                                                        |
| ----------------------------- | ------------------------------------------------------------------------------------------------------ |
| `warlock.configs.recommended` | Every security rule as an error, `no-js-import-extension` as an error and `no-await-log` as a warning. |
| `warlock.configs.strict`      | Every rule as an error, adding `one-controller-per-file` and `prefer-type-discriminator`.              |

Rules are named `@warlock.js/<rule>`. Override one after the preset:

```js title="eslint.config.js"
import warlock from "@warlock.js/eslint-plugin";

export default [
  warlock.configs.recommended,
  {
    rules: {
      "@warlock.js/require-route-guard": ["error", { guardFunctions: ["guarded", "adminOnly"] }],
    },
  },
];
```

## Rules

| Rule                                                                  | Recommended | Fix        | Catches                                                                     |
| --------------------------------------------------------------------- | ----------- | ---------- | --------------------------------------------------------------------------- |
| [`no-request-all`](./rules/no-request-all/)                           | error       | suggestion | `request.all()` passed to a query, service or `inApp()`                     |
| [`require-route-guard`](./rules/require-route-guard/)                 | error       | suggestion | a POST/PUT/PATCH/DELETE route with no auth middleware and no `public: true` |
| [`safe-redirect`](./rules/safe-redirect/)                             | error       | suggestion | redirect and `<Link to>` targets taken from request input                   |
| [`no-sensitive-log`](./rules/no-sensitive-log/)                       | error       | —          | raw emails, credentials and request bodies in log calls                     |
| [`no-unbounded-regex-on-input`](./rules/no-unbounded-regex-on-input/) | error       | —          | `*`, `+`, `{n,}` in a regex applied to request input                        |
| [`no-await-log`](./rules/no-await-log/)                               | warn        | autofix    | `await log.info(…)`                                                         |
| [`no-js-import-extension`](./rules/no-js-import-extension/)           | error       | autofix    | `.js` in relative import paths                                              |
| [`one-controller-per-file`](./rules/one-controller-per-file/)         | strict      | —          | several controllers in one file                                             |
| [`prefer-type-discriminator`](./rules/prefer-type-discriminator/)     | strict      | —          | `kind` instead of `type` as a union tag                                     |

Autofixes run with `eslint --fix`. Suggestions appear in the editor as quick
fixes and are never applied by `--fix`, because each one is a decision (a route
marked `public: true` is reachable by anyone).

Every rule's message links to its page here. Coding agents get the same
guidance from the `lint-warlock-app` skill shipped in the package.

## Oxlint

Oxlint can load ESLint plugins through `jsPlugins`, but in Oxlint 1.88 — the
version Warlock pins — that feature is alpha and not covered by semver. The
plugin is supported and tested with ESLint only, and `create-warlock --lint=oxc`
projects do not include it.
