`@warlock.js/sitemap` doesn't import Warlock. In a Warlock app,
`@warlock.js/web` calls the package, just as an Express handler would. Web
handles everything that depends on the app:

- finding pages and applying page-level `config.sitemap` policy;
- expanding locales into `hreflang` alternates;
- choosing `Sitemap` or `SitemapIndex`;
- generating the file at `warlock build` and at boot;
- serving `/sitemap.xml`, the shard files, and `/robots.txt`.

## Install

```sh
warlock add sitemap
```

This command installs `@warlock.js/sitemap`, and `@warlock.js/web` if it isn't
installed yet. It then adds a **disabled** `sitemap` section to
`src/config/web.ts`. If the file already exists, the section is merged in and
nothing else in the file changes. Running the command again does nothing.

```ts title="src/config/web.ts"
import type { WebSitemapConfig } from "@warlock.js/web/sitemap";

const webConfig: { sitemap: WebSitemapConfig } = {
  sitemap: {
    enabled: false,
    path: "/sitemap.xml",
    defaults: { changefreq: "weekly", priority: 0.5 },
  },
};

export default webConfig;
```

It ships disabled because a sitemap needs absolute URLs, and a new app doesn't
know its public origin yet. To turn it on:

1. Set `app.publicUrl` in `src/config/app.ts`, or set the `PUBLIC_APP_URL`
   environment variable. `app.publicUrl` wins if both are set.
2. Set `sitemap.enabled` to `true`.

<Aside type="caution" title="No origin, no sitemap">
  If the sitemap is enabled but has no origin, generation throws `MissingPublicUrlError`. It never
  builds URLs from a guessed or request-derived host. Sitemap generation runs at runtime, not during
  `warlock build`. At boot, the error is logged and `/sitemap.xml` returns `503` until a later
  generation succeeds.
</Aside>

The [Sitemap and robots.txt guide](/v/latest/web/guides/sitemap-and-robots/)
covers the rest: every `web.sitemap` key, page-level `config.sitemap`,
locales, `robots.txt`, and regenerating after your data changes.

## Upgrading from 5.15

5.16 rewrites this package, and the 5.15 API is gone. That includes the
connector, its standalone config file, the page-registry helpers, and the
`sitemap.path`/`defaults` config module. In 5.17, page sitemap policy moves
into the page's direct `config` object, typed with `PageConfig` from
`@warlock.js/web`.

| 5.15                                                 | Current API (5.17)                                                                                                                                                            |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A connector registered in `warlock.config.ts`        | Nothing to register. `@warlock.js/web` reads `web.sitemap` itself. Remove the connector entry.                                                                                |
| A standalone sitemap config file                     | A `sitemap` section in `src/config/web.ts`, typed as `WebSitemapConfig` from `@warlock.js/web/sitemap`. Move `enabled`, `path`, and `defaults` there.                         |
| `export const sitemap = async () => [...]` on a page | Move the function into `config.sitemap` and type the direct config object with `PageConfig` from `@warlock.js/web`. The value can also be a static options object or `false`. |
| API-only apps passing an `entries` supplier          | Build a `Sitemap` yourself and return it with `response.xml(sitemap)`. See [Build a sitemap](/v/latest/sitemap/essentials/standalone/#toxml).                                 |
| Collecting and serialising pages yourself            | `new Sitemap({ baseUrl })`, then `add()` and `toXML()`.                                                                                                                       |
| `MissingPublicUrlError` from the sitemap package     | `MissingPublicUrlError` from `@warlock.js/web/sitemap`, raised when generation runs rather than at connector boot.                                                            |

The builder takes its origin as the `baseUrl` argument, so the standalone
package can no longer be missing one.
