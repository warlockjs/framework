## Connector

```ts
function sitemapConnector(options?: SitemapConnectorOptions): Connector;

type SitemapConnectorOptions = {
  /** Supply the configuration directly instead of reading the `sitemap` config key. */
  config?: SitemapConfig;
  /**
   * App-supplied entries — the only source of entries in an API-only Warlock
   * project (Mode 2, no `@warlock.js/web` page registry). When web IS
   * installed, these are ADDED to the page-derived entries, not substituted
   * — see `mergeSitemapEntries` below.
   */
  entries?: SitemapEntries;
};

const DEFAULT_SITEMAP_PATH = "/sitemap.xml";
const SITEMAP_CONNECTOR_PRIORITY = 5.6; // after HTTP (5) and web (5.5)

class NoPageRegistryError extends Error {}
```

`@warlock.js/core` and `@warlock.js/web` are optional peers — the connector
is the only module in this package that reaches either, and it does so
through a lazy `import()` inside `boot()`, not a module-level import.

`NoPageRegistryError` is thrown at `boot()` when `@warlock.js/web` is not
installed **and** no `entries` option was supplied — there would be nothing
to serve. See [Configuration](../essentials/configuration/#no-page-registry-no-entries).

## Config & entry types

```ts
type SitemapConfig = {
  enabled: boolean;
  path: string;
  defaults?: SitemapDefaults;
};

type SitemapDefaults = {
  changefreq?: ChangeFreq;
  priority?: number;
};

type ChangeFreq =
  | "always"
  | "hourly"
  | "daily"
  | "weekly"
  | "monthly"
  | "yearly"
  | "never";
```

## Page-level export types

```ts
/** `export const sitemap: SitemapEntries = async () => [...]` in a *.page.tsx, or the same shape passed as `sitemapConnector({ entries })`. */
type SitemapEntries = () => SitemapEntry[] | Promise<SitemapEntry[]>;

type SitemapEntry = {
  path: string; // app-relative; joined against the configured origin
  lastmod?: string;
  changefreq?: ChangeFreq;
  priority?: number;
};
```

## `RoutablePage` — the standalone-usage input

```ts
type RoutablePage = {
  /** Unique route identity — named in the dynamic-route diagnostic when unresolved. */
  routeName: string;
  /** The effective route path, `:param` for a dynamic segment (e.g. `/posts/:id`). */
  routePath: string;
  /** `metadata.robots`, when the page's `metadata` export is a static object. */
  robots?: string;
  sitemap?: SitemapPageExport;
};

/** A page's `sitemap` export: the entries function, an explicit opt-out, or absent entirely. */
type SitemapPageExport = SitemapEntries | false | undefined;
```

Deliberately not `@warlock.js/web`'s own discovery type — this is the
minimal shape `collectSitemapEntries` needs, whether it was adapted from a
real page registry or built by hand for [standalone usage](../essentials/standalone/).

## Building blocks

These are what `sitemapConnector()` is assembled from — reach for them
directly for standalone usage, custom wiring, or tests.

```ts
function collectSitemapEntries(
  pages: readonly RoutablePage[],
  options?: CollectSitemapEntriesOptions,
): Promise<CollectSitemapEntriesResult>;

type CollectSitemapEntriesOptions = { defaults?: SitemapDefaults };
type CollectSitemapEntriesResult = {
  entries: SitemapEntry[];
  unresolvedDynamicRoutes: string[];
};

function isDynamicRoutePath(routePath: string): boolean;
```

Applies every exclusion rule (see [Configuration](../essentials/configuration/#what-ships-and-what-doesnt)
for the table) against a `RoutablePage[]`.

```ts
function mergeSitemapEntries(
  pageEntries: readonly SitemapEntry[],
  appEntries: readonly SitemapEntry[],
): SitemapEntry[];

function withDefaults(entry: SitemapEntry, defaults: SitemapDefaults | undefined): SitemapEntry;
```

`mergeSitemapEntries` combines page-derived entries with app-supplied ones,
deduplicating by `path` — where the same path appears in both, the
app-supplied entry wins. This is how `sitemapConnector()` combines a page
registry with an `entries` supplier; see
[combining a page registry with `entries`](../essentials/configuration/#combining-a-page-registry-with-entries).
`withDefaults` applies `SitemapDefaults` to one entry — shared by
page-derived and app-supplied entries alike.

```ts
function buildSitemapXml(entries: SitemapEntry[], origin: string): string;
function escapeXml(value: string): string;
```

Serialises entries into the sitemaps.org `urlset` document: correct
namespace, element order (`loc`/`lastmod`/`changefreq`/`priority`), and XML
escaping of `&`, `<`, `>`, `"`, `'` in every URL.

```ts
function resolveOrigin(options?: ResolveOriginOptions): string;
function joinOrigin(origin: string, routePath: string): string;

type ResolveOriginOptions = {
  /** `app.publicUrl` from the app's config, when set. */
  publicUrl?: string;
  /** Defaults to `process.env`; overridable for tests. */
  env?: Record<string, string | undefined>;
};

class MissingPublicUrlError extends Error {}
```

`resolveOrigin()` reads `app.publicUrl` first, then the `PUBLIC_APP_URL` env
fallback, throwing `MissingPublicUrlError` when neither is set. `joinOrigin()`
joins an origin and an app-relative path with exactly one slash regardless of
trailing slashes on either side.

```ts
function describeUnresolvedDynamicRoutes(
  routeNames: readonly string[],
): string | undefined;
```

The dev-mode diagnostic message for a dynamic route with no `sitemap` export.
Returns `undefined` when there is nothing to report.
