# Warlock.js 5.52.0 — release summary

Released 2026-11-11.

All **33 packages** (`@warlock.js/*` and `create-warlock`) move to 5.52.0 together;
keep every family package on the same version. This minor delivers a shared
`locales.json` to every site of a multi-site app, makes email sign-in ignore case
and surrounding spaces, keeps a repository's default order, and lets a page cover
its computed translation lookups with an exhaustive key list. The packages with
changes are `core`, `web` and `auth`. No breaking changes.

## Check first

- Sign-in now trims identifiers and lower-cases `email` before the lookup. A user
  stored as `sara@x.io` can sign in as `Sara@x.io`. Accounts stored with capitals still
  sign in (one retry with the value as sent). Set `auth.normalizeCredentials: false` to
  keep exact matching, or pass a function to normalize other fields.
- A repository's `defaultOptions` and the app-wide `repository.defaultOptions` are now
  trusted: a default `orderBy` applies even when its columns are not in `sortable`,
  and a default `select` or `cursorColumn` is no longer filtered. Only the caller's
  options to `list()` are checked against `sortable` / `selectable`.
- A string literal that is not a translator argument (`export const site = "client"`)
  now reaches only a key with that exact name, not the whole `client.*` group. If a page
  relied on such a literal to ship a group, call the translator with the key or declare
  it in `config.translations`.

---

## 1. Web

- Multi-site apps: a `locales.json` above the site folders (`src/web/locales.json`,
  `src/web/$sites/locales.json`) reaches every page of every site, in development,
  production and server rendering. Before, its keys were typed but no page received
  them, so pages rendered raw keys. It merges before each site's own dictionary. A key
  is still declared in one `locales.json` in the whole app.
- The build warns about a `locales.json` that applies to no page.
- `PageConfig`, `LayoutConfig` and `RootConfig` type `config.translations`.

## 2. Core

- `config.translations` accepts `{ keys: [...], exhaustive: true }` in a page, layout or
  root setup file. The declared keys cover the computed lookups in that page's graph,
  so the page ships the keys found in code plus the declared ones instead of every
  group. An error page's declaration covers only the error page.
- A name imported from something that is not a translator (`import { translateCopy as t }`)
  no longer counts as a translator. `import { trans as t }` still does.
- Repository `list()`: a caller's `orderBy` on a non-sortable column is dropped and the
  default order applies instead of none. The warning is logged once per repository
  and column set and names the order that applies.
- `WL9104` points to the exhaustive `config.translations` form.

## 3. Auth

- Email sign-in ignores case and surrounding spaces; the login throttle uses the same
  normalization, so its bucket and the account lookup always agree.
- New `auth.normalizeCredentials` option and `NormalizeCredentials` type.

## Verification

- Typecheck of all packages, the unit tests of `core`, `web` and `auth`, format, lint,
  the public-text, spec-coverage and skill gates passed on the final tree. The release
  gate runs every package's tests and the blog app on the tarballs.
