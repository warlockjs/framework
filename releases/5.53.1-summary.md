# Warlock.js 5.53.1 — release summary

Released 2026-11-12.

All **33 packages** (`@warlock.js/*` and `create-warlock`) move to 5.53.1 together;
keep every family package on the same version. This patch answers an application
team's report after upgrading to 5.53.0: a rate-limit crash for clients that
disconnect, a Windows process helper that let Node exit too early, hundreds of
source-map warnings at every dev start, and two smaller fixes. The packages with
changes are `core`, `process` and `ai-workspace`; the source-map fix also changes
what every package ships. No breaking changes.

## Who should upgrade

- **Every app on 5.53.0.** The global `http.rateLimit` key throws when the client's
  socket is already gone (a browser that drops a long-lived stream route), and the
  request answers 500 and records an error. 5.53.1 fixes it.
- Apps that see "Sourcemap for … points to a source file outside its package" in
  `warlock dev`, or that build a large app and hit the 30-second route-registration
  limit.
- Windows apps that use `@warlock.js/process` from a script with no server running.

---

## 1. Fixes

- **Rate-limit key for a disconnected client (`core`).** The key now falls back to
  the socket's remote address and then to one shared `unknown` key, the fallback
  `middleware.rateLimit()` already used, so the request is counted instead of failing
  with a 500.
- **Route registration on a large app (`core`).** `build.routeRegistrationTimeoutMs`
  (or `WARLOCK_ROUTE_REGISTRATION_TIMEOUT_MS`) now limits the time without progress:
  the limit restarts each time the registration child finishes a route module. The
  default stays 30000 ms. The timeout error names both ways to raise the limit, with
  an example.
- **Source-map warnings (all packages).** Published source maps embed their original
  sources again, as in 5.52. Without them the bundler looked for the framework's own
  repository files on disk and logged a warning for each package module it loaded.
  Tarballs are back to their 5.52 size (`@warlock.js/core` about 3.5 MB instead of
  2.4 MB). The release now refuses to pack maps that would bring the warnings back.
- **Supervisor calls on Windows (`process`).** A script that awaited `recover()`,
  `spawn()` or another supervisor call at top level, with nothing else keeping Node
  running, exited with code 13 about 20 ms in, because the process-query helper
  (one PowerShell per supervisor) and the timer guarding its answer did not hold the
  process open. The timer now does while a call is waiting. `recover()` with no
  registry file yet resolves with an empty recovery on every platform.
- **Shell approval reason (`ai-workspace`).** A command that sets a variable which can
  steer which program runs (`NODE_OPTIONS=…`, `PATH=…`, `GIT_PAGER=…` and the others
  that `shell.allowAssignments` covers) reaches `shell.onAsk` with
  `reason: "assignment"` and the variable name in `variable`, instead of `"nested"`.

## 2. Behaviour notes

- **`onAsk` reasons.** An approval handler that matches `reason === "nested"`
  exactly no longer sees assignment asks; add the `"assignment"` case. The text shown
  to the model now names the variable.
- **Route-registration timeout.** A value you set now means the longest time without
  finishing a route module, not the length of the whole step. A single module that
  takes longer than the limit still fails, and so does a start-up or a finishing step
  that takes longer.
- **`request.detectIp()`** returns an empty string, not `undefined`, when no address
  is left. `ipFilter` refuses such a request and the idempotency scope uses
  `"unknown"`.
- **Windows exit timing.** A pending process-query call keeps Node running until its
  answer arrives, at most `observationTimeoutMs`. An idle helper still never does.
- **PowerShell assignments.** `$env:NAME = value` is refused as `"unsupported-syntax"`
  (asked with `reason: "unparsed"` when `onAsk` is set). This is unchanged; the
  documentation now says so.
- **Route hooks in specs.** fastify 5.12.8, which a fresh install or a lockfile update
  resolves, types hooks in `RouteOptions["serverOptions"]` with `this: FastifyInstance`; a spec that
  calls one directly fails with TS2740. Call it as `hook.call(fastify, request, reply)`.
- **5.53.0 notes.** The line about tarballs shipping source maps without embedded
  sources no longer applies: that change is reverted.

## 3. Reported but not changed

One item from the report could not be confirmed from the source and is not changed in
this release: `warlock generate.typings` hanging on Windows. The command does not use
the supervisor code fixed here, and every step on its path is bounded or shared with
paths that work. The most likely cause is a slow route-registration child that prints
nothing while it waits. It stays open as a task with the steps that settle it on a
Windows machine.

## 4. Upgrade notes

1. **Update the family.** Run `npx warlock update`, then
   `npx warlock release-notes --from 5.53.0`.
2. If your approval handler matches `reason === "nested"`, add `"assignment"`.
3. If code tests `request.detectIp() === undefined`, test for a falsy value.
4. If you worked around the rate-limit crash with a custom `rateLimit.keyGenerator`,
   you can remove it.

## Verification

- The specs and typechecks of the changed packages pass.
- The workspace typecheck, the unit tests, lint, format and the release gates ran on
  the release tree.
- The Windows-only fix is verified on Linux by reproducing the mechanism (a script
  that awaits a helper answer exited with code 13 before the fix and settles after it)
  and by a spec that runs on the Windows CI job against the real PowerShell helper. It
  was not run on Windows locally.
- The typings generator hang on Windows (section 3) could not be confirmed from the
  source and is not changed.
