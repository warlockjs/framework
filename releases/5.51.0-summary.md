# Warlock.js 5.51.0 — release summary

Released 2026-11-11.

All **33 packages** (`@warlock.js/*` and `create-warlock`) move to 5.51.0 together;
keep every family package on the same version. This minor adds the original request
path, route path arrays on every verb, a built-in CSRF refusal message, and clearer
`warlock check` and translation-build diagnostics, and it makes a "no database"
scaffold actually database-free. The packages with changes are `core`, `web` and
`create-warlock`. No breaking changes.

## Check first

- `WL9006` now reports a route whose options object is only a spread
  (`{ ...opts }`) as a **warning**. Before, the spread was trusted and the route
  passed silently. Write `middleware` or `public: true` in the literal, or list your
  wrapper helper in `guardWrappers` in `.warlock-check.json`.
- A locale dictionary with text for a locale that is not in `app.localeCodes` no
  longer fails the build. That text is ignored and `WL1010` is reported once per file.

---

## 1. Core

- Every router verb (`get`, `post`, `put`, `patch`, `delete`, `head`, `options`, `any`)
  accepts an array of paths and registers one route per path.
- `request.originalUrl` (path and query) and `request.originalPath` (pathname) return
  what the client sent, before the terminal-slash normalization and any `rewriteUrl`.
  Use them to serve directory-style content where `/docs` and `/docs/` differ. The
  wildcard `*` param still comes from the normalized path.
- The CSRF origin refusal no longer answers with the raw key `auth.errors.csrfOriginMismatch`
  in an app without `@warlock.js/auth`. Core ships `http.errors.csrfOriginMismatch`
  (English and Arabic); the app's own auth text wins when defined. `resolveCsrfMessage()`
  is exported.
- The translation analyzer no longer treats a hook dependency list
  (`useMemo(() => t("a"), [t])`) as a translator that escapes, which made such a page
  ship every translation group.
- `WL9104` names the file, line and text of each computed lookup and states that
  `config.translations` only adds keys.
- `WL1010` (warning): dictionary text for a locale outside `app.localeCodes`.
- Docs and skills: `guardWrappers`, what makes a guard visible to `WL9006`, why a bare
  string equal to a translation group name ships the whole group, and the new request
  getters.

## 2. Web

- The page build logs each translation lookup computed at runtime (file, line, text),
  once each. Removing that lookup is what lets a page ship only the groups it uses.
- Docs and skills: how to avoid a circular `config` type in a page setup file.

## 3. create-warlock

- `--no-db` (`--db=none`) now removes the model-backed `users`, `auth` and `posts`
  modules, `src/config/auth.ts`, the `@warlock.js/auth` dependency and typings
  augmentation, the `DB_*` and JWT entries in `.env` and `.env.example`, and the
  migrate, seed and JWT scripts. The generated app has no dangling imports.

## Verification

- Typecheck of all packages, the full unit-test run of every package, the public-text
  and spec-coverage checks, and the code map passed on the final tree.
- Not run: a fresh `--no-db` scaffold installed and booted end to end; it is covered by
  the scaffold spec and the registry-backed scaffold check after publish.
