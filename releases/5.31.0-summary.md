# Warlock.js 5.31.0 — release summary

Released 2026-10-18. All 32 packages (`@warlock.js/*` and
`create-warlock`) move to 5.31.0 together; keep every family package on the same
version. One package joins the family in this release: `@warlock.js/ai-cli`.

This release turns on the HTTP rate limiter in production (it was silently off),
raises the minimum Node.js version to **22.15**, adds Bun and Deno as production
runtimes for a built app, and ships a `warlock upgrade` command that makes the
mechanical upgrade edits for you. It contains **breaking changes in a minor
version** (Warlock.js does not follow SemVer strictly), so read the first three
sections before upgrading.

---

## 1. Read this first

### Node.js 22.15 or newer is now required

The `warlock` CLI loads TypeScript through `module.registerHooks`, which Node
added in 22.15. On an older Node the CLI exits with one clear message before it
loads anything. Upgrade Node in development, CI, Docker images and production
**before** installing 5.31.0. `create-warlock` checks for 22.15 too (it used to
accept Node 20).

Runtimes in 5.31.0:

| Command                                            | Node 22.15+ | Bun 1.4.3                                                  | Deno 2.9.7                      |
| -------------------------------------------------- | ----------- | ---------------------------------------------------------- | ------------------------------- |
| `warlock dev`                                      | Yes         | No: exits `1` with an error naming the runtime             | No: same                        |
| `warlock build`                                    | Yes         | Runs, prints a notice that only the Node build is verified | Same as Bun                     |
| `warlock start`, or running `dist/app.js` directly | Yes         | Yes (`bun dist/app.js`)                                    | Yes (`deno run -A dist/app.js`) |

Build on Node, then start the build on any of the three. The "Supported runtimes"
docs page lists the exact commands.

### The HTTP rate limiter is now enforced in production

**In every release up to and including 5.30.0, the global `http.rateLimit` did
not apply to application routes in production, and per-route `rateLimit` options
had no effect in production.** Development enforced both, so the gap was easy to
miss. 5.31.0 enforces them everywhere. If you never set `http.rateLimit`, the
default now applies: **60 requests per minute per client IP**.

| What you have                                                                                                                                  | Production on 5.30.0 and earlier               | Production on 5.31.0                                                   |
| ---------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------- |
| No `http.rateLimit` config                                                                                                                     | No limit                                       | **60 req/min per IP**, one bucket shared by page routes and API routes |
| Global `http.rateLimit` (any `store`)                                                                                                          | Not applied to application routes or `/health` | Applied to pages and API routes                                        |
| A per-route `rateLimit` option                                                                                                                 | No effect                                      | Applied (own limit and bucket)                                         |
| Static files: public folder, `router.directory()`, `router.file()` / `cachedFile()` / `files()` / `cachedFiles()`, the web build's `/assets/*` | Not limited                                    | **Exempt** by default                                                  |
| Built-in `/health` and `/ready`                                                                                                                | Not limited                                    | **Exempt** by default                                                  |
| `middleware.rateLimit({ … })` in a route's middleware list                                                                                     | Enforced                                       | Enforced (unchanged)                                                   |

**What it will look like if the default is too low:** `429 Too Many Requests`
responses for real users, monitors or partner systems shortly after deploy.

**Check these before upgrading:**

1. **Behind a proxy, load balancer or CDN?** `http.trustProxy` defaults to
   `false`, so every request appears to come from the proxy's address and **all
   your visitors share one 60-per-minute bucket**. Set `http.trustProxy` to your
   proxy addresses (a CIDR list such as `"10.0.0.0/8"`, preferred over bare
   `true`), or give the limiter a `keyGenerator` (for example per signed-in user).
2. **Count what one busy user sends in a minute.** Pages and API calls share the
   bucket: page loads, client-side navigations, form submissions, API calls and
   polling all count. Raise `http.rateLimit.max` if a normal session comes near 60.
3. **Uploaded files served by a route handler count.** Routes such as
   `router.get("/uploads/*", createUploadedFileController())` are application
   routes, not static mounts; a page with 30 avatars spends 30 requests. Pass
   `rateLimit: false` (or a higher own limit) on those routes.
4. **Find callers that share one IP:** your own health or status routes (only the
   built-in `/health` and `/ready` are exempt), uptime monitors, payment and other
   webhooks, internal services, office or mobile-carrier NAT, load tests and
   end-to-end tests against a production build. Exempt a route with
   `rateLimit: false`.
5. **Several app instances?** The default `memory` store counts per instance. Use
   `http.rateLimit.store: "cache"` (added in 5.30) to share counts.
6. **Want the 5.30 behaviour back?** `http.rateLimit.global: false` turns off the
   blanket quota and keeps your explicit per-route limits.

```ts title="src/config/http.ts"
const httpConfigurations = {
  trustProxy: "10.0.0.0/8", // your proxy/load balancer addresses
  rateLimit: { max: 300, timeWindow: 60_000 },
  // staticFiles: true   → count static files too
  // global: false       → per-route limits only
};
```

`warlock upgrade` lists an `http` config without `rateLimit` for review (codemod
`rate-limit-defaults`). The development server now counts requests exactly as
production does: exempt routes, static files and unmatched URLs are not counted.

### Image-variant cache settings that overlap your uploads

In 5.30.0, if `uploads.images.cacheDirectory` was the same folder as a local
storage disk's root, or contained one, `purgeImageVariants()` and the cache
cleanup could recursively delete **uploaded originals**, not just generated
derivatives.
5.31.0 refuses that configuration with `ImageVariantsConfigError` and only ever
removes files it recognizes as its own cache files.

**Before upgrading:** check that `uploads.images.cacheDirectory` (if set) is a
dedicated folder outside every storage root. If it is not, move it; on 5.31.0 an
overlapping setting throws whenever variants are generated or purged.

### Security fixes

| Package                               | What was wrong                                                                                                                                                                              | What changed in 5.31.0                                                                                                                                                                                          |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@warlock.js/core`, `@warlock.js/web` | Global and per-route rate limits were not applied in production.                                                                                                                            | Enforced; see above.                                                                                                                                                                                            |
| `@warlock.js/core`                    | Image-variant purge and cleanup could delete uploads through an overlapping cache folder or a symlinked shard folder.                                                                       | Overlap rejected; only recognized cache files are removed; symlinks are never followed.                                                                                                                         |
| `@warlock.js/cache`, `auth`, `core`   | A login, token, OTP or rate-limit counter that expired between its first write and its increment was recreated **with no expiry**, so a client could stay throttled or locked indefinitely. | Every atomic increment carries the window's TTL. A counter already left without an expiry gets one at its next increment.                                                                                       |
| `@warlock.js/ai-workspace`            | A `deny` list could be bypassed through wrappers (`env rm -rf /` passed `deny: ["rm"]`) or by case (`RM`). A model-supplied `timeoutMs` could raise `shell.timeoutMs`.                      | Wrappers (`env`, `time`, `timeout`, `nice`, `nohup`, `command`, `builtin`, `exec`, `find -exec`) are unwrapped and the inner command checked; `deny` is case-insensitive; `timeoutMs` can only lower the limit. |
| `@warlock.js/ai-tools`                | The stdio transport of `ai.mcp.serve()` crashed the process on a line that was JSON but not a request (`null`, a number).                                                                   | Answers a JSON-RPC "Invalid Request" error.                                                                                                                                                                     |

## 2. Breaking changes — exact steps when upgrading from 5.30

### Start with `warlock upgrade`

The command ships in `@warlock.js/core` 5.31.0 and needs `ts-morph` (an optional
dev dependency). Once Node is on 22.15+:

```bash
pnpm add @warlock.js/core@5.31.0          # plus every other @warlock.js/* package at 5.31.0
pnpm add -D ts-morph
pnpm warlock upgrade --from 5.30 --to 5.31.0 --dry-run   # diff + review list, writes nothing
pnpm warlock upgrade --from 5.30 --to 5.31.0             # apply
```

Pass `--from` because the command otherwise reads the installed core, which is
already 5.31.0. Coming from 5.29, use `--from 5.29` to get the 5.30 codemods too
(and read the 5.30.0 summary). The command edits what is mechanical, lists every
place that needs a decision with `file:line`, and moves every `@warlock.js/*`
dependency to the target. `--json` prints the same result as JSON. The
`upgrade-from-5-29` skill in `@warlock.js/core` explains every item below.

Then work through the items that apply to your app, and finish with your type
check and test suite.

### Application (core, seal, logger)

1. **Node.js 22.15+** (`core`, `create-warlock`). Codemod `node-22-15` raises
   `engines.node`, `.nvmrc` and `.node-version`. Update CI and Docker images by hand.

2. **Rate limits apply in production** (`core`, `web`). Work through the checklist
   in section 1. Codemod `rate-limit-defaults` lists a missing `rateLimit`.

3. **Test fakes are on by default** (`core`, tests only). `setupTest()` and
   `startHttpTestServer()` now capture mail, record queue dispatches instead of
   pushing to Redis, use a fresh in-memory cache, write storage to a temp folder,
   and make `clock` / `ids` deterministic. Suites that need the real services set
   `fakes: false` (or `{ cache: false, queue: false }`, …) in `src/config/tests.ts`,
   or pass `fakes` to either call. Prefer the new assertions (`mailFake.assertSent`,
   `queueFake.assertPushed`, …).

4. **`.refine()` runs on validated output** (`seal`). It runs after child
   validation and transformers, skips absent, `null` and invalid values, runs on
   successful empty defaults such as `.default("")`, and is typed from the output
   instead of `any`. Move checks that need the raw input to `.addRule()`. Codemod
   `seal-refine-output` lists every `.refine()`.

5. **`.catch()` on a container does nothing** (`seal`), including failures in the
   container's own rules (length, unknown keys). Inputs an array/object catch used
   to rescue now fail. Put catches on child validators. Codemod
   `seal-container-catch` lists them.

6. **`v.union()` returns the matched branch's output** (`seal`): trimmed strings,
   parsed dates, object defaults; stripped unknown keys disappear. Persisted or
   compared values can differ; keep the raw input if you need it. A failed union
   now reports the closest member's errors at their own paths (`actor.id`, not
   `actor`), one per error with `firstErrorOnly: false` instead of one `;`-joined
   message. Codemod `seal-union-output` lists every `v.union()`.

7. **Dated log file names are ISO dates** (`logger`). `FileLog` / `JSONFileLog`
   daily files are `YYYY-MM-DD.log` (was `DD-MM-YYYY.log`), hourly
   `YYYY-MM-DD-HH.log`. A running daily channel starts a new file after the upgrade.
   Update log shippers and cleanup scripts, or keep the old names with
   `fileName: "{DD}-{MM}-{YYYY}"` and `rotateFileName: "{DD}-{MM}-{YYYY}"`.
   `rotateFileName` is now a `{YYYY}`-style pattern, not a Day.js format. The new
   `retention` option never removes files with the old names.

### AI packages

8. **A cut-off agent answer is an error** (`ai`). A run whose final response hit
   the output cap (`length`) or the context window (`context_exceeded`) now ends
   with `result.error` an `AgentIncompleteError` and `report.status: "incomplete"`;
   `result.text` keeps the partial text and a half-written tool call is never run.
   Handle the error, add `"incomplete"` to exhaustive switches over `ReportStatus`
   / `ErrorCategory`, and drop your own `finishReason === "length"` checks. To
   continue automatically, set `continueOnOutputLimit: n`.

9. **Provider overloads throw `ProviderOverloadedError`** (`ai` and the
   adapters): Anthropic 529, OpenAI-compatible and Gemini 503, Bedrock
   `ServiceUnavailableException`. It extends `ProviderError` but its code is
   `PROVIDER_OVERLOADED`. Update code matching `PROVIDER_ERROR` for these cases,
   exhaustive `AIErrorCode` switches and custom `fallbackModel({ retryOn })` lists.

10. **Anthropic default `max_tokens` rose from 4096** (`ai-anthropic`). With no
    `maxTokens`, streaming uses the model's maximum output (128K on Claude 5) and
    non-streaming uses 16384. Answers can be longer and cost more: set `maxTokens`
    to keep a lower cap; for a gateway or proxy model id, set `maxOutputTokens`.

11. **Some built-in prices were removed** (`ai-groq`, `ai-deepseek`,
    `ai-mistral`). Groq's `llama-3.3-70b-versatile`, `llama-3.1-8b-instant`,
    `deepseek-r1-distill-llama-70b`; DeepSeek's `deepseek-chat`,
    `deepseek-reasoner`; Mistral's `pixtral-*` and `magistral-*`. A USD budget on
    these now rejects the run as unpriced: pass `pricing`.

12. **Workspace tool set and interfaces grew** (`ai-workspace`). `ws.tools.all()`
    adds `multi_edit`, `list_dir`, `todo_write`, `todo_read` (plus `shell_output`
    / `shell_kill` with `shell.background`). Keep the old set with
    `ws.tools.pick("readFile", "editFile", "writeFile", "runShell", "runTests", "grep", "glob")`.
    Custom `WorkspaceOps` / `Workspace` implementations and test doubles must add
    `multiEdit`, `listDir`, `startShell`, `shellOutput`, `shellKill`,
    `listShells`, `dispose` (and `readTodos` / `writeTodos` on `Workspace`).

13. **Nested command runners are refused under deny rules** (`ai-workspace`).
    With `shell.deny`, `denyPatterns` or `allowCommand` set, `sh -c`, `bash -c`,
    `eval`, `source`, `xargs`, `sudo`, `setsid` and similar are refused
    (`reason: "nested-command"`) unless listed in `shell.allow`. Refusal messages
    changed; branch on `WorkspacePolicyError.reason`, not the text.

14. **`ai.mcp.serve()` refuses duplicate names** (`ai-tools`). Two tools with one
    name (or duplicate resource URIs or prompt names) throw `McpServeError`
    (`type: "collision"`); before, calls silently reached the last one. Rename a
    tool or serve groups with `prefixToolNames: true`. Custom `McpServer`
    implementations must return `{ url?, close }` from `start()`.

15. **AI test changes** (`ai`, tests only). `MockModel` infers
    `finishReason: "tool_calls"` when a response has `toolCalls` (set `"stop"`
    explicitly to keep the old ending) and rejects on an aborted `signal`.
    `agent.stream()` emits three new event types (`agent.trip.reasoning`,
    `agent.tool.streaming`, `agent.trip.usage`); tests asserting the exact event
    list should filter, or set `modelOptions: { streamChunks: false }`.

## 3. Behaviour changes that may break your app

Not type errors; they change what happens at runtime. Check each one you use.

| Change                                                                                                                                                  | Who is affected                                   | What to check                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Conditional requests follow RFC 9110 (`core`, `web` sitemaps)                                                                                           | Clients sending `If-Match` / `If-None-Match`      | A weak `W/` tag never satisfies `If-Match` (now `412`); a weak ETag matches its strong form in `If-None-Match` (more `304`s).                                 |
| Image-variant cache is bounded: `uploads.images.maxCacheBytes` 512 MiB, `maxCacheAge` 7 days (`core`)                                                   | Apps with large or long-lived variant caches      | Older and expired derivatives are evicted and re-rendered on request. Raise the limits if render load matters.                                                |
| `sse()` / `stream()` ignore `Content-Type`, `Content-Length`, `Transfer-Encoding`, `Connection` and other framing headers passed by the caller (`core`) | Code setting those headers on a stream            | They are dropped; cache headers are still accepted.                                                                                                           |
| `http.logging.private` rules are prepared once per array (`core`)                                                                                       | Code that edits that array in place at runtime    | Assign a new array instead.                                                                                                                                   |
| `warlock dev` exits `1` on Bun or Deno (`core`)                                                                                                         | Teams running dev on another runtime              | Use Node for development.                                                                                                                                     |
| `warlock dev` warns about POST/PUT/PATCH/DELETE routes with no auth middleware (`core`)                                                                 | Apps with deliberately public mutating routes     | Mark them `public: true`, or set `http.warnUnguardedRoutes: false`. Production never checks.                                                                  |
| Generated Vitest config includes `.spec.ts` (`core`)                                                                                                    | Existing apps adding generated notification specs | Use `include: ["src/app/**/*.{test,spec}.ts"]`.                                                                                                               |
| `v.union()` tries every type-matching member before failing (`seal`)                                                                                    | Unions of object schemas                          | Values matching a later member are now accepted.                                                                                                              |
| `v.tuple([...])` types each position (`seal`, types)                                                                                                    | Code assigning tuples loosely                     | `[string, number]` instead of `(string \| number)[]`; swapped positions no longer compile.                                                                    |
| Claude, OpenAI, Gemini and Claude-on-Bedrock models have built-in prices (`ai-*`)                                                                       | Apps with USD budgets and no `pricing`            | `usage.cost` now appears and USD budgets start enforcing. Pass `pricing` for contract rates.                                                                  |
| Cache writes are billed (`ai`, `ai-anthropic`, `ai-bedrock`)                                                                                            | Cost dashboards and budgets                       | Anthropic and Bedrock costs rise to the correct figure. Use `totalCost(cost)` instead of summing fields; set `cacheWrite`, not the deprecated `cachedOutput`. |
| DeepSeek defaults to peak prices (`ai-deepseek`)                                                                                                        | Off-peak users                                    | Pass `pricing: DEEPSEEK_OFF_PEAK_PRICING`.                                                                                                                    |
| `effort: "none"` sends `thinking: { type: "disabled" }` on Sonnet 5 and Haiku 5.5, and adaptive thinking at `low` on Opus 5 (`ai-anthropic`)            | Apps using `effort: "none"` on those models       | Before, they thought at the default effort; latency and tokens change.                                                                                        |
| Bedrock `cacheControl` also caches the system prompt and (Claude) tool definitions (`ai-bedrock`)                                                       | Bedrock calls with cache breakpoints              | First calls cost more; repeats read at the cache rate.                                                                                                        |
| Gemini and Bedrock merge consecutive same-role turns; parallel tool results go in one turn (`ai-google`, `ai-bedrock`)                                  | Code inspecting the provider request              | Request shape changes; behaviour should improve.                                                                                                              |
| `promptCacheKey` is also sent to xAI and Mistral (`ai-openai`)                                                                                          | Those providers                                   | `prompt_cache_key` now appears in requests.                                                                                                                   |
| A `providerOptions.openai.body` object with a different `type` replaces the built one (`ai-openai`)                                                     | Format and tool-choice overrides                  | Fields from the old variant are no longer kept.                                                                                                               |
| Bedrock `server_tool_use` blocks are no longer returned as tool calls (`ai-bedrock`)                                                                    | Apps dispatching them                             | They were never the agent's to run.                                                                                                                           |
| Incomplete runs are exported as errors (`ai-panoptic`)                                                                                                  | Tracing dashboards and alerts                     | Error counts can rise.                                                                                                                                        |
| MCP `initialize` negotiates the protocol version (`ai-tools`)                                                                                           | MCP clients                                       | A supported requested version is echoed; it used to always answer `2025-06-18`.                                                                               |

## 4. Defects fixed

### `@warlock.js/core`

| What broke                                              | What it looked like                                                                                                                    | What changed                                                                  |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Rate limiter in production                              | No `429`s or limit headers from the global or per-route limits                                                                         | Enforced (section 1).                                                         |
| Rate limiter in development                             | Exempt routes, static files and unmatched URLs were counted                                                                            | Counted per matched route, as in production.                                  |
| Worker threads started from a `.ts` entry on Node 22.15 | Health-check workers could fail before their loader ran                                                                                | Started through a JavaScript bootstrap.                                       |
| HTTP/2 servers                                          | No default shutdown options; drains set forbidden connection headers                                                                   | Sessions tracked and closed after active streams finish.                      |
| Image-variant cache                                     | Crashed-write temporaries and old object-storage generations piled up; an unreadable cache root surfaced raw `ENOTDIR`/`EACCES` errors | Swept after a grace period; throws `ImageVariantsConfigError` with the cause. |
| `warlock generate.module` list controllers              | Passed `request.all()` to the service                                                                                                  | Validate `page` / `limit` and pass `request.validated()`.                     |
| Dev-server Oxlint checks                                | One over-long path aborted the boot scan; shutdown could hang 30 s                                                                     | Bounded batches; that file alone is reported; SIGKILL after 250 ms.           |
| Unsupported Node                                        | Confusing errors such as "registerHooks is not a function"                                                                             | One clear message and a non-zero exit.                                        |

### `@warlock.js/web`

| What broke                                                | What it looked like                                                   | What changed                                 |
| --------------------------------------------------------- | --------------------------------------------------------------------- | -------------------------------------------- |
| Pages on Bun and Deno                                     | Every page request: `500`, "renderToPipeableStream is not a function" | Loads React's Node server build when needed. |
| Sitemap `If-Match`                                        | Weak tags satisfied it                                                | Strong comparison; `412` otherwise.          |
| `useUser(name)` during an abandoned concurrent transition | The signed-in user was lost                                           | Keeps the last committed user and page.      |

### `@warlock.js/seal`

| What broke                                  | What it looked like                                 | What changed                         |
| ------------------------------------------- | --------------------------------------------------- | ------------------------------------ |
| Union of object schemas                     | A value matching a later member was rejected        | Every type-matching member is tried. |
| Failing union after an earlier failure      | Reported a stale message from a previous validation | Reports the default message.         |
| `.merge()`, clone, extend, select fields    | Refinements were lost                               | Kept, in order.                      |
| String replacement mutators without context | Threw                                               | Preserve the input.                  |

### `@warlock.js/logger`

| What broke                             | What it looked like                  | What changed                                         |
| -------------------------------------- | ------------------------------------ | ---------------------------------------------------- |
| Size rotation with `groupBy`           | Renamed the ungrouped top-level file | Renames the group file that grew.                    |
| `rotateFileName` given as a getter     | Every archive kept the boot date     | Rendered at each rotation.                           |
| A `fileName` that threw during a write | Channel stuck in its writing state   | Reported as a failed write; later writes go through. |

### AI packages

| What broke                                                           | What it looked like                                                            | What changed                                |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------- |
| Workspace tools' input schema (`ai-workspace`)                       | Providers sent the model an empty object schema, so it guessed parameter names | Real JSON Schema published.                 |
| `run_tests` pattern under shell mode (`ai-workspace`)                | `$` and backticks expanded                                                     | Single-quoted.                              |
| Anthropic/Bedrock cost (`ai`)                                        | Cache reads subtracted from input (could floor at 0); cache writes free        | Each billed once at its own rate.           |
| Anthropic usage with server-side compaction                          | Compaction iterations missing from token counts                                | Included.                                   |
| Usage rollups in batch, planner and fallback models (`ai`)           | Dropped some usage channels                                                    | Use the shared merge.                       |
| Streaming agent loop (`ai`)                                          | An unknown chunk type was treated as `done`                                    | Only `done` ends the stream.                |
| Durable resume and compaction with a corrupted snapshot index (`ai`) | Could summarize the run's input                                                | Falls back safely; records `no-safe-range`. |
| Anthropic request build errors                                       | Raw error escaped unlogged                                                     | Logged; rejects with an `AIError`.          |
| `ai-ollama` `complete()`                                             | Ignored `signal`                                                               | Aborts the HTTP request.                    |
| Same-role turns (`ai-google`, `ai-bedrock`)                          | Parallel tool results sent as separate turns                                   | Merged in order.                            |
| Semantic cache (`ai`)                                                | Could store a cut-off response                                                 | Never stores one.                           |

### `create-warlock`

| What broke                                         | What it looked like                                            | What changed                                 |
| -------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------- |
| Group feature selection                            | Selecting the rest of a group re-ticked items you had unticked | Unticks kept.                                |
| Project-ready summary on narrow or piped terminals | Lines overflowed                                               | Wraps to the terminal width (80 when piped). |
| ESLint-toolchain `format` script                   | Relied on shell glob expansion; used `npx`                     | Quoted glob; local binaries.                 |

## 5. New in 5.31.0 (short list)

- **New package `@warlock.js/ai-cli`:** drive coding-agent CLIs (Claude Code,
  Codex, Copilot, Cursor, OpenCode, Aider and more) headless as agents, with one
  event model, a capability probe, secrets kept out of argv, process-tree
  cancellation, and `cliModel()` to use a CLI as an `ai.agent` model.
- **Framework conventions in `warlock check`:** linter-independent checks with
  stable codes for unvalidated `request.all()` (`WL9005`), unguarded mutating
  routes (`WL9006`), unsafe redirects (`WL9007`), sensitive values in logs
  (`WL9008`) and unbounded regexes on input (`WL9009`), plus warnings for
  `await log.*`, a second controller in one file and `kind` discriminators. They
  run the same with ESLint, Oxlint or no linter; new apps' `AGENTS.md` tells
  agents to run `npx warlock check`.
- **Runtimes:** a built app starts on Bun and Deno (section 1).
- **CLI:** `warlock upgrade`, `warlock inspect` (routes, models, config keys, jobs,
  … as versioned JSON), `warlock check` (typecheck, lint, affected tests and
  convention checks in one command), `warlock typecheck`, `warlock test`,
  `warlock explain <code>`, `warlock make endpoint`; `--dry-run` and `--json` on
  every generator.
- **Core:** stable `WL####` error codes; `@warlock.js/core/tests` fakes and
  assertions, `defineFactory()`, `createTestHttpServer()`, `actingAs()`,
  `snapshotResponse()`; validated config files (`defineConfigSchema`);
  `safeRedirect()`, `escapeHeaderValue()`, `public: true` routes; custom
  validation failure bodies; image variants on object-storage disks; SSE
  `enqueue()` with byte caps; `http.logging.private`; `@warlock.js/core/net`.
- **AI:** `ai.session()`; file and SQLite snapshot stores; opt-in history
  compaction; `continueOnOutputLimit`; per-run `modelOptions`; provider tools
  (`ai.providerTool`); streamed reasoning, tool arguments and usage; budget
  reservations; `measureTools()`, compact tool schemas, `countInputTokens()`;
  `callId` on tool events; MCP serving over HTTP with auth; Bedrock API-key auth;
  Anthropic context management.
- **Workspace:** `list_dir`, `multi_edit`, background commands, todo tools,
  argument rules (`denyPatterns`, `allowCommand`), opt-in shell mode
  (`interpreter: "sh"`), `checkShellCommand()`.
- **Logger:** `fileName` patterns, `retention`, `escapeLogValue()`.
- **Queue:** `registeredJobs()`, `setDispatchInterceptor()`.

Packages with no changes in this release (version bump only): `ai-live`,
`context`, `devtools`, `herald`, `scheduler`, `sitemap`. `access`, `cascade`,
`fs` and `notifications` changed docs or tests only.

## 6. Verification

How each claim in this summary was checked, and what was not.

All checks below ran once, on Node 22.15.0, against the final `release/5.31` tree before the version bump.
The release workflow repeats the gate on the release tarballs before anything is published.

- **Install:** `pnpm install --frozen-lockfile` at the workspace root succeeds (32 packages).
- **Typecheck:** every package's `typecheck` script passes (the five type errors left by merging parallel work were fixed first).
- **Strictness:** every package is within its strict-mode budget; the budgets for `ai-workspace` (12 → 5) and `ai-panoptic` (61 → 60) went down.
- **Tests:** 1,518 test files and 17,023 tests across all 32 packages ran once; 3 tests failed in `@warlock.js/core` because their assertions depended on the test runner (package-manager user agent, a 10-second timeout under load, a scaffold stub now marked `public: true`). They were fixed and re-run green; no runtime code changed for them.
- **Skill snippets:** the compile gate passes with 204 known failing blocks against an allowance of 204 (down from 279). Examples that taught wrong APIs were corrected, not removed.
- **Public text:** no internal identifiers or private application names in tracked package and docs files.
- **Lint / format:** Oxlint reports 0 errors; the repository Oxfmt check is clean.
- **Docs build:** the documentation site builds (901 pages); the MDX and TabItem guards report 0 violations; every spec file is reachable by its package's test globs.
- **Release-tool tests:** 264 tests, 263 pass, 1 skipped. The zero-edit generator matrix was not run locally (it runs in the release workflow at the scope chosen there).
- **Security review:** the new HTTP transport for MCP serving, the static-file rate-limit exemption and the CLI-agent secret handling were reviewed with probes; no authentication, origin, body-limit or rate-limit bypass was found. Two low-severity defects it found (a malformed stdio MCP line crashing the server, and cancelling a finished CLI-agent run signalling a recycled process group) are fixed in this release.
- **Runtimes:** run locally on this server: a built app started and served on
  **Bun 1.4.3** and **Deno 2.9.7** (pages, API routes, static files, `/health`, clean
  `SIGTERM` shutdown), directly and through `warlock start`. A `runtimes` CI workflow
  builds a fixture app from the packed framework and checks it on Node, Bun and Deno.
- **Not verified:**
  - The workspace's opt-in shell mode (`interpreter: "sh"`) has unit and policy
    tests but **no adversarial bypass testing**. It is a policy layer checked
    before `/bin/sh` runs the line, not a sandbox; run untrusted agents in a
    container, microVM or as a separate unprivileged user.
  - `@warlock.js/ai-cli` adapters for **Antigravity, Cursor, Grok Build, Mistral
    Vibe and Aider** were checked against vendor documentation only, not against
    the real CLI's `--help` (`adapter.verification` says which).
  - **Windows-specific paths** (`cmd.exe` quoting and `taskkill` in `ai-cli` and
    `ai-workspace`) are unit-tested on Linux only.
  - The generator test-matrix row for **`warlock make endpoint`** was tested with
    a fake runtime only.
