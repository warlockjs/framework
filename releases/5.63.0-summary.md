# Warlock.js 5.63.0 — release summary

Released 2026-11-22.

All **34 packages** (`@warlock.js/*` and `create-warlock`) move to 5.63.0 together;
keep every family package on the same version. This minor makes `warlock scry` fast and useful for
agents: it reads the stored book instead of rebuilding it on every call, ranks `--search` hits so a
whole sentence finds the right file, and finds page URLs with `--route`. It also fixes route facts that
were reported fresh when they were not, and six issues found while building apps on 5.62.0 in
`cascade`, `core`, `web` and `create-warlock`. The packages with changes are `grimoire`, `core`,
`cascade`, `web` and `create-warlock`.

## Check first

- **Run `warlock grimoire build` after editing.** `warlock scry` and the Grimoire MCP read tools no
  longer rebuild the book. When files changed since the last build, the answer comes from the stored
  book and ends with `note book is stale (… files changed); run warlock grimoire build`. A project
  whose book was never built with 5.63.0 gets `GR9007` until it runs `warlock grimoire build` once.
- **PostgreSQL apps scaffolded before 5.63.0:** the user migration's `role` column used
  `.default("user")`, which PostgreSQL reads as `CURRENT_USER`, so new users got the database role
  name as their `role`. Change it to `.defaultString("user")` and fix the column default.
- **PostgreSQL migrations with `.default("word")`** now stop with an error naming the column and
  `defaultString()`. They failed before too, with a database error that named neither.

---

## 1. What changed most

- **`scry` reads, `build` writes.** `warlock grimoire build` also stores the derived data
  (`grimoire/book/.cache/derived.json`); `scry` and the MCP tools read it and run one change check.
  Measured on a copy of an app with 11,454 files: median 6.6 s → 1.1 s per answer, the same answers
  for all 56 benchmark queries.
- **`--search` takes a sentence.** A hit no longer needs every word. Names and titles that match the
  text still come first; everything else is ranked by a BM25F score over path words, export names,
  header sentences and written text, with whole-word matching and light stemming. Hits print in score
  order with their score and carry `app`. On 105 held-out commit titles of that app, the file the
  commit changed is in the top 20 for 72 titles (0 with 5.62.0); feature and flow titles are found
  60 of 60. A search takes about 9 ms.
- **`--route` finds pages.** `warlock scry --route "GET /chat"` returns the page or mobile screen
  behind a URL served by the web dispatch route, with its files and layouts; `--site` picks one site
  when several serve the path.
- **Route facts stay honest.** A live read that finds fewer than half the stored routes keeps the
  stored list and says so; route facts with no source files are reported as incomplete; the dev tab
  reads the routes again after a routes file changes instead of reporting them fresh for a minute.

## 2. New options and APIs

- `warlock scry --app <id>`, `--site <id>`; `grimoire_search` `app` and `grimoire_route` `site` inputs.
- `warlock scry --json` errors: `{ "type": "error", "code", "message", "fix" }` on stdout (`ScryError`);
  the scry MCP tools use the same JSON as their error text.
- `warlock grimoire build --force` accepts a route read that shrank the list.
- `warlock migrate --fresh --prune-missing` and `--rollback --prune-missing`; `pruneMissing` on
  `rollbackMigrations()` and `freshMigrate()`.
- `GR9007`, `openStoredGrimoire()`, `checkBook()`, `SCRY_STOP_WORDS`.

## 3. Fixes

- `warlock dev`: a routes file that throws on reload keeps its previous routes until it loads again.
- `requireUser()` / `requireGuest()` redirects no longer throw "Converting circular structure to JSON"
  when the reply is sent asynchronously (for example with compression on).
- A forbidden or error page reached before a layout's loader ran renders without that layout, on the
  server and in the browser, instead of crashing inside it.

## 4. Upgrade notes

- `--search` output changed: score order with the score in front, no grouping by type, no
  letters-in-order matching. Scripts that parse the text output should use `--json`.
- `ScryRouteResult.route` is `null` when the answer is a page; the pages are in `pages`.
- The shared test HTTP server (started in Vitest's `globalSetup`) reads worker 1's database. Tests in
  other workers that need the server to see their rows should use `createTestHttpServer()`.

## 5. Verified

- Each app-reported issue was reproduced with a spec before its fix; the specs now pass as regression
  tests. Two reports did not reproduce (an empty `Content-Type` for `.apk` files; the shared test
  server's database is documented, not changed).
- The search ranking was chosen by an offline evaluation and re-run on the shipped code (numbers
  above).
- One typecheck of the family, the strictness gate and every package's full test suite ran green on the
  final tree, along with format, lint, the public-text, skill and release-note checks, the devtools UI
  gate and the docs build.
