# Warlock.js 5.47.1 — release summary

Released 2026-11-07.

All **33 packages** (`@warlock.js/*` and `create-warlock`) move to 5.47.1 together;
keep every family package on the same version. This patch changes no runtime
behaviour: it documents how to check whether a model field holds a value. The package
with changes is `cascade` (JSDoc, skills and docs).

---

## 1. Checking whether a field holds a value (`cascade`)

- On PostgreSQL an unset column reads back as `null`; on MongoDB it is absent. Test
  for a value with `model.isFilled(field)` or `model.get(field) == null`, never with
  `=== undefined`.
- `model.has(field)` checks that the key exists, so it is `true` for a `null` column.
- The default in `get(field, fallback)` (and `string()`, `number()`, `boolean()`)
  applies only to a missing key. Use `get(field) ?? fallback` to cover `null` too.
- The JSDoc of these methods, the `define-model` skill, the accessors page and the
  multi-tenant recipe now say so.

---

## 2. Upgrade notes

1. **Update the family.** Run `npx warlock update`.
2. **Read what changed.** Run `npx warlock release-notes --from 5.47.0`.
3. **Checking optional columns with `=== undefined` or `has()`?** Switch to
   `isFilled()` or `== null`.
