# Warlock.js 5.30.0 — release summary

Released 2026-10-16. All 31 packages (`@warlock.js/*` and `create-warlock`) moved
to 5.30.0 together; keep every family package on the same version.

This release fixes problems found while building real applications on 5.29 and
from a security and correctness review. It contains **breaking changes in a
minor version** (Warlock.js does not follow SemVer strictly), so read the first
two sections before upgrading.

---

## 1. Read this first

### Known issue: the HTTP rate limiter is not enforced in production in 5.30.0

**This was found after 5.30.0 shipped. It is fixed in 5.31.0. If you rely on
rate limiting, upgrade to 5.31.0. 5.30.0 does not fix it.**

In 5.30.0 and every earlier release, the rate-limit plugin was registered
_after_ the application routes. Routes registered before the plugin do not get
its hook, so in a production start:

| What you configured                                                      | Development (`warlock dev`) | Production (5.30.0 and earlier)                            |
| ------------------------------------------------------------------------ | --------------------------- | ---------------------------------------------------------- |
| Global `http.rateLimit` (any `store`, including the new `"cache"` store) | Enforced                    | **Not applied** to application routes or `/health`         |
| A per-route `rateLimit` option                                           | Enforced                    | **No effect**                                              |
| `middleware.rateLimit({ … })` in a route's `middleware` list             | Enforced                    | Enforced (it is ordinary route middleware, not the plugin) |

**What it looked like:** no `429` responses and no rate-limit headers from the
global limiter in production, even under load, while local development
(`warlock dev`) showed the limiter working.

**What to do:**

1. If you depend on `http.rateLimit` or per-route `rateLimit` options to protect
   login, signup, OTP or other abuse-prone endpoints, upgrade to **5.31.0**.
   Read its upgrade notes first: once limits are actually enforced, a `max` that
   was never exercised in production starts rejecting requests.
2. If you cannot upgrade yet, add `middleware.rateLimit({ max, duration })` to
   the sensitive routes. That middleware is enforced in 5.30.0.
3. The `@warlock.js/auth` login throttles are separate from the HTTP limiter and
   are not affected by this issue.

### Security fixes — upgrade from 5.29 is recommended

| Package                             | What was wrong                                                                                                                                                                                                           | What changed in 5.30.0                                                                                                                                                                                   |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@warlock.js/cache`                 | On **Redis 6**, `increment()` with a default `ttl` ran `EXPIRE … NX` (Redis 7+ only) and threw _after_ the counter had gone up. This **silently disabled login throttles and the cache-backed rate limiter** on Redis 6. | Increment and TTL are applied together by one Lua script; an existing TTL is never shortened.                                                                                                            |
| `@warlock.js/core`                  | Request log entries carried the full `Request`/`Response` objects, and URLs with credentials (OAuth `code`, `signature`, `token`, `X-Amz-*`, …) were logged as-is.                                                       | Log entries carry a bounded, plain `RequestLogSnapshot`; credential query values are masked in both the URL and the parsed `query`. | `@warlock.js/core`                  | `response.sse()` event names and ids were written verbatim, so values built from user input could inject extra SSE fields or events.                                                                                     | Line breaks and NUL are removed from event names and ids; multi-line comments are written one line at a time.                                                                                            |
| `@warlock.js/web`                   | `redirect(request.input("next"))` could send a `javascript:` or `data:` URL to the browser, and the client followed it.                                                                                                  | Redirects are followed or emitted only for relative and `http(s)` targets; others throw on the server and are refused on the client.                                                                     |

| `@warlock.js/ai-anthropic`          | A stored transcript from outside the process could smuggle a `tool_use` or user-side block into an assistant turn on replay.                                                                                             | A stored block is replayed only when its type matches and is one Claude returns on an assistant turn; anything else is rebuilt from `content` and `toolCalls`.                                           |
| `@warlock.js/ai`                    | A model (or a prompt injected into its context) could start an unbounded number of tool calls in one turn.                                                                                                               | Concurrent tool calls are capped at `maxConcurrentTools` (default 4).                                                                                                                                    |

## 2. Breaking changes — exact steps when upgrading from 5.29

Install all family packages at 5.30.0, then work through the items that apply to
your app. Finish with your type check and test suite.

1. **Logger calls no longer return a promise** (`@warlock.js/logger`, types).
   `log.info/warn/error/debug/success/fatal/log/assert` and the function returned
   by `timer()` return the logger synchronously.
   - Remove `.then()` chained on a log call (it no longer compiles).
   - `await log.info(…)` is harmless but no longer waits for delivery. Where you
     must wait (graceful shutdown, end of a CLI command), call
     `await log.flush({ timeout: 3_000 })`. `flush()` now gives up after 5 s by
     default instead of waiting forever.

2. **AI tool calls in one model turn run concurrently** (`@warlock.js/ai`).
   Up to four at a time; results still reach the model in request order.
   - If your tools share mutable state, depend on each other's side effects, or
     your tool middleware reads earlier results from the same turn, restore the
     5.29 behaviour: `ai.agent({ …, toolDispatch: "sequential" })`. Sub-agents
     need it too: `ai.spawnSubAgent({ …, toolDispatch: "sequential" })`.

3. **`FinishReason` has three new values** (`@warlock.js/ai`,
   `@warlock.js/ai-anthropic`): `context_exceeded`, `pause_turn`, `refusal`.
   - Add cases to any exhaustive `switch` over `finishReason`.
   - With Anthropic, a full context window now reports `context_exceeded` (was
     `length`); pause and refusal report their own values (were `error`).

4. **`AgentResult.blocks` is set only for single-trip runs** (`@warlock.js/ai`).
   If you persist conversations with provider blocks, keep them through
   `captureMessages: true` → `report.messages` plus the last trip's `output` and
   `blocks`, not the final text plus `blocks`.

5. **`providerOptions.anthropic.body` cannot override core fields**
   (`@warlock.js/ai-anthropic`). Setting `model`, `messages`, `system`, `tools`,
   `mcp_servers` or `stream` there now throws `InvalidRequestError`. Move those
   to the normal API fields.

6. **Request log entries carry a snapshot** (`@warlock.js/core`). Only affects a
   custom log channel or redaction function that reads `context.request` or
   `context.response`. These are now plain objects:
   `{ id, method, url, route, name, ip, userAgent, query?, body? }`, plus
   `statusCode` on response logs. Replace reads like `request.baseRequest.url`
   or `request.route.path` with `url` and `route`. In your own log calls, pass
   `request.toLogSnapshot()` instead of the request.

7. **Login throttle counters and locks reset once** (`@warlock.js/auth`). Keys
   changed shape, so failed-attempt counts and **locked accounts and IPs from
   5.29 are forgotten when 5.30 starts**. Old keys expire on their own TTL; you
   do not need to flush the cache. If an attacker is currently locked out, they
   get a fresh set of attempts after the upgrade, so plan the rollout window.
   Changing `auth.accessToken.secret` resets them again. A custom `identify`
   function keeps its keys.

8. **Seal's `validate()` result is narrowed on `isValid`** (`@warlock.js/seal`,
   types). On success `data` is the schema's output type; on failure it is
   `undefined`. Check `isValid` before reading `data`, or add a cast where you
   assigned it to an unrelated type. Schemas typed as bare
   `BaseValidator`/`ObjectValidator` keep `data: any`.

9. **Custom `Workspace`/`WorkspaceOps` implementations** (`@warlock.js/ai-workspace`).
   `RunShellResult` must now set `cancelled` (`false` unless cancelled), and
   `readFile()` must return `ReadFileResult` (adds `startLine`, `endLine`,
   `truncated`, `bytesCapped`, `totalBytes`). Test doubles need the same fields.

10. **Image-variant cache layout changed** (`@warlock.js/core`). Derivatives
    cached by 5.29 under `<cacheDirectory>/<2 hex>/<hash>.<ext>` are no longer
    read; each is re-rendered on its next request. Originals are untouched.
    Expect extra render load right after the upgrade, then delete the old
    two-level files from the cache folder by hand to reclaim space.

11. **`<Head />` emits a viewport tag** (`@warlock.js/web`). If your `root.tsx`
    writes `<meta name="viewport" …>` itself, remove it (or move its value to
    `metadata.viewport`) so the page does not get two. Set
    `metadata.viewport: false` to emit none.

## 3. Behaviour changes that may break your app

These are not type errors; they change what happens at runtime. Check each one
you use.

| Change                                                                                                                                      | Who is affected                                                                            | What to check                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `v.union([...])` now validates a present `""` against its members instead of accepting it (`@warlock.js/seal`)                              | Forms posting blank strings to union fields                                                | `v.union([v.literal("x"), v.int()]).present()` now rejects `""`.                                                                                                       |
| A `null` default no longer satisfies "required" on a non-nullable field; `v.int().default("")` now fails its type rule (`@warlock.js/seal`) | Schemas using `null` or wrong-typed defaults                                               | Requests that passed before may now return validation errors.                                                                                                          |
| `read.maxBytes` is actually enforced (`@warlock.js/ai-workspace`)                                                                           | Agents reading long files with a small cap                                                 | Reads now come back cut with `bytesCapped: true`. A window past the end of a file returns empty `content`.                                                             |
| `result.text` joins the text of a resumed `pause_turn` (`@warlock.js/ai`)                                                                   | Code that parsed only the last segment                                                     | Structured output is parsed from the joined text.                                                                                                                      |
| `effort: "none"` on Claude Sonnet 5.5 now sends `thinking: { type: "between_tools" }` (`@warlock.js/ai-anthropic`)                          | Apps that set `effort: "none"` on that model                                               | Before, the model still thought at its default effort; token use and latency change. Claude 5-family models never receive `budget_tokens` or `disabled`.               |
| Consecutive tool results are sent as one `user` message (`@warlock.js/ai-anthropic`)                                                        | Code that inspects the request sent to Anthropic                                           | This is the format Anthropic expects for parallel tool use.                                                                                                            |
| `response.stream()` and `response.sse()` no longer keep sent data in `response.body` (`@warlock.js/core`)                                   | Code or tests that read `response.body` after `end()`                                      | Pass `retainChunks` / `retainEvents` to keep the last _n_. After a client disconnects, stream `send()`/`render()` do nothing.                                          |
| `@fastify/static` loads only when there is something to serve (`@warlock.js/core`)                                                          | Apps with no public folder and no `router.directory()` that call `reply.sendFile` directly | `reply.sendFile` is not decorated in that case; `response.sendFile()` is unaffected.                                                                                   |
| `middleware.rateLimit()` returns an async middleware (`@warlock.js/core`)                                                                   | Code that called the returned middleware and used its return value synchronously           | `await` it.                                                                                                                                                            |
| A page action that redirects keeps `useIsSubmitting()` `true` until the destination page's data has loaded (`@warlock.js/web`)              | UI that re-enabled buttons on redirect                                                     | `onSuccess` fires later than before. `useIsSubmitting()` is also `true` during independent submissions.                                                                |
| `warlock add notifications` writes a smaller module (`@warlock.js/core`, `create-warlock`)                                                  | New notifications modules                                                                  | Clear-all and delete endpoints are no longer generated; the model path is `app/notifications/models/notification/notification.model`. Existing modules are left alone. |

## 4. Defects fixed

### `@warlock.js/core`

| What broke                                                                                              | What it looked like                                                                                            | What changed                                                                                                                    |
| ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Graceful shutdown with keep-alive clients                                                               | `close()` waited out its full timeout; later connectors did not shut down cleanly                              | In-flight responses answer `Connection: close` and idle connections are closed as they go idle. Active responses are never cut. |
| SSE/stream started during shutdown                                                                      | Its `Connection: keep-alive` held shutdown until the timeout                                                   | It keeps the drain's `Connection: close`.                                                                                       |
| A throwing `onDisconnect` handler on SSE/stream                                                         | Process crash, or later handlers skipped                                                                       | Logged; remaining handlers still run.                                                                                           |
| `warlock.config.ts` importing local TypeScript without an extension or through a tsconfig `paths` alias | Config failed to load                                                                                          | A fallback bundles the config's own local imports; packages stay external and errors name `warlock.config.ts`.                  |
| `v.file()` chains (`maxSize`, `image`, …)                                                               | Lost the `UploadedFile` output type                                                                            | Rule methods return `this`; `saveTo()` is typed as `string`.                                                                    |
| Module `utils/locales.json` files in dev and the HTTP test server                                       | `t()` printed raw keys until the file was edited                                                               | Registered at boot.                                                                                                             |
| HTTP test server                                                                                        | Vitest's main process did not exit after teardown                                                              | The loader-hook port no longer keeps it alive.                                                                                  |
| Quoted config keys (`"machine-thumb"`)                                                                  | Invalid `.warlock/typings/config.d.ts`                                                                         | Written without quotes; a file broken by 5.29 is regenerated on first boot.                                                     |
| Circular-dependency check                                                                               | Reported a file importing itself because a comment mentioned `import("./same-file")`                           | Comments are ignored and self imports are not edges.                                                                            |
| Image derivatives cache                                                                                 | Grew forever; deleted sources left derivatives behind; concurrent requests across two disks could answer `500` | Cached per source and pruned on delete, move and rewrite.                                                                       |
| `warlock add image` on pnpm 9 and 10.0–10.4                                                             | `packages field missing or empty`                                                                              | Build approvals are written where the installed package manager reads them.                                                                |
| `storage.use(name)` typing                                                                              | Directory and URL methods needed a cast                                                                        | Typed as `ScopedStorage`.                                                                                                       |
| `http.serverOptions` typing                                                                             | Node options such as `http.maxHeaderSize` did not type-check                                                   | Typed as `HttpServerOptions`.                                                                                                   |

## 5. New in 5.30.0 (short list)

- **Core:** `request.signal` (aborts on client disconnect); backpressure on
  `response.stream()` and `response.sse()` (`write`, `drain`, `backpressured`,
  `signal`); `http.errorMapper` for non-`HttpError` errors;
  `@warlock.js/core/errors` (error classes without the framework's heavy
  imports); per-route request logging policy; shared rate-limit counts through
  `http.rateLimit.store: "cache"` (see the known issue above);
  `purgeImageVariants()`, `createUploadedFileController({ disk })` and
  `resolveImageVariant()`.
- **Web:** `<Form query>`, `<Form independent>`, `isRouteName()`,
  `LinkPropsWithout`, `metadata.viewport`, `webConnector({ build: { testOnly } })`.
- **AI:** provider content blocks (thinking, compaction) replayed verbatim;
  `toolDispatch` and `maxConcurrentTools`; `mapWithConcurrency()`;
  `providerOptions` and `cacheControl.ttl`; `AnthropicModel.countTokens()`.
- **Workspace:** per-call `signal` for `exec()`; richer read results.
- **Logger:** `onChannelError`, `maskEmail()`, `maskEmailsInText()`.
- **Seal:** `TypedValidationResult<T>`, `ValidatedOutput<T>`.
- **fs:** `moveDirectoryNoReplaceAsync()` and `DirectoryMoveError` (POSIX only).

Packages with no API changes in this release: `access`, `ai-bedrock`,
`ai-deepseek`, `ai-google`, `ai-groq`, `ai-live`, `ai-mistral`, `ai-ollama`,
`ai-openai`, `ai-panoptic`, `ai-tools`, `ai-xai`, `cascade`, `context`,
`devtools`, `herald`, `queue`, `scheduler`, `sitemap`. `notifications` changed
docs only.

### Other known issues in 5.30.0

- **HTTP rate limiter not enforced in production** — see section 1. Fixed in
  5.31.0.
- **Changelog text in the npm tarballs** — the `CHANGELOG.md` files inside the
  5.30.0 npm packages contain some internal tracking ids in parentheses. They
  are harmless and do not affect behaviour; 5.31.0 replaces them.
