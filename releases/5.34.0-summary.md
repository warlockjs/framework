# Warlock.js 5.34.0 — release summary

Released 2026-10-19.

All **33 packages** (`@warlock.js/*` and `create-warlock`) move to 5.34.0 together;
keep every family package on the same version.

This release **removes ESLint and Prettier support** (deprecated in 5.33), and adds
multi-file transactions in `@warlock.js/fs`, a browser end-to-end harness
(`warlock e2e`), an AI tool catalogue, a local queue driver that needs no Redis,
MCP serving hooks, and fixes from apps that adopted 5.33. It contains **breaking
changes in a minor version** (Warlock.js does not follow SemVer strictly). Read the
upgrade steps and behaviour table before installing.

---

## 1. Read this first

### ESLint and Prettier support is gone

`create-warlock --lint eslint`, the dev-server ESLint checker,
`devServer.healthCheckers: { eslint }`, `warlock check --lint eslint` and the
Prettier compatibility scripts are removed. Each removed option now fails with a
message naming 5.34.0 and the Oxlint/Oxfmt replacement, so a stale config is never
silently ignored. No published package depends on ESLint or Prettier any more.

Apps still on ESLint run **`warlock upgrade --from 5.33 --to 5.34.0`**. It now
**ports custom ESLint rules** where Oxlint has an equivalent (per-folder
`no-restricted-imports` overrides, `no-restricted-exports`, TypeScript rules,
unused imports, globals and ignores) and reports each rule it cannot port with its
source and file scope.

### Oxlint correctness rules are on

New apps and migrated configs enable Oxlint's `correctness` category as errors.
Expect new diagnostics on first lint; they flag likely bugs, not style.

### `v.object()` refuses arrays

`v.object()` now requires a plain (or null-prototype) object. Arrays, built-ins,
class instances and custom prototypes fail, even with unknown keys allowed. Validate
arrays with `v.array()`, and convert class instances to plain objects first.

## 2. Breaking changes — exact steps when upgrading from 5.33

1. Update every installed `@warlock.js/*` dependency to **5.34.0**, including
   development and optional dependencies. Use `create-warlock@5.34.0` for new apps.
2. Preview and apply the toolchain migration (it needs `ts-morph`, as in 5.33):

   ```bash
   npm install
   npx warlock upgrade --from 5.33 --to 5.34.0 --dry-run
   npx warlock upgrade --from 5.33 --to 5.34.0
   ```

3. Review every reported finding. Port rules it could not translate (for example
   `no-restricted-syntax` selectors) to Oxlint where possible, or to your own
   checks. Existing Oxc configs are kept on conflict.
4. Install, format and check:

   ```bash
   npm install
   npm run format
   npm run lint:check
   npx warlock check
   ```

   Fix new `correctness` diagnostics, then run your tests.

5. Search for `v.object(` schemas that receive arrays or class instances (request
   bodies that may be arrays, stored records, DTO classes) and adjust them.

Coming from 5.32 or earlier? Apply the earlier summaries' migrations first.

## 3. Behaviour changes that may break your app

| Change                                                                    | Who is affected                                    | What to check                                                                  |
| ------------------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------ |
| ESLint/Prettier options fail (`core`, `create-warlock`)                   | Apps with `healthCheckers.eslint`, `--lint eslint` | Run the 5.33 → 5.34 upgrade; remove the old options.                           |
| Oxlint `correctness` enabled (`core`, `create-warlock`)                   | New and migrated apps                              | Fix the new diagnostics.                                                       |
| `v.object()` rejects arrays and non-plain objects (`seal`)                | Schemas that received arrays or class instances    | Use `v.array()`, or pass plain objects.                                        |
| Refresh events carry a `reason` (`web`)                                   | Apps listening to page refresh events              | Use `reason` to tell user refreshes from live, polling and focus revalidation. |
| Guardian variables no longer reach workloads on macOS/Windows (`process`) | Workloads that read supervisor variables           | Nothing should read them; Linux behaviour is unchanged.                        |

## 4. Defects fixed

| What broke                         | What it looked like                                                                  | What changed                                                                         |
| ---------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| Package manager detection (`core`) | `warlock upgrade` told an npm app with a `pnpm-workspace.yaml` to run `pnpm install` | A real lockfile now wins over a workspace marker without its own lockfile.           |
| Object validation (`seal`)         | `v.object({}).allowUnknown()` accepted `["x"]` as `{ "0": "x" }`                     | Arrays and non-plain objects are refused.                                            |
| Record schemas (`seal`)            | `v.record(keyValidator, valueValidator)` threw a `TypeError` at validation time      | Both forms are supported; malformed arguments fail at definition with a clear error. |
| Supervisor config (`process`)      | `supervisor(null)` crashed with a property-read `TypeError`                          | The error names the missing `owner` or `registry` option.                            |
| Shared page data (`web`)           | `useShared()` kept stale data after a client-side shell switch                       | Each page or shell swap seals and publishes its shared snapshot.                     |
| MCP policy errors (`ai-tools`)     | A `beforeCall` that threw `McpError` always returned -32602                          | The thrown code, message and data are kept; other throws keep -32602.                |

## 5. New in 5.34.0

### Multi-file transactions in `@warlock.js/fs`

```ts
import { fs } from "@warlock.js/fs";

const root = "/srv/state";
const result = await fs.transaction(
  root,
  async (tx) => {
    const previous = await tx.readBuffer("state.json"); // null when missing
    const expectedHash = previous === null ? null : fs.hash.buffer(previous);
    await tx.write("state.json", '{"ready":true}', { expectedHash });
    await tx.write("status.txt", "ready");
    return tx.read("status.txt"); // reads see this transaction's own writes
  },
  { operationId: "initialize-001" },
);
```

Writes are staged with read-your-writes, guarded by content-hash or root-epoch
preconditions, and committed through a durable intent journal. A crashed
transaction is completed on the next open; `fs.inspectTransactions` shows what is
pending. Re-running an `operationId` that already succeeded returns the recorded
result without writing. `fs.read(path, { root, consistent: true })` and
`readMany` on an opened store retry when a writer changes the snapshot mid-read. Guarantees cover cooperating processes on a
single host; Windows offers file-level durability only. See the fs docs for the
exact API.

### Browser end-to-end tests: `warlock e2e`

```ts
import { defineE2E } from "@warlock.js/core/e2e";

export default defineE2E({
  // Builds and starts dist/app.js in a disposable copy of the app.
  app: { build: ["npx", "warlock", "build"] },
  run: async ({ page, step }) => {
    await page.goto("/signup");
    await step("submit the form", async () => {
      await page.fill("#email", "ada@example.com");
      await page.waitForNavigation(() => page.click("#submit"), { url: "/welcome" });
      await page.waitFor({ selector: "h1", text: "Welcome" });
    });
    await page.captureViewports("welcome");
  },
});
```

The harness starts your app on an ephemeral port with a disposable data root,
drives Chrome or Edge directly over the DevTools protocol (no Playwright), clicks
only after confirming the element is the topmost hit at its point, checks for
horizontal overflow at 1280 and 390 px, fails on console errors and failed
requests (with allowlists), writes evidence JSON and screenshots, and stops only
the processes it started after checking their command lines.

### AI tool catalogue

`ai.tools.catalogue({ core, searchable })` advertises a small stable set of tools
plus two meta-tools: search (returns at most 8 real schemas by default) and call
(runs a hidden tool through the same validation, approval, budget and tracing as
an advertised one). Searchable tools can load lazily. Provider tools pass through
unchanged. `ai.measure` shows the token saving.

### Local queue driver

```ts
// src/config/queue.ts
import type { QueueConfig } from "@warlock.js/queue";

export default {
  driver: "local",
  local: { path: "/var/lib/my-app/jobs.sqlite" },
  defaultJobOptions: { attempts: 3, backoff: { type: "exponential", delay: 1000 } },
} satisfies QueueConfig;
```

`driver: "local"` keeps jobs in SQLite through Node's built-in `node:sqlite`, with
no Redis: delays, priorities, retries with backoff, concurrency, renewable leases,
crash recovery and graceful shutdown, behind the same `defineJob()`/`dispatch()`
API. `driver: "memory"` runs real handlers in tests. Delivery is at least once, so
keep handler side effects idempotent.

### MCP serving hooks

`ai.mcp.serve` adds `listFilter(context, tools)` to hide tools from `tools/list`
while keeping them callable under the same policy, HTTP `transport.routes` for
small authenticated routes beneath the MCP URL, and `validateCallParams` to refuse
call envelopes the app does not support.

### Smaller additions

- `v.record(keyValidator, valueValidator)` validates keys too and infers literal-key
  dictionaries.
- Secrets: `SECRETS_DRIVER=memory` (or `secrets.driver`) for test runs against a
  built app; refused in production unless `allowMemoryInProduction: true`.
- `atomicWriteAsync(path, content, { durability: "file" | "full" })` flushes file
  bytes, and with `full` the directory entry, around the rename.

## 6. Verification

All checks ran once on the final tree, on **Node 22.15**, each through a memory-
and CPU-capped runner, one at a time.

- **Install:** frozen install passes.
- **Typecheck:** 0 errors.
- **Tests:** 1,578 files; **17,747 passed, 0 failed, 24 skipped**.
- **create-warlock standalone:** 427 passed. **Release-tool tests:** 278 passed.
  **Script tests:** 22 passed.
- **Skill snippets:** within allowance. **Strictness:** within budget.
- **Docs build:** 916 pages. **Format, lint, public text, spec coverage, MDX,
  shipped-docs and skill-reference guards:** clean.

The first validation found and fixed a catalogue scoring type, the queue driver's
dependency on newer `node:sqlite` type definitions (the driver now declares the
surface it uses, so apps type-check it with any `@types/node`), a test endpoint
that dropped WebSocket frames of exactly 127 bytes, two test-data and fixture
mistakes, a migrated `.oxfmtignore` ending, a stale spec option, three changelog
formats, and pnpm commands lost from the installation page's pnpm tabs.

**Not verified:** the real-browser e2e spec ran against the Chrome installed on the
Linux test host only; Edge and macOS/Windows browser discovery are covered by unit
tests. Transaction durability was tested on Linux; Windows behaviour follows the
documented file-only durability.
