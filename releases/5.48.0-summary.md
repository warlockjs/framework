# Warlock.js 5.48.0 — release summary

Released 2026-11-07.

All **33 packages** (`@warlock.js/*` and `create-warlock`) move to 5.48.0 together;
keep every family package on the same version. This minor adds an ordered tool dispatch
mode, makes timed-out shell commands return at their deadline, lets `shell_output` wait
for a job to finish, adds a `path` option to `grep`, reports tool-result clearing, fixes
cloud storage public URLs that dropped the disk prefix, and makes `warlock upgrade --check`
update the lockfile in its trial install. The packages with changes are `ai`, `ai-workspace`, `ai-tools`
and `core`. No breaking changes.

---

## 1. Agents (`ai`)

- `toolDispatch: "ordered"`: consecutive read-only calls in a step run together
  (capped by `maxConcurrentTools`); any other call runs alone, after every earlier call
  and before every later one. A step that writes a file and then runs it now runs in
  that order. The default stays `"concurrent"`.
- `ai.tool({ readOnly: true })` marks a tool that only reads. The workspace's
  `read_file`, `grep`, `glob`, `list_dir` and `shell_output`, the catalogue's
  `tool_search`, and `fetch_url`, `web_search`, `calculator` and `date_time` are marked.
- Tools receive the model's call id as `ctx.callId`.
- A new `agent.context.edited` event reports each tool-result clear (`tripIndex`,
  `clearedResults`, `tokensBefore`, `tokensAfter`), and the trip's cache-miss cause
  lists `messages`. The docs explain when a clear pays for the cache rewrite.

---

## 2. Workspace (`ai-workspace`)

- A command that times out or is cancelled returns within about a second of its
  deadline, even when processes outside the killed tree still hold its output (seen on
  Windows with Git Bash). Background jobs behave the same on `shell_kill`, their timeout
  and `dispose()`.
- `shell_output({ until: "exit" })` waits until the job stops (up to 10 minutes) and
  returns everything printed meanwhile, instead of returning at the next line.
- `grep` takes `path` (a folder or a single file) to limit the search, reads files 16 at
  a time and skips binary files.
- `hooks.onShellOutput` events from `run_shell` carry the model's call id as `callId`,
  so two identical commands can be told apart.

---

## 3. Storage and CLI (`core`)

- Cloud drivers (`s3`, `r2`, `do-spaces`) apply the disk `prefix` in `url()`, as writes
  already did. Before, public URLs pointed at keys without the prefix and returned 404.
  A `urlPrefix` that already ends with the prefix keeps producing the same URL.
- `warlock upgrade --check` installs the trial copy with a lockfile that can update
  (pnpm, Yarn, npm, bun), and `warlock upgrade` exits with code 1, naming the failed
  step, instead of reporting success.

---

## 4. Upgrade notes

1. **Update the family.** Run `npx warlock update`.
2. **Read what changed.** Run `npx warlock release-notes --from 5.47.2`.
3. **Storage URLs.** If you put the disk prefix into `urlPrefix` to work around the
   missing prefix, it keeps working; you can now drop it from `urlPrefix`.
4. **Coding agents.** Consider `toolDispatch: "ordered"` for agents with workspace
   tools, and mark your own read-only tools with `readOnly: true`.
