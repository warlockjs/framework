# Warlock.js 5.40.0 — release summary

Released 2026-10-28.

All **33 packages** (`@warlock.js/*` and `create-warlock`) move to 5.40.0 together;
keep every family package on the same version. No breaking changes. This release makes
`warlock check` finish on large apps, stops the CLI from loading test files, makes manual
transactions cover the caller's queries, and fixes new projects created without web pages.

---

## 1. Breaking changes

- **None.** 5.40.0 has no breaking changes.

---

## 2. `warlock check` finishes on large apps (`core`)

- On a large app the conventions step could run for tens of minutes at full CPU without
  printing anything. Two causes are fixed:
  - The `.client` boundary rule (`WL9022`) re-read, re-parsed and re-resolved every shared
    file for each controller, service, model and route it checked. Import chains are now read
    once per run, and files known to reach no `.client` module are never walked again.
  - Parsed syntax trees kept their parent links in shared lookup tables. With thousands of
    trees alive, memory cleanup stalled for seconds at a time. The links now live on the nodes,
    and the import rules reuse one parse per file.
- On an app with about 7,500 source files, the conventions step now takes about 14 seconds.
- **Progress lines.** `warlock check` prints one line to stderr when each step starts and
  ends. The conventions step also reports when it collects project facts and every 1,000 files,
  naming the slowest rule so far. stdout is unchanged, so `--json` still prints only the report.
- **Per-rule time budget.** Each convention rule may use 30 seconds over a run. A rule that
  goes over is skipped for the remaining files and reported as a **`WL9026`** warning naming
  the rule and the time it used, instead of hanging the command. Set `ruleBudgetMs` in
  `.warlock-check.json` to change it; `0` turns it off.

---

## 3. Spec and test files are never auto-loaded (`core`, `cascade`)

- A `*.spec.ts` or `*.test.ts` file next to a CLI command (for example
  `import-guides.command.spec.ts` beside `import-guides.command.ts`) was imported by command
  discovery. A `vi.mock()` in it then threw "Vitest mocker was not initialized" and broke
  `warlock migrate` and every other command.
- Command discovery now skips `*.spec.*` and `*.test.*` files. The same rule applies to
  `main`, `routes`, `worker`, `events` and locale files, and to the standalone
  `cascade migrate` loader.

---

## 4. Manual `beginTransaction()` covers the caller's queries (`cascade`)

- After `const tx = await driver.beginTransaction()`, the queries you ran next did not use the
  transaction: on MongoDB they ran outside it, so `rollback()` did not undo them, and on
  PostgreSQL they ran on other pool connections.
- Now every query the calling async flow runs after `await beginTransaction()` uses the
  transaction until `commit()` or `rollback()`, and runs with no session afterwards. Other
  requests, timers and jobs running at the same time never see it.
- Call `beginTransaction()` inside the async function that does the transactional work, and
  always commit or roll back, for example with `try` / `finally`. `transaction(fn)` is
  unchanged and is still the simpler choice.

---

## 5. New projects without web pages typecheck (`create-warlock`)

- A project created without the web feature (the default API-only setup) received
  `src/config/web.ts`, which imports `@warlock.js/web`, a package such a project does not
  install, so `tsc` failed on a fresh project. The file is now created only for projects with
  web pages.

---

## 6. Upgrade notes

1. **Update the family.** Run `npx warlock update`.
2. **Read what changed.** Run `npx warlock release-notes --from 5.39.2`.
3. **Run `npx warlock check`.** It should now finish on a large app. If a `WL9026` warning
   names a rule, that rule was cut off by its time budget; raise `ruleBudgetMs` in
   `.warlock-check.json` if your app needs more time.
4. **Remove test-file workarounds.** Specs that you moved away from command folders before
   running the CLI can go back next to the code they test.
5. **Review manual transactions.** Code that calls `beginTransaction()` now runs its later
   queries inside the transaction, which is what the API always promised. Make sure each one
   commits or rolls back.
