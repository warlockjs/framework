# Warlock.js 5.32.0 — release summary

Released 2026-10-18.

All 32 packages (`@warlock.js/*` and `create-warlock`) move to 5.32.0 together;
keep every family package on the same version. No new packages join this release.

This release adopts **TypeScript 7.0.2's native compiler**, adds declared,
self-hosted fonts with metric-matched fallbacks, preserves opted-in native MCP
results, protects local AI conversation files, and improves Gemini token counting
and hosted-search accounting. It contains **breaking changes in a minor version**
(Warlock.js does not follow SemVer strictly). Read the upgrade steps and behaviour
table before installing.

---

## 1. Read this first

### TypeScript 7 requires application config changes

The regular `tsc` command now runs TypeScript's native Go compiler. Pin your app
to `typescript@7.0.2` and migrate every applicable tsconfig, including configs for
tests and scripts. Removed options will stop compilation; aliases previously
resolved through `baseUrl` need explicit config-relative targets. Section 2 has
the exact steps.

### Local AI files are now private — check existing files and shared readers

Snapshot/session JSON and VCR cassettes could previously inherit permissions that
let other local users read conversation or tool data. New store directories now
default to `0700`; saved JSON files are exactly `0600`, including temporary files
before atomic rename and rewrites of older files. SQLite path stores protect the
database and journal/WAL/SHM sidecars with `0600` and create private parents.

**Before upgrading:**

1. Inspect permissions on existing snapshot/session/cassette directories and
   files. Existing directories are **never chmod-ed**, and untouched older JSON
   files keep their permissions until rewritten. Tighten dedicated store
   directories to `0700` and private files to `0600` yourself where needed.
2. If another service account reads these files, arrange ownership or a trusted
   read group first. File snapshots support explicit read-sharing modes:

   ```ts
   ai.snapshot.file({ dir: "./shared-sessions", dirMode: 0o750, fileMode: 0o640 });
   ```

   Modes must be integers from `0o000` to `0o777`; group/other write bits are
   refused. New directory creation remains subject to umask.

3. With `ai.snapshot.sqlite({ database })`, permissions remain your responsibility;
   the protection applies to path-based stores. Windows ignores POSIX modes:
   configure filesystem ACLs there.

### New apps default to Oxlint + Oxfmt

`create-warlock` now scaffolds **Oxlint + Oxfmt** by default, with TypeScript 7.0.2. The ESLint + Prettier
toolchain is still available with `--lint eslint`, but it uses **TypeScript 6.0.3**: typescript-eslint (8.71.2 and
canary) only supports TypeScript below 6.1, so an ESLint scaffold on TypeScript 7 could not even install with npm.
ESLint mode is planned for deprecation in 5.33 and removal in 5.34. Existing apps are not changed.

### esbuild security update

`@warlock.js/core`, `@warlock.js/web` and `@warlock.js/cascade` now depend on esbuild **0.28.2**, past the
advisory [GHSA-g7r4-m6w7-qqqr](https://github.com/advisories/GHSA-g7r4-m6w7-qqqr) (low severity: files outside
the served folder could be read through esbuild's development server on Windows; fixed in 0.28.1). Apps that
pinned or overrode esbuild below 0.28.1 should remove that pin. No application changes are needed otherwise.

### Hosted-search cost tracking needs explicit request prices

Search request fees are separate from token prices. To include them in reports,
set `pricing.serverTools` on the model, using the appropriate exported table:
`ANTHROPIC_SERVER_TOOL_PRICING`, `OPENAI_SERVER_TOOL_PRICING`, or
`GOOGLE_SERVER_TOOL_PRICING`. The Google table applies to **Gemini 3 and newer**;
older models bill per grounded prompt, so their query counts cannot price those
fees correctly.

Use `totalCost(usage.cost)` instead of summing only token cost fields. If using
USD reserve budgets with hosted search, set `reserve.serverToolRequests` and a
`serverTools.webSearch` rate. A positive reservation without a rate fails closed
unless `onUnpriced: "allow"`. Budget-specific pricing does not configure model
report pricing; set both if they must agree. Pair reservations with provider
limits where available: reserving fees alone does not cap provider search calls.

## 2. Breaking changes — exact steps when upgrading from 5.31

### Install the family together, then migrate TypeScript

1. Update every installed `@warlock.js/*` dependency to **5.32.0**, including
   development and optional dependencies. Use `create-warlock@5.32.0` for new
   apps. Keep the family versions aligned.
2. Pin the application compiler and ensure Node ambient types are installed:

   ```bash
   pnpm add -D -E typescript@7.0.2
   pnpm add -D @types/node   # if not already installed
   ```

   No native-preview compiler package is needed.

3. Edit each tsconfig:

   - Remove `baseUrl`. Rebase **every** `paths` target relative to that config.
     For example, `baseUrl: "src"` with `"app/*": ["app/*"]` becomes
     `"app/*": ["./src/app/*"]`.
   - Replace `moduleResolution: "node"` / `"node10"` with `"bundler"` and set
     `module: "ESNext"` for Warlock's build pipeline.
   - Remove `downlevelIteration` and obsolete `ignoreDeprecations` settings.
   - Explicitly include Node ambient types with `"types": ["node"]`. Preserve
     other types your app needs, such as test-runner globals.
   - Set `rootDir` explicitly if the source layout requires a root outside the
     config folder. Keep strict checking enabled.

   ```json title="tsconfig.json — compilerOptions excerpt"
   {
     "compilerOptions": {
       "module": "ESNext",
       "moduleResolution": "bundler",
       "types": ["node"],
       "paths": { "app/*": ["./src/app/*"] }
     }
   }
   ```

   Merge this excerpt into your existing config; retain its strictness, JSX,
   target and source settings.

4. After those edits, check the app:

   ```bash
   pnpm exec tsc --noEmit
   pnpm warlock typecheck
   pnpm warlock typecheck --changed
   ```

   Then run your application's tests. Coming from 5.30 or earlier? Apply the
   earlier summaries' migrations too; this checklist covers 5.31 → 5.32.

### Two third-party tooling exceptions

Framework, application, docs and release-tool typechecks all use **7.0.2**.
Two third-party tools retain their own compilers:

| Tool                                           | Compiler it keeps                                                             | What to do                                                                                                                                                 |
| ---------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `typescript-eslint` in optional ESLint mode    | Private **TypeScript 5.9.3**, because TS7 removed the JavaScript API it needs | Prefer Oxlint/Oxfmt. If retaining ESLint, keep its compatible compiler isolated from the app's TS7 compiler; the optional mode still needs that older API. |
| `ts-morph`, used by `warlock upgrade` codemods | Bundled **TypeScript 6.0.2**                                                  | Keep it for codemods; continue to typecheck the application with TS7.                                                                                      |

## 4. Defects fixed

| What broke                                                      | What it looked like                                                                                                          | What changed                                                                                                                                    |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Local conversation and cassette permissions (`ai`)              | Sensitive JSON, database or sidecar files could be readable by other local users                                             | Private creation and rewrite modes, including atomic-write temporaries; see section 1 for existing-file limits.                                 |
| Native MCP `CallToolResult` forwarding (`ai-tools`)             | Structured output, rich content or `isError` became serialized text, including with an advertised output schema              | Explicitly opted-in results preserve content blocks, `isError`, `structuredContent` and `_meta` over stdio and HTTP.                            |
| Malformed opted-in MCP results (`ai-tools`)                     | Invalid native payloads could be sent to the client                                                                          | The serving boundary validates them and returns a JSON-RPC internal error instead.                                                              |
| Gemini Developer API token counting (`ai-google`)               | Preflight undercounted requests containing system prompts or tools                                                           | Sends the full `generateContentRequest`, including generation settings, through the existing SDK transport with cancellation and error mapping. |
| Unsupported native token-count shapes (`ai`)                    | Budget preflight failed even though generation could proceed                                                                 | `countInputTokens` estimates the full input only for `InvalidRequestError.reason: "count-unsupported"`; other provider errors still propagate.  |
| Hosted-search accounting and metadata (`ai`, provider adapters) | Request fees were absent from cost reports; grounding, actions or sources were unavailable through the shared response shape | Provider-reported counters and raw metadata are retained, with opt-in fee tables and stream snapshot reconciliation.                            |
| Trace usage aggregates (`ai-panoptic`)                          | Hosted-tool counters or historical fees could disappear from rollups                                                         | Uses canonical usage merging, retaining those fields alongside cache accounting.                                                                |
| Frozen documentation sidebars                                   | Nested groups could link to pages available only in the latest docs                                                          | Latest-only entries are filtered inside nested groups too.                                                                                      |

The unsupported-count signal is preserved by Anthropic, OpenAI Responses and
Bedrock adapters as well as Google. Unsupported cached-content counting can use
the estimate fallback; authentication errors are never turned into estimates.

## 5. New in 5.32.0

### Declared fonts in `@warlock.js/web`

Declare self-hosted font files once in `web.fonts`. Warlock generates font-face
CSS, CSS variables, critical preloads in buffered and streamed document heads,
and metric-matched local fallback faces. These fallbacks match width and line
height to prevent the heading reflow and layout shift when a web font swaps in.

```ts title="src/config/web.ts"
import type { WebConfigurations } from "@warlock.js/web";

export default {
  fonts: [
    {
      family: "Display",
      variable: "--font-display",
      fallback: ["Arial", "Helvetica"],
      files: [
        {
          path: "src/fonts/display-regular.woff2",
          weight: 400,
          preload: true,
          aboveFold: true,
        },
      ],
    },
  ],
} satisfies WebConfigurations;
```

Use `font-family: var(--font-display)` so the adjusted fallback stack takes
effect. Supply your own licensed font file; prefer WOFF2. When migrating, remove
equivalent handwritten font-face declarations and preloads to avoid duplication.

Declared files and their stylesheet become hashed Vite assets with
`Cache-Control: public, max-age=31536000, immutable` in production. Unhashed
public URLs retain their usual cache policy. Page, layout or root
`config.fontPreload: false` suppresses preloads for that document; any ancestor's
opt-out wins, while CSS remains linked for navigation.

Development caches metrics and warns about TTF/OTF and critical faces missing
preload or fallback. Width matching is approximate: check the actual heading at
its breakpoints with a cold cache. Variable fonts use default-instance metrics;
non-Latin sampling is not implemented.

### Native MCP results

Return `mcpResult(...)` from `@warlock.js/ai-tools` for explicit passthrough, or
enable detection for existing native-returning tools with
`ai.mcp.serve(tools, { results: "native" })`. Per-tool
`meta.mcpResults: "native" | "text"` overrides detection; the explicit helper
always opts in. `McpNativeResult` types the wrapper, and `McpToolCallResult` now
includes `structuredContent` and `_meta`.

`meta.outputSchema` advertises structured output in `tools/list`. Tool authors
remain responsible for schema conformity; include a serialized text block for
clients that need it. Per-request headers and abort signals remain available to
tools, and thrown-tool errors keep their existing handling.

### Hosted/native search usage and cost

Responses and streaming terminal chunks retain `providerMetadata`; agent reports
keep it on each trip. Hosted actions stay outside local function dispatch.

| Provider path    | What is available                                                                                                                                                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Anthropic        | Cumulative hosted web-search/fetch usage; preserved server-tool blocks; explicit `ANTHROPIC_SERVER_TOOL_PRICING`.                                                                                                                                 |
| OpenAI Responses | Web-search call counts without double-counting stream snapshots; hosted output, actions and sources; explicit `OPENAI_SERVER_TOOL_PRICING`. Chat Completions does not map hosted-search billing counters.                                         |
| Gemini           | Raw candidate grounding metadata; unique nonempty search-query counts, plus raw query-array lengths. `GOOGLE_SERVER_TOOL_PRICING` is opt-in for Gemini 3+ only.                                                                                   |
| Qwen/DashScope   | Typed `providerOptions.qwen.enableSearch` controls on the OpenAI-compatible adapter.                                                                                                                                                              |
| Kimi/Moonshot    | `kimiSearchTool()` (Basic/Pro) and `kimiFetchTool()` client tools for Kimi's standalone search and fetch endpoints, with cancellation, error mapping and usage/cost accounting. The `$web_search` builtin (retiring 2026-10-20) is not supported. |
| Bedrock Converse | No hosted-search request counter is exposed; system-tool blocks do not establish a request fee, so no count is fabricated.                                                                                                                        |

`ModelPricing.serverTools` expresses USD per request; `usage.cost.serverTools`
retains historical amounts. `mergeUsage`, `totalCost`, agent reports and trace
rollups include them. Fee tables are explicit opt-ins; missing data stays
unreported or unpriced.

### Report framework issues from your agent

Core's skills now include `report-framework-issue.md`, linked from the core skill index: when an agent finds a
Warlock.js bug or missing capability, it confirms it with a minimal reproduction, searches existing issues, drafts
a report without secrets or private code, and **asks you before filing** it on
[warlockjs/framework](https://github.com/warlockjs/framework/issues). `warlock issue [--type bug|feature]` prints
the environment block and a pre-filled new-issue link (it never sends anything). The repository now has bug and
feature issue forms.

### Faster typechecking throughout the family

All 32 packages, generated apps, docs and release tooling pin **TypeScript
7.0.2**. CLI checks retain incremental state and changed-file filtering;
development diagnostics reuse a native compiler session. Syntax analysis uses
OXC instead of the removed JavaScript compiler API.

Recorded workspace typecheck time is **36 seconds**, versus the earlier
**1 minute 51 seconds**. Treat these as indicative timings, not a controlled
benchmark: the migration report notes that an initial baseline overlapped
dependency installation. Seal's recorded type benchmark check time falls from
**6.0 to 3.2 seconds**, using about **one-third less memory**. Its TS7 baseline
uses one checker to keep type and instantiation counts deterministic.

Packages without another feature or fix in their 5.32.0 changelog receive the
same compiler migration. Release tooling also moves strictness and skill-snippet
compilation to native `tsc`, preserving skill-local aliases and dependency scopes.

## 6. Verification

All checks ran once on the final tree before the version bump, on Node 22.15.0, each through a memory- and
CPU-capped runner, one at a time. The release workflow repeats the gate on the release tarballs before publishing.

- **Install:** `pnpm install --frozen-lockfile` passes (32 packages); create-warlock's standalone install passes.
- **Typecheck:** every package passes on TypeScript 7.0.2 with 0 errors; docs and release tooling too.
- **Strictness:** every package within budget; no allowance raised.
- **Tests:** 17,217 tests across all 32 packages pass (19 skipped). The run surfaced one CLI spec timing out on a
  cold import under the CPU cap; core's test timeout was raised and the spec re-run green. create-warlock's
  standalone specs: 425 pass.
- **Skill snippets:** 21 known failing examples (allowance lowered from 204 to 21); compiled 787, passed 766.
- **Release build:** pkgist builds declarations on TypeScript 7 (verified by building `@warlock.js/context` and
  `@warlock.js/core`, 329 declaration files) after moving the release runner to tsdown 0.23.
- **Public text, lint, format:** clean (Oxlint 0 errors). **Docs build:** 904 pages; MDX and TabItem guards pass.
- **Release-tool tests:** 267 pass. **Script tests:** 19 pass.
- **Runtimes:** not re-run locally for this release; the `runtimes` CI workflow (Node, Bun, Deno) runs on the
  release commit.
- **After the first CI run:** the release commit's CI exposed three gaps that the local pass could not: release
  gate scripts needed `jsonc-parser` at the workspace root, a dev-server worker test failed only on Node 24 (fixed in
  shipped code: source workers keep Node built-ins out of the loader's namespace), and the default ESLint scaffold
  could not install TypeScript 7 with npm (now the Oxc default; ESLint mode on TypeScript 6.0.3). All six fresh
  scaffold combinations (npm, pnpm, yarn × Oxc, ESLint) install and typecheck.
- **Not verified:** native Windows behaviour (esbuild's patched dev-server path, `cmd.exe` quoting) is unit-tested
  on Linux only; Kimi search/fetch, Qwen search and hosted-search counters were tested against mocked transports,
  not live paid calls; the generator matrix scope is decided in the release workflow.
