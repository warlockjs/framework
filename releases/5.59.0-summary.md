# Warlock.js 5.59.0 — release summary

Released 2026-11-19.

All **34 packages** (`@warlock.js/*` and `create-warlock`) move to 5.59.0 together;
keep every family package on the same version. This minor brings the Warlock look and
version display to devtools and the Grimoire tab, adds flow cards, a "What changed"
timeline and tabbed feature and flow pages, lets `warlock check` reuse a passing test
result, and adds an experimental per-file isolated test lifetime. The packages with
changes are `core`, `devtools`, `grimoire` and `cascade`.

## Check first

- **Production sign-in options.** `twoFactor: "off"` and `passwords: { minLength, rejectCommon }`
  are new. Without them nothing changes: the second factor stays required and common
  passwords stay rejected. A password that is too short now answers with the configured
  minimum length.
- **`warlock check` may skip the tests.** When the working tree matches the last passing
  full run, the tests step reports that result. Pass `--rerun-tests` to run the suite anyway.

---

## 1. What changed most

- **Warlock look in devtools and Grimoire.** The dashboard uses the Warlock gold palette and
  logo in the light and dark themes, and shows the framework version in the sidebar header
  and the app's name and version in the footer. A reconnect banner shows while the app is
  unreachable, and panels refetch when it returns.
- **Flow cards, a timeline and tabbed pages.** The flow list shows steps, cases, criteria,
  proven criteria and unexpected findings per flow. A "What changed" timeline lists releases,
  tasks and changes with chips that jump to the feature or flow they name. Feature and flow
  pages are tabbed, a feature map shows flows against apps, and a skeleton shows while the
  book opens.
- **A Product map you can sort and export.** Sort features, see what changed since a release
  you pick, and export the share-safe map alone with `warlock grimoire build --site --product`
  (no file paths, test names or per-file answers). A missing test-results file shows a grey
  "not measured" instead of a problem.
- **Better search.** Search indexes the written text of flows (summary, who, story, cases and
  criteria), ranks written content above files and exports, and groups hits by type.
- **Fewer false findings.** GR3006 no longer reports route middleware, migrations, seeds,
  commands, layouts or test helpers that specs import; GR5008 is skipped for mail and
  notification entries when the book has no route facts.
- **Faster Grimoire calls.** The MCP server keeps the opened book in memory and opens it
  again only when a file it lists changed.
- **Faster `warlock check`.** The tests step reuses a passing result for the same tree, and
  its time limit is sized from the last full run.

## 2. New options and APIs

- **`warlock check`.** `--rerun-tests`, `--test-report` (default
  `node_modules/.cache/warlock/vitest-report.json`) and `WARLOCK_CHECK_TEST_REPORT`. The
  limit is 1.5 times the last full run when that is longer than 600 s; `--test-timeout` and
  `WARLOCK_CHECK_TEST_TIMEOUT` still win. WL8007 messages say how long the run took.
- **Experimental `tests.lifetime: "worker-isolated"`.** Connectors boot once per worker like
  `"worker"`, and every test file also gets a fresh module graph and clean Vitest state. The
  `tests.resetAppCaches` hook clears caches the app keeps outside its own modules. In one
  large app the full test step went from 148.8 s to 129.7 s, with setup falling from 27% to
  3% of the run.
- **Devtools.** `DevtoolsSessionView` gains `warlockVersion` and `app`. Production options
  `twoFactor: "off"` and `passwords`. The AI tab names which of four reasons it is empty
  (`@warlock.js/ai` missing, `@warlock.js/ai-panoptic` missing, Panoptic failed to load, or
  observation off) with the command to run; the `/ai` answer carries `reason`, `title`,
  `command` and `detail`.
- **Grimoire.** The adapter's optional `host()` reports the framework and app names, versions
  and logo. `warlock grimoire build --site --product`. `build --site` leaves the page alone
  when it was built from the same book; `--force` writes it again. `openGrimoire`'s snapshot
  source takes an opt-in `collectRoutes` option for tooling processes only.
- **Cascade.** Registering a model under a name that is already registered no longer warns
  under `"worker-isolated"`; the duplicates are counted instead.
- **Core.** CLI command lines show the arguments you passed: `Running grimoire build`, not
  `Running grimoire <action> [release]`.

## 3. Upgrade notes

- Nothing to change for existing apps.
- Specs that need a fresh module graph per file can try `tests.lifetime: "worker-isolated"`;
  it needs the same Vitest setup as `"worker"`.

## 4. Verified

- One typecheck of the family and the full test suites ran green; two core CLI tests that
  timed out under server load pass in isolation.
- The new dashboard, the Grimoire tab and the Product map were reviewed in a browser preview.
- `"worker-isolated"` was measured in a real application (148.8 s to 129.7 s).
