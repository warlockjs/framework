# Warlock.js 5.65.0 — release summary

Released 2026-11-26.

All **34 packages** (`@warlock.js/*` and `create-warlock`) move to 5.65.0 together;
keep every family package on the same version. This minor closes the open findings in one release.
Web pages now render in API tests from each worker's own server, a production build that fails to
boot exits instead of staying up with nothing served, and five long-requested capabilities land: a
navigation blocker for unsaved changes, raw request bodies for webhook signatures, the request in the
error formatter, per-site locales, and a login policy that knows how and where a user signs in. Auth,
the ORM, the queue, the AI guard and Grimoire get fixes found by apps. The packages with changes are
`core`, `web`, `auth`, `cascade`, `queue`, `ai`, `grimoire` and `create-warlock`.

## Check first

- **Web apps no longer need a shared test server.** The request helpers' per-worker server also starts
  the web connector, so pages and API routes read the worker's own database. `warlock add test` no
  longer writes `src/test-global-setup.ts`. An app that has one keeps working; delete it and its
  `globalSetup` line to move to the worker servers, and set `WARLOCK_TEST_DATABASES` to the number of
  test databases.
- **Access-token claims.** Tokens are built from the user model's `accessTokenPayload()` on login,
  refresh and renewal. A payload passed at login is now merged over those claims instead of replacing
  them.
- **Queue job ids.** `dispatch({ jobId })` rejects an id with `:` or made only of digits on every
  driver, including the local driver and the queue fake. Use ids such as `invoice-43`.
- **A failed boot exits.** A production build (`warlock start`, `node dist/app.js`) that fails while
  booting now exits non-zero after logging the error. Errors after boot, and in the dev server, are
  still only logged.
- **`setupTest({ importModule })` loads the app's `main.ts` files** right after boot; a `main.ts` that
  throws now fails the setup instead of the first request.

## 1. What changed most

- **Pages in API tests.** `testGet("/")` returns the page from the worker's server, which runs the web
  connector next to the API routes and reads the worker's database. Two workers each see only their own
  rows, for pages and API routes alike.
- **Navigation guards.** `useBlocker(when, confirm?)` asks before a `<Link>` click, `navigateTo()` or
  Back/Forward leaves a page with unsaved work, with an optional prompt on reload and tab close.
  `routerEvents.onBeforeNavigate()` is the listener underneath; it can answer later (an in-page dialog).
- **Raw request bodies.** `rawBody: true` on a route keeps the exact bytes as `request.rawBody` and
  `request.rawBodyText()`, in production and in the dev server, so a webhook signature is checked over
  what the sender signed.
- **Per-site locales.** A site's `localeRouting` takes `locales` and `defaultLocale`. An Arabic-only site
  answers `?locale=en`, the locale cookie or header in Arabic, its prefixed routes and 404 pages use its
  own set, and its dictionaries are checked against it at build time. Sites without the options behave as
  before.
- **Login policy context.** `auth.canAuthenticate(user, { via, request })` knows the method (`password`,
  `otp`, `passkey`, `oauth`, `token`, `refresh`, `custom`) and the request, so a tenant-membership check
  runs before tokens are issued. `authService.verifyCredentials()` tells a wrong password from a refused
  account, revealing the refusal only after the right password.
- **Error capture.** The `http.errorResponse` formatter receives the request and the thrown error, so a
  5xx can be recorded with its route, method, user and request id in one place.

## 2. New options and APIs

- Core: route option `rawBody`; `request.rawBody`, `request.rawBodyText()`; `request` and `error` in the
  error-response context; `useHashedPassword({ keepHashes })`, `isPasswordHash()`,
  `HashedPasswordOptions`; doctor code `WL9106` (a migration file `warlock migrate` never runs);
  `createTestHttpServer({ web })`; the e2e app fixture's `envFile` option and `WARLOCK_E2E=1`.
- Web: `useBlocker`, `routerEvents.onBeforeNavigate`, the `BeforeNavigate*`, `BlockerConfirm` and
  `UseBlockerOptions` types; `SiteLocaleRouting` with `locales` and `defaultLocale`.
- Auth: `authService.verifyCredentials()`, `CredentialsVerification`, `AuthenticationContext`,
  `AuthenticationMethod`; the request on `login`, `attemptLogin` and `verifyOtp`, and a context on
  `completeLogin`.
- Cascade: `DatabaseWriterValidationError` carries `constraint`, `columns` and `cause`.
- Grimoire: `scry --search` and the `grimoire_search` MCP tool fold the top file's impact (importers,
  routes, flows and tests) into the answer, as `impact` in `--json`; the devtools panel's `warm` option.
- create-warlock: a `format:file` script that formats only the files you name.

## 3. Fixes

- `query().limit(n).update(...)` changes only the rows the limit selects, on PostgreSQL and MongoDB.
- A unique-index violation names every column of the index, without quotes.
- `removeAllAccessTokens()` and the token models' user lookups match the user type as well as the id.
- `warlock migrate` finds migrations in `models/<name>/migrations/` at any depth.
- `useHashedPassword()` can keep a value that already is a hash (seeding, imports).
- `warlock build` checks route `locales.json` files against `app.localeCodes`, as boot does.
- Chunk-cycle members with equal code get their own files; a font `fallback` the framework cannot measure
  is refused with a clear message; the production 404 page for `/ar/missing` renders in Arabic.
- The AI guard's credit-card category redacts only Luhn-valid card numbers and keeps the space after them.
- The Grimoire devtools tab no longer blocks the server at start on large apps.
- `warlock e2e` reads `.env.e2e` (else `.env`), runs Chrome without the sandbox as root, and the starter's
  components page and scenes work in an e2e run.
- pnpm 11+ installs with the queue no longer fail on `msgpackr-extract`, in new apps and in
  `warlock add queue`.
- New apps pass their own Grimoire check: the starter declares its site, an `accounts` feature for
  sign-in, password reset, posts, users and uploads, and tests that prove every criterion. The contact
  form says to check the connection when the server cannot be reached.

## 4. Upgrade notes

- `--search` text output prints an `impact of <file>:` block in place of the `next:` line when the top
  file has an impact; scripts should read `--json`.
- One-argument `auth.canAuthenticate` policies keep working; the context is an optional second argument.
- To use the starter's e2e setup in an existing app, copy `.env.example` to `.env.e2e` with a test
  database and `CACHE_DRIVER=memory`.

## 5. Verified

- One full verification pass on the merged tree (format, lint, public text, release notes, skills,
  strictness, the typecheck of every package, every package's tests, the devtools UI gate and the docs
  build), with each failed step fixed and re-run green.
- Live services: the cascade PostgreSQL (143 tests) and MongoDB (111 tests, relations included)
  integration suites, the auth hardening suites on MongoDB and PostgreSQL, the Redis login-throttle,
  rate-limit and cache suites, the AI checkpoint stores on PostgreSQL and Redis, and RabbitMQ direct
  reply-to and reconnect.
- A freshly scaffolded web app on the 5.65.0 code: two test workers each read their own database
  through API routes, the starter's page test passes without a global setup, `warlock e2e` runs the
  starter's scenes with only the documented `.env.e2e` (the components page captured in English and
  Arabic), `warlock grimoire check --all` reports no errors or warnings, `warlock start` exits 1 within
  two seconds when the database is missing and serves the site when it is not, the dev server keeps
  serving after an unhandled rejection, `warlock build` refuses a route `locales.json` that mixes codes
  with nested entries, and `warlock add queue` installs under pnpm 11.
